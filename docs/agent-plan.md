# AI agent 执行计划

2026 年 11 月 6 日制定。本文是后续实施方案，当前阶段仅交付计划。战略依据为保持原稿的 [用户计划](user-plan.md)；[拟议修改](user-plan-proposals.md)单独列出，尚未应用。本计划中的目录、数字预算和接口名是可调整的工程建议，不冒充用户指定值。

## 目标与取舍

在本项目重新实现可复用的三种工具。先交付小范围、可日常使用的记忆闭环，再扩大资料规模，接入资源协调与分层组织。旧项目作为参考：取用明确的需求、事故样例和经确认的小接口，不在旧 Context 上接着升级，不整体迁入旧数据库、任务台账、授权或审计树。

首个可用版本包含短项目说明、文字检索、原文定位、一个廉价检索 worker、最小增量维护；紧接着补齐本地向量、图片和实际语义图。不能把这些后续能力从完整交付范围中删掉。

代码只保留一份维护源，项目实例保存配置与数据。三种工具分别可用；记忆的一次查询不以完整资源平台或三层组织已建成为前提。

## 最小结构与责任

建议采用一个源码仓库和三个模块，不为每轮尝试另建长期产品副本。

```text
basePack/
  README.md                 安装与使用入口
  docs/                     战略、实施、设计决定与精简结果
  src/basepack/
    memory/                 来源、检索、图与增量处理
    resources/              现有资源设施的薄适配
    agents/                 宿主衔接及任务包处理
  skills/                   短技能、角色 prompt
  tests/                    小样例和真实事故回归
  examples/                 可随包分发的小型公开资料
  pyproject.toml            依赖与安装入口
```

这是拟建目录，当前尚未创建产品骨架。项目使用时只需少量常驻文档、一个配置文件和项目局部 `.memory/`。源码与生成后的 skill 不分别手工维护。实验的临时输入和输出放仓库外或被忽略的工作目录；长期只保留能解释结论的小报告与必要样例。

| 对象 | 唯一职责与保存位置 |
| --- | --- |
| 用户计划 | 用户意图和战略；本文不重复维护其正文 |
| AI 执行计划 | 阶段、依赖、验收；实施时只在一份短进度文件记当前状态 |
| 项目原件 | 继续位于业务项目；记忆保存定位、版本及必要派生内容，不默认复制全库 |
| 来源、片段、节点、边、变化记录 | 项目局部数据存储；优先少量数据库/索引文件，避免每节点一文件 |
| 通用代码与依赖 | 产品源码仓库与明确安装的环境；机器环境优先复用 AgentTools |
| 权重与机器调度 | AgentTools 等共享基础设施；不存项目知识 |

底座先比较现有 Basic Memory 路线与一个更薄的数据库路线，最多做两个小型适配样例。选择能满足全文、向量、图、原文定位、增量与机械盘 I/O 要求的一种。若现有底座要求大量镜像文件或与新接口强耦合，采用更薄路线；若其原生能力已够用，停止自建。选择前核对实际安装版本及官方接口，不在本轮预设必须保留 Basic Memory，也不另设图数据库服务。

## 调用方式与最小数据约定

本地程序负责材料准备、查询、持久化、数值排序、变化检测和资源适配。理解、建图、图片识读、筛选和评分由宿主实际派发的订阅 agent 执行。宿主不支持的能力直接报告，不用不存在的 LLM API，不把准备好的任务包称为已执行。

对外先提供四种记忆动作，命令拼写在首版实现时固定：

| 动作 | 输入 | 紧凑输出 |
| --- | --- | --- |
| `brief` | 项目根、可选任务说明 | 核心目的、少量当前线索、值得注意的变化或缺口、原文入口 |
| `search` | 问题、来源范围、结果预算 | 文字/向量/图候选，正文摘录、来源定位及可读图路径 |
| `read` | 来源 ID、版本、范围 | 指定原文/图片及定位；不存在或已变化则给具体结果 |
| `maintain` | 变更范围、候选批次、自动/手动模式 | 应用结果、错误或未完成位置，供宿主继续 |

用户层的一次检索委托流程：工作 agent 发目标与预算 → 一个廉价 worker 检索并按需扩展/读原文 → 对实际读到的候选打分 → 脚本排序截取 → 返回直接相关的内容、来源和缺口。默认同一 worker 完成检索与评分，不强制独立评分员；工作 agent 仍能自行深入检索。候选多时分批，但先在共享候选范围或有共同锚点的批次内评分，避免把不同批的主观分数直接当作统一标尺。

最小数据字段：来源有稳定 ID、路径/聊天定位、内容版本和类型；片段有来源及原文范围；节点有稳定 ID、简短内容和支持来源；边有独立 ID、两端、关系含义、必要条件和依据。修改保留时间、操作及宿主可取得的执行聊天/turn/根聊天信息；宿主不给的字段留空，不编造。每项当前状态只存一处，不再建一套完整的事件认证系统。

自动与手动维护共用一条流程：找变化 → 准备相关新旧材料 → agent 共同阅读并产出节点/边及必要分段 → 可选批量审核 → 一次提交 → 更新受影响索引。自动模式处理当前任务的小批变化，手动模式可以深读、重访旧图和随机共读。默认不加独立审核层，争议关系或专项评估可显式启用审核；错误能在使用中更正。

## 阶段与完成条件

### P0 收敛边界和运行入口

**输入：** 本轮计划、精选调研、AgentTools 现有说明与实际接口。

**动作：** 建立新 Git 仓库和忽略规则；确定包名与四种动作；核对系统 Python、共享权重和现有 GPU 锁/HTCondor 接口；用同一个小资料集完成底座比较并选定一种。共享路径通过配置或安装探测获得，公共源码不硬编码 `D:\AgentTools`。

本轮盘点：AgentTools 只有模型、空 `profile` 和锁状态；系统 Python/依赖位于目录外。不要重建用户已决定留空的 profile，也不建离线 packages 仓库。HTCondor 25.4.0 能查询本机 slot，但当前 `condor_q -json` 认证失败；先查清查询/提交的认证条件，沿现有配置解决接入问题。现有项目 Qwen 文件锁只提供合作式 GPU 互斥，没有统一 CPU/RAM 队列，也没有已完成的 `agent-run`。

**交付：** 可安装骨架、一个小资料集、一份不超过一页的设计决定，列明未选路线的主要理由。首个资料集包含当前/旧决定、低字面相似度关联、两份跨材料关系、图片及待处理材料；人工写出少量预期结果，单独保存以便隔离测试。

**完成：** 新路径可安装和运行；配置能指定项目根；测试数据不含旧业务授权；底座选型结束后不长期维护两套实现。P0 不全量读取旧库、不重新下载已有权重、不改造 AgentTools。

### P1 文字记忆闭环

**动作：** 来源登记、文字检索、片段与原文定位先跑通。生成短项目地图，通过宿主可用的项目启动指令/skill 在正常任务开始时交付最简 `brief`，先用项目核心和少量人工确认线索实现主动提示。提供一个可用的检索 skill：工作 agent 一次派工，廉价 worker 自行检索、评分、整理结果。附一段文件组织建议 prompt，帮助 agent 保存可读资料，不建设自动目录治理模块。先允许显式触发维护，失败保留简单错误和未完成范围。

**交付：** 文本可用版本；一次实际订阅 subagent 检索记录；简短使用说明。建议返回给主 agent 的普通结果默认不超过 6,000 个中文/英文字符，可由调用者调整。

**完成：** 新聊天的普通任务能收到短地图及一个有关线索，未主动检索也有发现信息的入口；同一真实问题能从资料找到依据；找不到时说明具体缺口；主 agent 不必手动调度每轮查询；内容和定位对应；两个项目的相同问题不混入彼此资料。这时即可供小范围日常使用。

### P2 本地向量、图片和语义图

**依赖：** P1 可用；大规模 embedding 前先解决本机资源准入。接入 HTCondor 受认证问题阻碍时，小样例可临时遵守现有 Qwen GPU 锁并明确其不能约束其他 CUDA 程序；不据此启动无人协调的大规模建库。P6 的接口设计可并行提前，完整记忆工具不以完整资源平台建成为前提。

**动作：** 优先复用 AgentTools 已固定的多模态 embedding 权重和环境；本轮调研所见旧方案为 Qwen3-VL-Embedding-2B、统一 2048 维，正式实现时核 revision、预处理与输入合同。查询与资料必须进入兼容的向量空间。先支持图片文件和 PDF 必要页面，视觉 agent 实际看图，保存短描述、必要 OCR/表格与区域定位；识读文本是派生解释。

建图以真实实体、决定、条件和材料关系为主，不能只在有“新洞见”时才建节点。新增与变更时共同阅读相关片段、旧图邻域、检索近邻；手动维护增加小比例随机共读和旧内容重访。先批量合并跨 worker 候选，再应用关系，避免各 worker 只能连到自己的新节点。边独立增改，新增一条边不能覆盖既有其他边。

分段是同次阅读的副产物，不能替代语义任务。普通原件先用稳定的结构分段即可，需要智能边界时再利用同次阅读；不为追求全量智能分段延迟可用版本。

**完成：** 文字问题能召回图片；相关图像能定位原图/页；低字面相似度任务能沿至少一条有依据的跨材料关系找到关键资料；矛盾、更正、删除、节点合并和重复维护有正确结果。只报告有效关系的例子、错误和未测范围，不用边数阈值结案。

### P3 主动提示与增量维护

**动作：** 通过短入口 skill/项目指令在任务开始或接续时调用 `brief`；按任务触发小批变化处理，手动深维护调用同一处理入口。自动维护仅发生于任务过程中，不建设常驻后台 agent。

主动提示优先使用短项目地图、最近变化和相关决定/条件，再按有限预算轮换探索线索。启动不重新遍历全文；初建负责已声明范围的整体整理，后续按变化和重访扩充。已有项目允许分批建库并清楚说明剩余资料。

默认从文件清单、大小和时间等低成本信息发现变化，实际读取时绑定内容版本；不每查询都遍历/哈希全部权重、原件和历史快照。已知变更影响的知识标为待更新或历史，更新前不冒充当前结论。所有资料已登记、已经读过、已经形成语义和已经能检索是不同覆盖信息，直接从实际记录汇总，不另建四套工作流。

如采用独立修改建议中的「已知必读」提案：将少量已确认前提直接传给工作 agent，作为探索性候选的补充；预算不足时明确尚未交付的内容。先用简单显式列表，不复制旧 map 平台和通用依赖推理器。该提案尚未确认，不作为用户要求或其他阶段的前置条件。

**完成：** 在未指示检索的任务中，主 agent 通过启动线索发现一个原本未点名的相关前提；任务内修改资料后能完成一次真实增量维护；自动预算结束能说明下次位置，手动处理可以继续；全程没有被流程要求反复完整载入长合同。

### P4 小型独立评估与机械盘检查

**依赖：** P2/P3 核心行为形成。早期就用 P0 的小样例回归，不等本阶段才第一次试完整闭环。

用约 8–12 个固定任务覆盖主动未知提示、精准查找、跨材料关系、图片、更正/删除、范围隔离和失败。比较三组：普通文件工具；短常驻信息加文件工具；完整记忆。需要时做一次去掉图的消融，确认收益来自哪里。评测起点不用建设聊天 fork，不把答案和评分材料放入被测可见目录；固定模型配置、任务输入和资料范围，报告实际可观察的配置。

| 维度 | 记录方式 |
| --- | --- |
| 质量 | 预先列出的必要信息找回/漏项，错误和过期事实，原文是否支持答案 |
| 主动性 | 未提示检索的任务中发现了什么；不能据几个成功样例宣称解决所有未知未知 |
| 上下文 | 工作 agent 实际收到的字符数、检索委托次数；有宿主 token 数据时再记 token |
| 成本 | 初建、更新、worker 与主 agent 的总墙时/可得用量；无价格或计量则留空，不用字符冒充费用 |
| 维护 | 改动后的正确性、重复处理量、待处理范围、失败是否可定位 |
| I/O | 文件数、读写量与频率；在真实机械盘或明确标注的替代条件上观察，区分冷/热启动 |

**完成：** 核心行为样例通过，报告各任务的收益、无收益或未定条件及成本；即使未发现净收益也如实结束本阶段。质量无收益或维护成本明显过重时，先收敛导致问题的机制，不扩大语料掩盖问题。报告不足以决定时记录未定，不用无限扩测拖延交付。

### P5 独立目录安装试用

**动作：** 在一个与开发目录分离的试用项目安装，使用小型代表性公开/合成资料跑首建、检索、正常修改、任务内维护与手动深维护；再使用另一个独立目录核隔离。若用户已指定真实业务资料，按其范围替换其中一组；未指定时不擅自把旧业务项目变成新试验。

**完成：** 换路径后可用，不依赖旧项目的可变文件或数据库；发现实例问题只回改产品维护源再安装，不产生业务分叉；输出一个短试用报告。真实新业务项目的效果待指定资料后验证，公开/合成安装试用不替代该结论。至此可发布第一版完整记忆工具，不等待后两种工具全部完成。

### P6 资源协调工具

**依赖：** P0 确认现有基础设施。P6 的认证诊断与最小提交适配可以从 P0 后并行提前，以供 P2 使用；完整功能验证不必阻塞前几阶段的小型记忆闭环。

先以两个项目争用同一 GPU 为场景，统一 `submit/status/cancel` 等少量动作。任务明确 executable、参数、工作目录和 CPU/内存/GPU 请求；共享调度保存资源与任务元数据，项目资料和记忆留在项目内。共享代码与本机管理配置分开。

优先利用已经安装的 HTCondor 及其 CLI，核 `condor_q` 认证、实际提交、路径/工作目录、输出和取消。历史轻任务成功不代替本次接入成功。HTCondor 若已能作为中央队列，不再叠一套互不知情的调度器；如存在具体不适配，记录原因后选择最薄替代。basePack 管理的 embedding 服务、普通 GPU 任务通过同一资源分配规则；外部直接启动的程序仍需使用者协调，不承诺全机强制管控。旧 Qwen 锁向队列切换时验证兼容期不会双重授予 GPU，不把锁文件存在当作持有证明。

**完成：** 实际观察两个项目的请求、等待、取得资源、执行、正常释放、取消和异常退出清理；CPU/RAM 按声明额度预留与排队，两个请求超过总预算时不同时准入，不把预留等同于操作系统硬限制；请求大于可用资源能显示原因；空闲时无高频写盘。先以整卡串行为保守默认，显存并发作为实测后的配置；不扩展为统一计算云平台。

### P7 分层 agent 组织

从 P1/P2 的实际派工提炼短角色 skill 和任务包。任务包只含目标、范围、必要材料入口、约束、输出和预算。返回包含结论、直接依据、已做动作、缺口/下一位置；有相关内容就返回内容，长证据给精确链接。链接只是入口，关键判断者仍要读必要依据。

主 agent 负责目标和高层取舍；协调 agent 定界、去重、汇总；廉价执行 agent 广读与执行。默认每个协调者最多管理四个廉价执行者，简单任务跳过协调层。新主题使用干净起点避免无关历史，同一任务需要续读时可沿同 worker 继续，不建设独立的上下文认证流程。

**完成：** 一个广读任务在单 agent 和分层方式下各跑一次，比较完成质量、主上下文、总成本和耗时；主 agent 能依据精选材料决策，执行者的重复劳动与遗漏可见。模型名称和推理强度放配置，角色不写死为某一代型号。

### P8 联合交付与轻量发布

联合场景：业务主 agent 提出资料问题 → 检索团队返回证据 → 项目有变更时增量维护 → embedding 等重任务经过资源协调 → 新结果保持项目局部。短文件读取和每次 agent 派工不进入重任务队列。

发布仅包含源码、skills、安装配置、依赖声明/必要锁、小样例和短文档。权重、虚拟环境、数据库、缓存、原始聊天、业务资料、大测试结果及多份升级备份不进 Git 或发行包。版本通过可用的远端/包索引恢复依赖，通过配置绑定本机共享资产；不把本机绝对路径当作安装要求。

建议第一版预算：被跟踪文件的逻辑总大小目标不超过 **20 MiB**、普通单文件不超过 **2 MiB**，发行压缩包目标不超过 **10 MiB**。这些是 agent 提出的起始预算，用户可调整；例外先说明具体必要性，优先外置。实施时直接基于待提交文件计算，并看仓库历史有没有误纳大对象，不仅量压缩包。初始源码从新仓库开始，不导入旧 Git 历史。

调研时 [basePack](https://github.com/YS-Pan/basePack) 连接器返回 public、默认分支 main、size=0；这不单独证明无提交，首次推送前读取实际远端引用。新路径安装、核心闭环和发布清单检查完成后再发布。本轮不提交或上传产品，也不修改远端。

## 工作方式与停止条件

- 一个功能批次一个主 owner；不同人可并行研究/写独立模块，写同一数据存储和最终整合顺序执行。
- 先验证完整的最短实际流程，再补局部优化。修复真实事故保留一个对应回归，不照搬旧测试矩阵；文档小改只检查相关内容和链接。
- 避免静默 fallback、广泛 catch 和猜测成功。错误直接返回可操作原因；完成标准达到即结束该批，不再追加假想风险检查。
- 默认不做层层复审、不逐事件落一堆小文件、不每细修就完整打包安装。形成可用功能批次后统一发版；阻断用户的具体缺陷可单独修。
- 控制常驻入口：建议项目启动说明约 1,500 字符内、单个通用 skill 约 3,000 字符内，细节按需链接。超出时删重与拆按需资料，不增加新的全量必读链。
- 原始材料和已知更正需可回查；索引可重建。首版使用数据库事务与必要内容版本即可，不建设全面快照、协议签名或审计平台。
- 阶段结束只记录结果、实际检查、余项及设计决定；不把长过程复制到战略计划。用户新指令改变范围时更新本执行计划和唯一进度来源，避免讨论中的要求丢失。
