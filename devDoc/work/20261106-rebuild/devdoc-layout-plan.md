# 将 devDoc 结构纳入记忆系统推荐方案

2026 年 11 月 7 日记录。用户明确提出：当前项目的 `devDoc/` 文件结构，可以作为记忆系统推荐的文件结构之一。此方向已确定，推荐 prompt、示例和效果验证待产品实施。

## 适用场景与参考

适用于开发者与 agent 共同维护、需要区分长期依据、现行说明、活动工作和历史材料的项目。参考本项目的 [文档维护约定](../../documentation.md) 与 [当前结构](../../current/architecture.md)，提炼可复用的组织方法。

```text
AGENTS.md                       简短入口与任务路由
devDoc/
  项目目标与长期依据.md
  current/                      现行说明
  work/YYYYMMDD-short-topic/    活动工作的计划、进度、调研和结果
  archive/                     已结束的工作目录
  change_log/major/            每次重要变化一个文件
  change_log/minor/            每次有意义的局部变化一个文件
```

这是一种可选择、可调整的方案。根据项目实际材料创建目录，尊重已有结构与命名，小项目可合并文件；采用其他布局的项目同样应能使用记忆工具。源码、用户操作文档、原始资料和大型运行产物按其职责另行安排。

## 实施计划

1. **P1 提炼推荐 prompt。** 随记忆工具提供一段给 agent 的短提示与小样例，说明适用条件、内容归属、单一维护位置、工作结束后的整体归档及按次变更记录。样例使用通用内容，保留一个维护源，通过链接或生成方式分发。
2. **P1 接入项目建议。** agent 根据项目内容、已有约定和当前问题，说明是否适合采用此方案及需要怎样调整。建议应能增量采用；实际目录迁移属于相应项目的具体任务。
3. **P1/P3 衔接记忆读取与维护。** 目录作为材料职责、状态和关联的线索，结合内容与版本识别现行结论、提案和历史依据。相关文件或章节同批读取，需要语义判断时一次委托检索 worker；移动、修改和归档后更新受影响的来源定位。归档材料仍可提供有效证据。
4. **P4 复用自用验收。** 纳入 [devDoc 自用与读取轮数](agent-plan.md#devdoc-自用与读取轮数) 的任务，检查推荐是否使材料归属和证据更清楚，能否减少主 agent 无效往返，并记录必要信息遗漏、维护负担与主/worker 合计可得用量。按实际结果说明适用边界，不以目录整齐或文件数量代替效果。

## 完成条件

能向合适的项目提供该选项及具体适配建议；短 prompt 和小样例可随工具分发，包含来源定位、读取和维护的说明；自用结果可回查，明确已验证与未验证的效果。推荐材料只保留通用方法，本项目纲领、历史、业务状态和机器路径继续留在本项目。
