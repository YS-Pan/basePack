# 项目术语

遇到不同叫法时，用任一表述查本表，按所列语境确认含义。新写的文档和派工用首选词，必要时在第一次出现时括注原来的叫法。引用原话、命令或字段时保留原写法。新增同义叫法就补在现有条目。如果简称可指不同对象、阶段或版本，写明适用条件或分别列出义项。比如「入库了」应说明是已采集原件、已登记来源，还是已发布知识。

## 记忆来源与维护

| 首选词 | 其他叫法或查找线索 | 含义与边界 |
| --- | --- | --- |
| Codex 聊天 | Codex thread、Codex 会话，常简称「聊天」或 `thread` | 宿主持久化的一条对话。一次交互是其中的 turn，精确回读还可定位到 item 和 part。 |
| 来源原件与来源记录 | 材料、原件、来源登记 | 原件是文件、图片或聊天等材料。来源记录保存原件的身份、位置和版本。登记确认来源进入管理范围，理解和知识发布另有记录。 |
| 聊天采集 | 采集聊天、抓取聊天、保全聊天原件 | 从宿主保存项目聊天原件和采集回执。讨论「聊天入库」「已摄入」时，分别注明已采集的范围、已发布知识的范围和兼容向量覆盖。 |
| 聊天采集覆盖核对 | 聊天新鲜度、采集对账、`memory check-codex-capture`、`memory freshness`（兼容名称） | 只读对照 Codex 当前可见的聊天与已保存原件。逐条核对可确认指定聊天的文本覆盖，知识是否发布另行查看接受记录。 |
| 保留原件 | 已保留原件，聊天语境中的「已有快照」 | 先前保存的原件。`--retained` 选择用这些原件开展维护，本轮聊天覆盖仍待核实。 |
| 知识发布 | 语义接受、发布记忆、写入知识库 | 作者完成稿由程序核验后提交，成功后已接受的知识可供查询。提案、采集回执和已发布知识各有自己的状态。 |
| 手动维护 | 显式维护 | 用户明确要求执行的记忆维护。「做一次维护」通常指这一流程。自动维护随业务任务按条件启动，手动审计按明确的审计意图触发。 |
| 维护候选与检索候选 | 两种语境下都简称「候选」 | 维护中的来源候选通常按待处置的原件路径计数，一个来源可产出多条成员，或经阅读后无需新增知识。检索候选是进入筛选的成员、语义节点或关系版本。 |
| 维护波次 | wave、读者波次 | 用固定读者池处理一组语义任务的派工单位。同一轮维护可以跨多个波次。阶段接续保存已处理和剩余范围，发布批次是程序提交的单位。 |
| 记忆维护所有权 | 维护 owner、单 owner | 控制本项目同一时刻由哪一轮维护执行预检和发布。协调者是宿主中的角色，检索和独立采集均可在维护所有权之外运行。 |
| 私有资料 | 私有开发上下文、限制分发资料 | 包括隐私、机密及版权或许可受限资料。`private/` 是一种存放位置，`private` 是记忆记录的分发标记。`source_scope` 用于发现额外来源，`memory.private_scope` 用于补充原位私有分类。 |

## 记忆检索与行为

| 首选词 | 其他叫法或查找线索 | 含义与边界 |
| --- | --- | --- |
| 启动简报 | `brief`、记忆简报 | 任务启动时读取已发布的必保留条目、项目概况线索和已知缺口。针对问题的搜索与回源属于检索。 |
| 必保留信息 | `mandatory`、必须保留的信息、必读记忆 | 常驻信息中无条件交付的一类。常驻信息还包含按需保留的信息。「必读」指保留在简报中，知识待核状态仍随条目交付。 |
| 检索成员 | `member`、成员 | 文件摘要、实际章节摘要、智能原文块或图片的记忆表示，同一成员可检索也可作图节点。成员数只描述表示规模。 |
| 语义节点与图关系 | `node`、语义边、图边 | 独立语义节点表达实体、决定、条件等，以成员为依据。语义边表示有依据的关系，可带条件。字面相似、同目录或共同交付只提供候选线索。 |
| 语义知识与派生索引 | 知识内容、文字索引、向量索引 | 语义知识由 agent 根据原件判断并保留依据与更正。派生索引用于召回，重建索引只更新检索表示。 |
| 原证回读 | 回源、回读原文，「补读」可指直接读未采集的聊天 | 顺着依据查到可核对的正文或图片。已发布知识用 `id` 和 `knowledge_revision` 定位，作为依据的来源快照用 `source_version` 和范围或图片定位信息固定。 |
| 检索交付 | 实际交付、实收 | 主任务收到精确知识版本。「确认交付」或「交付记账」指宿主随后用 `memory delivery` 登记实际收到的内容。召回、回读、排名和生成待确认回执都是前序步骤。 |
| 连续相似度加权遗忘 | 相似度加权遗忘、Gaussian 连续降权 | 某版本未再次交付时，按后续交付活动与它的行为相似度调整访问权重，交付该版本会刷新访问状态。低权重的正文、依据、图和索引仍保留，材料仍可被检索。 |
| 访问投影 | 行为访问投影、访问状态。「投影追平」指编译游标到达事实头 | 从已登记的事实和当前行为模型算出的访问状态。「追平」时最新事实已纳入计算，即 `compiled_j = fact_j`。事实游标 J 和只随非空交付推进的机会钟 C 各自记录。 |
| 检索排序与模型秩 | `memory rank`、KL-NMF 的 `--rank` | 前者按综合分排序、去重并应用字符预算。后者设定行为表示的维数。Gaussian 的相似度作用范围由其带宽参数决定。 |

## Agent 与宿主

| 首选词 | 其他叫法或查找线索 | 含义与边界 |
| --- | --- | --- |
| 性能（agent 与团队） | 完成任务的能力、成果质量 | 包括能否处理单 agent 原本无法完成的材料规模或复杂任务，以及正确性、完整性和判断质量的提升。协作是否成功以能力和成果为准，允许增加用量以提高性能，用量和耗时作为代价单独记录。 |
| 维护协调者 | 协调、协调 agent、coord，维护语境中也用 Terra 代指 | 组织维护读者并汇总发布的角色。Terra 是模型系列名。角色、配置选定的模型和宿主实际派出的模型分别确认。 |
| 维护读者 | 读者、reader、维护 worker，派工名称前缀 `bp_w_` | 领取维护工作、阅读来源并提交语义稿的角色。维护对话中的 Luna 有时指读者，检索对话中也可能指检索 worker 使用的模型。 |
| 检索 worker | 检索子代理、search worker、search subagent，派工名称前缀 `bp_mem_search_` | 在一次委托内完成多轮检索、回源、评分和证据交付。结果交给调用的业务任务。准备请求、宿主实际派工、主任务收到结果是三个阶段。 |
| 子代理启动与唤回 | 派工、`spawn_agent`，续接、`followup_task` | 宿主派工创建新子代理。唤回已结束当前 turn 的协调者时，沿用同一身份启动下一 turn。仍在原 turn 内等待事件的 agent 可由相应事件继续。 |
| AI 档位 | AI level，纲领和旧文中的 `tier1` 至 `tier4` | 现行配置与 CLI 使用 `level`，数字越大，能力档越高。常用分工是 1 档广读与检索、2 档协调、3 档日常工作、4 档高难度专项。具体模型和推理强度由项目配置维护。 |

## 部署与资源

| 首选词 | 其他叫法或查找线索 | 含义与边界 |
| --- | --- | --- |
| 产品源码与项目实例 | 上游源码、本地客户端、业务项目、共享资产 | 产品源码维护可复用工具，安装包提供实际执行的客户端。项目实例保存自己的配置、来源、知识和任务状态，模型、环境和机器设施可以显式复用。 |
| Codex 项目绑定 | 聊天归属、Codex project ID | 宿主注册的项目与聊天之间的归属关系，用于圈定采集范围。basePack 项目实例有自己的配置和记忆库，记忆项目 UUID 用来核对连到的库。 |
| 项目记忆库 | 项目库、本地记忆库、在用库 | 指特定项目的数据库。`store` 在路径语境下指物理数据目录，schema 指库内数据结构版本，客户端版本另行记录。回退入口是恢复先前运行方式的脚本或步骤，可重新打开同一份数据，也可能指向保留的旧库。 |
| Codex 宿主状态库 | 宿主 SQLite、Codex 状态库、`state_5.sqlite` | Codex 本机的宿主状态。聊天采集与覆盖核对可能在这一侧遇到权限错误。项目记忆库由 SurrealDB 持久化，连接和读写状态另行核对。 |
| 动态端口 | 自动分配端口、按次分配端口 | 项目库启动时由系统分配回环端口。配置中的 `:0` 表示分配方式，客户端使用本次运行公布的实际地址。 |
| Windows 用户计划任务 | 用户任务、用户级任务 | 本项目用来按需启动项目库或共享 embedding 的托管方式。Windows 服务由 SCM 管理。共享 embedding 服务也可指模型提供的接口，需看讨论的是接口还是启动方式。 |
| Auto Review | 自动审查，Codex 权限语境中也称自动审批、auto approve | 宿主审查一项权限请求的方式。用户授权确定任务范围，宿主决定是否放行该次调用，实际访问由运行账户的系统权限决定。 |
| 软件发行 | GitHub Release、公开发行、发布版本 | 提供可下载版本及对应产物。源码提交、推送、构建候选包、安装到项目和正式发行分别记录。 |
