## 实施顺序

### 1 确定发布内容

保留当前项目自己的开发历史，核查所有将推送的可达提交，不引入旧项目历史。Git 保存源码、测试、依赖声明与锁文件、skills、短文档和小样例；模型、环境、数据库、密钥、缓存、作业材料与大运行产物留在本机，复核并补齐实际需要的私有配置忽略规则。按 [P8 的建议预算](plan.md#p8-联合交付与轻量发布) 统计文件和历史对象；发现实际误纳再定点处理。

核对许可证与第三方声明。项目许可证由用户选择后补入根 LICENSE 和包元数据，现有 Qwen 声明保留；若暂不授权复用，在发布说明中明确当前许可状态。

完成条件：待发布文件与历史范围明确，凭据及本机运行状态未被纳入，许可处理方式已确定。

### 2 补齐面向新用户的入口

调整根 README，说明四项能力、Windows 与 Python 3.13 的支持范围、当前成熟度，并提供从 clone 到安装轻量客户端的可执行命令。包位于 `experiments/20261106-basepack`，根目录不是 Python 包；从仓库根安装须显式指定该目录。

路线 README 与使用文档分别给出纯文字记忆、图文 embedding、HTCondor 作业及独立 skills 的入口，按所选能力说明需要的设施。新用户无需先安装全套模型服务才能尝试文字记忆或使用通用 skills。

将通用安装步骤中的本机路径替换为用户选择的路径；本机实测留在开发说明。检查公开文档指向被忽略的 `artifacts/`、`dist/`、`.basepack/` 的引用：用户所需步骤和结论在 Git 中可读，原证注明本地保留；选用的交付 wheel 转为 Release 附件。

检查根 AGENTS 的启动约定：新 clone 尚无 `.basepack/instructions.md` 时应能进入初次接入流程；启用后才读取该本机入口。核对通用 skills 的安装/发现方式，覆盖不随 Git 分发的 `.agents/skills` 本机联接。

完成条件：仅凭仓库内文档即可找到安装、配置、使用和开发入口；使用者无需依赖作者机器上的现存文件。

### 3 从待发布源码验证

使用待发布提交生成干净副本，在根 `tmp/` 的独立 Python 3.13 环境按路线 README 安装依赖、运行已有回归并构建 wheel。先核源码回归的实际导入位置，再从源码外普通安装本次 wheel，核版本、导入位置和包内模板、schema、memory skill。临时目录与端口独立于正式项目，保留正在服务其它聊天的数据库和共享服务。

验证最短实际流程：

1. 新项目 `init` → 配置 → `memory init/brief` → 示例 `prepare/apply/search/read/neighbors`，完成纯文字记忆闭环。
2. 宿主订阅 agent 读取两份小材料，实际完成一次分块、关系写入与评分检索；修改一份材料后执行必要的小批维护，验证新知识和旧依据的状态。
3. 连接已有共享服务完成图文编码/检索；提交一个小型 HTCondor 作业并取回结果。共享设施复用，业务项目配置和数据独立。
4. 在新目录核对两项通用 skills 的可发现性和使用入口；分层协作尚未完成的质量对照按现状披露，不扩成首次上传前的新研究任务。

完成条件：现有必要回归通过，新目录和普通安装的核心流程可用。记录提交、wheel SHA256、实际环境、结果与未测范围；已有质量和费用结论保持其原边界。

### 4 上传源码

完成上述准备后汇总待推送提交、变更摘要和验收结果。当前用户只要求计划，后续收到上传指令再操作远端。

执行时重新核对目标仓库及远端引用，配置 `origin`，预览推送内容，再将本地 `main` 正常推送至目标 `main`。若远端期间有新增提交，先核对内容与历史关系再处理，保留双方有效修改。同步简短的仓库简介与能力说明。

完成条件：GitHub `main` 的 SHA 与验收提交一致，首页、相对链接及源码目录可正常浏览。

### 5 核验分发并按需发布附件

从 GitHub clone 到另一目录，按公开 README 重新安装轻量客户端并运行最小文字记忆流程；核独立 skills 的分发入口。这一步检验 Git 忽略和本机文件是否造成遗漏。

如需直接下载 wheel，在已验收提交打版本 tag 并建立对应 Release，附本次 wheel、SHA256、简短功能与支持范围说明；版本号以最终交付包为准。PyPI、跨平台支持与更广泛性能评测另按需求安排。

完成条件：远端 clone 的新用户流程通过；如提供 Release，tag、源码、包内版本及附件一致。
