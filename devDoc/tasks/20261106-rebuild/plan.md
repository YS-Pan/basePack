# 重建实施计划

2026 年 11 月 7 日用户指定下一阶段先做计算资源协调，按 [资源协调专项计划](resource-coordination-plan.md) 从真实接入推进到跨项目争用验收；它不依赖记忆系统完成。文件结构与分层协作已有 skill 初版，资源工具交付后继续下面的记忆建设顺序。旧项目只取思想、事故样例和少量可复用接口；不搬入数据库、旧任务系统和整套维护流程。

1. **做出最小可用记忆。** 少量项目说明负责常驻提示；文字检索与原文定位先跑通。用一个廉价检索 agent 筛选和评分，主 agent 一次派工取得紧凑结果。
2. **补齐图、向量和图片。** 复用成熟检索底座、系统 Python 环境与 AgentTools 中的模型；建图必须真正产生可解释的关系并帮助跨材料发现。手动深维护与任务内增量维护共用处理流程，审核可选。
3. **验证主动发现与总成本。** 用隔离的小型真实任务对比普通文件、常驻提示和完整记忆。重点测未点名信息是否被发现、更正是否生效、主 agent 少读了多少，以及维护是否值得。
4. **接入资源协调，当前提前实施。** 按 [R0–R5](resource-coordination-plan.md#实施批次) 提取旧 runtime/服务和提交样例，改造跨项目共享 embedding；普通重任务交 Condor，按显存预算与独立 embedding 并行，交付一次调用与两个项目的真实联合验收。
5. **沉淀分层协作。** 已提供 [agent-team skill](../../../skills/agent-team/SKILL.md) 初版，支持主 agent、协调 agent、执行 agent；结合记忆任务继续比较质量、主上下文、总用量与耗时。小任务保持简单，不强制组队；[参考与检查](research/agent-team.md) 保留证据边界。
6. **发布轻量 basePack。** 只上传源码、skills、短文档、依赖声明和小样例。新路径安装能复现，模型、环境、数据库和大运行结果留在仓库外。

记忆建设的前两步就交付可使用版本，各工具仍可独立交付。开发按完整功能批次验证和发布，不为每次细修重复制作整套交付物。每项新增机制必须服务于具体需求或已经出现的故障；失败直接报告，不用静默回退制造成功。

战略以 [项目纲领](../../project-charter.md) 为准；任务、验收和建议的大小预算见 [AI 执行计划](agent-plan.md)。[近期历史](legacy-history.md)解释这些取舍的依据；推进情况见 [工作进度](progress.md)。
