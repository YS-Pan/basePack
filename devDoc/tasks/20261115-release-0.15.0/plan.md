# 0.15.0规则修订、记忆维护与发行

2026-11-15。用户要求移除普通task自动退役机制，说明复杂工作不适合ongoing；判断当前记忆是否需要维护，必要时维护，再推送GitHub并发布0.15.0。

1. 删除普通task“完成即自动归档”的活规则。按用户明确要求进行的任务归档作为普通工作；不撤销已完成归档。ongoing仅适合业务中可顺手完成的有界小整改，复杂调查、完成状态判断、跨任务清理／批量迁移转普通任务。此前明确的ongoing期限与到期归档保留。
2. 文档稳定并提交后，执行一次全项目显式记忆维护，固定候选与聊天截点；按实际layout派协调者及作者，处置已知反馈，完成后核发布状态并stop／release。未经处理的范围及真实阻塞如实报告；不追加语义审计，不把业务收尾后的新增记录冒充已纳入固定回执。
3. 从确定Git提交隔离构建0.15.0普通wheel，核包文件、metadata／RECORD／许可、普通安装和短入口；已有0.15完整功能与GPU／HTTP证据沿[实施结果](../../archive/20261115-runtime-and-maintenance/result.md)，文档变更不重跑全套产品测试。旧身份迁移ZIP沿用原字节，生成本次校验清单。
4. 核远端main及标签，以正常push推送已授权修改。准备Release草稿及附件，确认版本／提交／内容后公开0.15.0并设Latest，实际下载校验，再记录发行结果与推送文档。GitHub连接器无发行附件能力，沿本机Git／gh及既有认证执行，不输出凭据。

主agent统一判断、提交、维护生命周期和发布；规则与发行准备由两独立分支负责。源码、模型、数据库和服务的已有功能不在本次重构范围。开发任务保留当前位置，按新约定不在收尾自动归档。
