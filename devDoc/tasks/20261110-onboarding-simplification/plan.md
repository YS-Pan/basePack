## 目标与范围

完整项目接入应使所选技能可被宿主发现；新 shell 使用记忆无需手工装载密码；命令只加载实际需要的配置；检索输出与内部编码逻辑各保留必要的合同。增量维护先由脚本判断字节变化、换行等价及位置映射，只有剩余语义工作进入agent，减少重复阅读和派工。

拟将数据库收敛为**可信本机、仅回环监听、免认证**这一种运行方式，删除产品密码机制。该方案意味着能连接端口的本机程序具有数据库管理权限；项目 UUID 负责防误连。此处记录拟实施取舍，现行带密码流程在实施前继续有效。

保留独立技能的维护位置与按需使用、项目独立数据库与 UUID、原生备份、已发布快照回源、版本标识、stale/retired、向量补建及 jobs 的 run/submit/wait。项目纲领正文保持原文。

## A．补齐技能接入闭环

1. 在[项目接入](../../../experiments/20261106-basepack/docs/setup-project.md)加入完整步骤：选择所需技能 → 安装完整目录或建立项目内发现联接 → 核对入口与引用 → 核对宿主实际发现。`init` 生成程序接入材料，core doctor 检查其既有范围；两者成功不代表独立技能已安装。
2. 通用技能仍从根 `skills/` 获取，resources 从实验工程获取；保留现有 wheel 合同。新项目优先把所选完整目录放入 `.agents/skills/<name>/`。已有 `skills/<name>/` 维护原件的项目建立指向它的 junction，保持一个维护源。
3. 重复执行先核已有目录及目标；正确入口直接复用，同名用户技能或不同目标联接保留原状并报告冲突。说明复制目录随项目保存，忽略的本机 junction 在新检出后需重建。只用 wheel 的使用者另取配套源码中的独立技能，无需因此重装客户端。
4. 同步根 README、路线 README 与接入说明，修正路线 README 的“两项通用 skills”；将 resources skill 中复制后失效的 `../../docs/...` 改为仓库公开文档链接。随包记忆 skill 继续由 `memory guide` 和 instructions 直接到达。
5. 外部修复方案：在 array reconstruct 已有两项原件上补 `.agents/skills` 入口，沿该项目约定记录及核对实际发现。新增加的 engineering-judgment 是否选用独立决定，不因本次修复自动加入。

**完成条件：** 所选技能文件及同目录参考完整，指针可达；真实目标项目的宿主列表或新聊天显示所选技能的名称与项目作用域。宿主结果不可取得时如实记为待核。这里验收安装与发现，不安排技能行为、触发、效果、收益或专门测试项目。

本批采用现有复制/联接方式和实际宿主验收，不新增安装平台、技能清单状态、默认全装或 wheel 打包机制。

## B．删除产品密码机制

### 实现与文档

1. 在唯一配置边界限定 memory endpoint 为明确的回环地址，launcher 显式使用回环 `--bind` 和 `--unauthenticated`。禁止把免认证服务绑定到通配或局域网地址；共享 embedding、Condor 的认证与部署合同不在此次改动内。
2. 删除 `memory.username/password_env/password_file` 模板字段、`ProjectConfig.memory_password_file`、config show 对应输出、客户端 Basic Authorization 及只服务于它们的导入和测试分支。同步 launcher 中的 SURREAL_USER/PASS 设置。
3. 将 `memory init` 生成入口缩短为显式 Python、绝对配置与一次 brief 调用，保留 UTF-8 和原始失败。删除新 shell 读取配置再加载凭据的桥接；更新随包 memory skill、两级 README、接入/管理员/记忆文档及现行 system 说明。
4. 用 SurrealDB 原生 `--allow-origin` 收紧默认跨域范围，并验证实际浏览器请求行为。CORS 不能代替访问认证；不能只凭缺少响应头宣称写请求已被阻断。仅可信本机使用的边界须写在部署动作旁。

官方已提供[免认证模式](https://surrealdb.com/docs/reference/cli/db/commands/start#unauthenticated-mode)和[监听与 CORS 参数](https://surrealdb.com/docs/reference/cli/db/commands/start#command-help)，本机 SurrealDB 4.0.0 帮助也已核对。免认证下 guest 具备 root OWNER 权限。现有库读写、导出及浏览器行为本轮未实测。

### 迁移顺序

1. 先在一次性库验证无凭据 init → apply → brief/search/read/neighbors，以及原生 export/import；再用既有版本备份恢复集合，保留旧 wheel、配置、launcher 和必要回退凭据。
2. 将一个现有库的原生导出恢复到独立目录/端口，验证免认证后的旧快照、图、图片和兼容向量。核对 UUID 及七表（meta/source/source_version/member/node/semantic/change）逐记录逐字段，不能只比计数。
3. 确认共用客户端的全部在用项目和调用方，安排每项目短暂停写。先停止自动维护及相关调用，再停止该项目数据库进程；确认监听和进程树退出后，以原 store、原 UUID 和免认证 launcher 重启。一次只迁一个项目，不并行打开同一 store。
4. 在受控迁移窗口普通升级共用客户端，删除在用配置的旧凭据字段并刷新入口；新旧客户端与服务认证方式必须在业务恢复前一致。失败保留原错，按已保留的 wheel/配置/launcher 回退，不通过清库重建绕过。
5. 新进程在无密码环境变量、无运行时密码文件的条件下读写成功后，再恢复业务。确认回退资料后移除原在用密码文件；历史备份中的恢复材料按其保留约定管理。保留原 UUID、目录、知识、ID、来源、快照及 stale/retired 状态，无需重新建库、总结或编码未变向量。

**完成条件：** 上述无凭据闭环、原生恢复、误连 UUID 拒绝和非回环 endpoint 拒绝均有实证；新 shell/新聊天可直接 brief；正式项目数据保持，回退路径可定位。产品只保留免认证合同，不再新增自动找密码或双认证模式。

在 B/C 接口稳定后，仅提取 `candidate_vectors.py` 与 `vectors.py` 共同的“一批输入调用服务并核对 identity/返回数量”逻辑，必要时共用文字/图片输入构造。先确认净减少重复和维护位置，再决定是否提取；两行分批循环无需单独框架。

**完成条件：** 模型身份变化、缺失/错数量、已有向量复用、图片补建、编码期间 stop 和过期候选冲突的已有行为回归通过。若合并反而增加模式参数或跨层状态，本批保留必要重复并记录理由。

## E．脚本优先的增量维护（优先实施）

### 机械处理与语义判断

在现有 memory 维护入口中先运行确定性程序，合并声明范围的来源变化、既有待核及未完成候选，按来源生成小批。宿主以现有工具独立启动预检，业务不等待；尽量批量发出已有调用，减少工具往返。brief/search/read保持纯读，扫描与写入归维护路径。纯机械批次直接执行，确有语义剩余时再一次派给订阅维护worker。自动维护可接续历史小批，业务结束按control停止；积压较多只建议另开独立手动维护，不据此退出全部自动工作。

| 实际情况 | 脚本职责与处理结果 | 语义agent的工作 |
| --- | --- | --- |
| 只有mtime等元数据变化，原字节hash相同 | 更新来源元数据，保留已有知识与索引；不顺便清除原有stale | 无 |
| 整文件仅CRLF/LF变化 | 仅在比较视图将CRLF转为LF，确认全文件正文等价；沿旧/新行对应生成原件定位及必要更新批，复用原ID、标题、摘要、父级与覆盖说明 | 无；既有更正/退役或其它未决语义状态另行保留 |
| 局部原文块仍在，只是位置变化 | 用旧/新完整行序列及唯一匹配生成定位、未变块复用与差异范围；已证明的机械事实由程序完成，不让agent逐块确认相同文字 | 只处理实际变化的上下文、摘要覆盖及相关关系；定位相同不等于语义全部有效 |
| 正文变化、位置有歧义或结构/条件变化 | 给出变化片段、候选位置、受影响父级/依据及旧版本入口，保留未决范围 | 阅读必要新旧上下文，智能分块、更新摘要/关系并接受结果 |

按[定位积木选型](research/text-anchoring-libraries.md)复用 `content.py` 的原字节读取、标准库 `re` 的escaped literal/lookahead全候选匹配、`store.py` 已使用的 `difflib.SequenceMatcher` 及 `bisect` 行号换算。一期零新增定位依赖；不采用缺少成熟使用证据的reanchor，也不自研编辑距离、近似打分或通用锚定框架。归一视图仅用于CRLF/LF比较，不改业务原件，不strip、不折叠空格/缩进。精确查找保留重叠命中、完整前后文命中与0/1/多候选；位置须落完整原文行边界。重复时结合旧/新行映射和既有父级范围核实，旧位置接近不能代替唯一性，未决候选交语义处理。

成熟同类实现以Hypothesis为首选参考；其纯字符串核心需要固定release源码复用，最终返回近似最佳项，不能直接作为strict/fresh判断。一期严格机械处理无需它的近似排序；以后真实需要正文改写后的候选建议时再验证该核心，不因JavaScript而排除，也不先堆叠多个fuzzy库。具体分发、采用证据和限制见选型报告。

整文件等价可以机械复用已接受语义；局部文字相同仅证明文字和位置。移动到不同标题/父级、上下文条件变化、章节范围新增例外时，相关摘要和关系仍待语义判断。程序只向agent交付必要变化、受影响摘要/关系和可回读依据，不重复发送全部未变原文；agent可按需要展开原始材料。

### 发布、向量与历史边界

- 沿现有 `prepare/expected/apply`、来源hash核对、知识版本及任务stop仲裁发布。完整回执保存到项目 `.basepack/memory/` 的本批材料，宿主只接收数量、需语义范围及路径；脚本处理不冒充agent阅读、总结或建图。
- source/source_version 继续记录原始字节；新原件版本与旧快照分别保留。更新到新原件时，chunk取真实原文，raw_revision/input_revision按实际输入重算。只有标题、编码文本及embedding identity均未变才复用向量；块字节因换行变化时由程序完成必要重编码，不能把归一hash伪装成原hash。摘要文本未变可复用其向量，不为本批改动向量身份合同。
- 有效关系可继续引用明确的旧snapshot，不为位置变化全面改写basis。确需更新依据或恢复待核关系时，按既有事务规则处理相关成员、节点和边，避免只重交node使边留在新一轮待核。
- 历史stale只在其机械等价及依赖有效性可由现有证据完整确认时自动恢复。检查自上次接受以来仍生效的更正、退役和依赖状态；仅“最后一次命中detected_change”不足以排除此前已知错误。证据不足就保留语义候选，不批量stale=false，不复活retired。
- 部分机械批次完成后，其余语义范围必须跨任务继续可发现；来源基准前移不能吞掉未更新摘要。结合现有source/member/basis版本与实际范围计算剩余候选，固定历史依据和核实未变的兄弟不一律算积压。按来源合并推进，不把426条记录拆成426次agent阅读。

主要实现位置为 `memory/content.py`（比较、行映射）、`store.py`（候选、复用与发布）、`cli.py`（薄入口/输出）和随包memory skill/生成instructions（先机械后语义的派工与接续）。复用 `candidate_vectors.py` 的既有输入版本判断及 `maintenance.py`，不另建状态队列、后台服务或审阅层。先跑通一个机械闭环，再接续语义小批。

### 完成条件

1. 只有纯元数据或整文件CRLF/LF变化、没有其它语义候选的真实闭环不创建语义维护worker；机械相同文字不要求agent重新阅读/复述。有其它语义待核时独立接续它；相同输入不重编码，实际输入变化才编码，旧snapshot精确回源保持。
2. 在文件前部插入内容导致后续块整体移动时，脚本给出正确新行号及未变块映射；agent材料只含实际变化及必要上下文。复制同段、移入另一标题、追加例外分别进入准确的歧义/语义候选，不能误称完整维护已完成。
3. 更正/退役后又被detected_change触及的样例不会被机械恢复；独立语义待核、来源缺失及坏snapshot保留真实状态或原始错误。
4. 来源/知识并发修改和stop先到时沿现合同拒绝该批；先前已发布机械批次保留，后续业务能继续发现尚未处理的语义与历史待核，覆盖sources-only盲区。
5. 用已选留的267个待核原文块作只读回放，核对既有110个归一后唯一完整正文匹配及其中86个完整literal前后文匹配的定位结果；本轮已验证标准库re与regex全部span一致。实施时覆盖复制/重叠及Unicode边界，再在隔离库验证可机械完成与需语义两类。记录机械完成数、需语义范围、实际编码量及实际派工，不能把110或86个匹配预先算作自动恢复或节省额度。产品修改时保留对应回归，选型探针不修改正式库。

## 实施组织、检查与交付

主 agent 负责最终契约、跨文件整合、普通安装及 main 提交。E由一个记忆owner贯通机械分类、派工材料、候选可见性与发布；A可独立推进。B的配置、存储和入口由一个owner贯通，C/D按依赖接续，避免并写cli/config/store。外部项目修复与数据库切换沿对应项目授权和记录约定执行；实施后在原技能调查处补结果指针，保留调查当时的事实。

建议按 E → A → B → C → D 分为可独立完成的提交；A的独立准备可与E并行。每批完成相关检查后在main提交实现、文档与change_log，保留用户已有改动。没有实际收益的D可以据证据不做。
