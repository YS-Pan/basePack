## 1. 更新版本命名

目标：后续完成交付的常规版本使用简洁数字版本，如`0.13.0`；`.devN`留给开发周期中的中间构建。项目仍在开发、兼容与验证边界继续由README和发行说明明确，不由版本字符串代替。

依据：[Python版本规范](https://packaging.python.org/en/latest/specifications/version-specifiers/#developmental-releases)中，`.dev1`是对应基础版本的第1号开发发行标记，排序在该基础版本的普通发行之前；开发发行按预发行处理。去掉后缀会形成不同的包版本，需按新版本构建和交付。

实施范围：

1. 本批包含默认来源发现和隐私标记行为变更，基础版本选定 `0.14.0`，常规交付不使用 `.devN`；版本号不代替开发状态与兼容边界说明。
2. 在[pyproject.toml](../../../experiments/20261106-basepack/pyproject.toml)更新权威版本，同步锁文件根包版本、当前说明和发行材料。`basepack.__version__`继续读取安装元数据，保持单一维护源；构建新的wheel、文件名和校验清单。
3. 同步核对Git tag、Release标题与prerelease标记，使其反映当次发行用途。现有`v0.13.0.dev1`的tag、wheel、哈希、迁移边界及交付记录作为历史保留，新命名用于后续版本。
4. 安装升级按本批实际影响安排，现行入口如实记录已安装版本。单纯命名变化沿用数据库、知识版本和向量身份；其它新增内容另按其影响处理。

完成依据：源码声明、锁文件、wheel元数据、安装后版本及新发行命名一致；版本排序正确，受影响入口可用，历史发行和恢复资料仍可定位。发布沿项目既有授权约定执行。

## 2. 私有开发上下文与文件结构 skill

目标：为真正机密的开发背景建立明确的本机存放与公开引用边界，降低误入 GitHub 的风险。它服务于人和 agent 理解情境、目标与理由；公开需求、源码及交付流程保持自足。本节是本需求的方案维护源。2026-11-14 用户已选定 `private/` 与方案 C：在其中建立独立 Git 仓库；方案 B 仅在迁移期间临时使用，完成后撤除。已建立独立私有仓库，首批限定清点未确认需要搬入的机密原件，迁移映射为空；功能验收使用明确的合成资料。

### 已明确的需求与现状

- 项目根设置一个私有区域；仅真正机密的内容进入。按本次用户口径，姓名、邮箱可公开，与上级的私人聊天应私有；机密性按内容和公开意图判断，不把全部个人信息或开发材料自动归为私有。
- 公开文档可以引用私有来源，但正文仅保留可公开的需求、决定及必要理由。机密业务原件、人工维护的分析及摘录留在私有区；篇幅短也不自动意味着可公开。记忆系统生成的受管副本沿后文的同库存储约定，不要求所有机密字节都位于 `private/`。
- 引用仅供开发追溯和补充理解。缺少私有区时，公开说明仍能理解，安装、构建、测试、文档生成与产品运行不依赖其中的文件、数据或链接解析。
- 私有区可有自己的文档层次。公开 `devDoc/` 继续维护目标、现行实现、任务状态与交付结论；私有文档按相同任务键存放机密研究和依据，避免镜像维护另一份公开计划或进度。
- 现有 [Git 忽略规则](../../../.gitignore) 已覆盖 `/private/`、`.basepack/`、`tmp/`、`artifacts/` 等本机内容。这些目录按职责与寿命组织，不能据此断言内容可公开或已泄漏。本轮没有审计已发布全历史，也未迁移未确认的原件。

### 已定方案：独立私有仓库与临时迁移检查

- **名称固定为 `private/`，采用方案 C。** 在 `private/.git/` 建立完整的独立仓库，有自己的对象、索引、分支与提交历史；不建为公共仓库的 submodule、gitlink 或共享公共 Git 存储的 worktree。
- **公共仓库忽略整个 `/private/`。** 公共提交、源码归档与发行清单排除其内容及内层仓库；私有区自身按实际材料维护 `.gitignore`，忽略其一次性内容、缓存及不需版本管理的产物。两仓的提交范围分别检查，命令显式定位仓库，不将私有提交并入公共历史。
- **私有 Git 先用于本机版本管理。** 它不复用公共仓库的 remote，也不自动创建远端或上传。备份位置和恢复方式随首批材料确定；同盘的 `.git/` 历史不代替独立备份，私有 Git 自身忽略但仍需保留的原件、附件和证据也要覆盖。以后确需远端时再配置明确的私有目的地。
- **B 仅为迁移期临时检查。** 将一次性检查脚本放根 `tmp/<migration-task>/`，在该批公共暂存时核对、提交与发行前运行；发现公共 Git 最终索引或待发布清单包含 `private`、`private/` 路径时阻断本批后续动作，也识别误加入的 `160000` gitlink。以最终树判断，允许正常提交既有私有条目的移除。它检查路径和清单，不做正文语义分类；迁移期间脚本若被临时清理，按计划重建后再继续。
- **迁移验收即撤除 B。** 完成拟迁清单、公共引用、两仓边界、发行清单及最短工程流程检查后，保留必要结果并撤除临时脚本和调用步骤；不留下永久 hook、全局 Git 配置、CI 门禁或常驻检查器。长期保留独立私有仓库、忽略规则、内容约定和既有提交/发行差异检查。

目录与独立 Git 建立版本和发布边界，不提供加密或访问控制，也不自动限制已获授权的 agent/工具读取或发送内容。临时路径检查不能识别复制到公开正文中的秘密，公开提炼仍按内容判断。

### 内部组织与引用

按真实内容创建目录，不预建完整的第二套 devDoc：

```text
project/
  .git/                           公共仓库的独立历史
  .gitignore                      公共仓库忽略 /private/
  devDoc/                         可公开的开发说明与唯一公共任务状态
  private/                        整体从公共 Git 和发行清单排除
    .git/                         私有仓库的独立历史，不登记为 submodule
    .gitignore                    私有仓库自身的产物/临时内容规则
    README.md                     本机索引与恢复入口，有内容时建立
    sources/context-001/          机密原件及相邻附件，中性名称
    devDoc/tasks/<task-key>/       确有需要的机密分析，引用 sources 原件
    devDoc/archive/               需保留的已结束机密工作，按需建立
    tmp/                          机密的一次性衍生物，选留后可清理
    artifacts/                    机密的选留证据与输出
```

公开文件可用中性的项目相对路径和章节位置标注“私有来源，可选”，例如正文中的代码路径 `private/sources/context-001/notes.md#scope`；路径按引用文件位置换算。真实机密标题、人物关系和文件名也不在公开引用中暴露。公开链接检查只将这类明确标记的私有引用视为可选，普通失效链接仍处理。

从私有来源提炼出的可公开需求应在所属公共文档完整表达，详细背景继续引用原件。私有来源被移动或未恢复不影响公开工程与产品流程；本机记忆发现、维护和来源状态仍按既有缺失/变更合同处理，已发布快照沿原合同回读。不复制大段材料，也不通过公开摘要、截图、测试夹具、提交说明、Issue/PR 或发行说明重新暴露机密；人工维护的机密衍生物进入私有区，受管记忆副本及工作包按下文处理，非机密的一次性和选留内容继续沿根 `tmp/`、`artifacts/`。

### 同一项目记忆：默认纳入与轻量标记

2026-11-14 用户明确：`private/` 的资料默认进入同一项目记忆，无需逐项配置 `source_scope`；对私有来源及其衍生知识做标记，便于将来公开记忆时剔除，改动保持小。

- **默认发现追加私有资料。** 外层 Git 的默认清单之外，自动加入根 `private/` 独立仓库的已跟踪与未忽略新文件，尊重其自身忽略规则，排除 `.git/`、工具状态、环境和缓存。仍归外层项目的 UUID、数据库与维护生命周期，不把内层 Git 当作另一个记忆项目。根 `private/` 不存在时正常完成默认发现，已登记来源的缺失另按既有合同处理。`source_scope` 继续服务其它额外来源；显式 `--scope` 只按所选范围发现新文件，不再自动追加私有范围，也不限制既有来源和历史待处理范围。
- **只加一个逻辑标记 `private: true/false`。** 现有 [表定义](../../../experiments/20261106-basepack/src/basepack/memory/schema.surql) 为 `SCHEMALESS`，无需新建标签表、分级体系、ACL 或第二个数据库；但现有 apply 会重组字段，需在 [写入处](../../../experiments/20261106-basepack/src/basepack/memory/store.py) 显式保留和计算。新写来源与来源快照按规范化的项目相对路径判断是否位于根 `private/`，普通来源明确标为 false。
- **复用已有依据关系传播。** 成员由自身来源版本及 `basis` 固定的来源/知识版本判断，摘要/节点有私有依据即标 true，关系同时考虑依据和固定版本端点；不拿依据或端点的当前标记替代已引用版本，仅 stale/retired 等状态更新保留原标记。公私混合的一条知识整体标私有；公开文档中仅含一个可选私有路径引用，不等于读取或使用了该私有正文，不做字符串见到 `private/` 就扩大标记。检索、brief、回读与交接返回相关标记，供 agent 判断公开写入边界。
- **补标作为小范围元数据升级。** 新写知识的历史保留继续携带同一标记；首批迁移按已确认的原件映射和固定版本依据，同步补齐可确认的当前记录及已有历史副本，保留原件字节、历史路径、UUID、知识/输入版本和未变向量。只补标不制造语义改写或使既有依据过期，未覆盖及无法确认的旧记录记明范围，缺标不等于已核为公开；不将全库语义审计列为本批前置。未声明依据的暗含机密无法靠一个字段自动识别，不增加全文隐私分类器。
- **完整备份与公开分享分开。** 同一项目的现有记忆存储继续保留全部公私内容：持久记录、来源快照及图关系沿 `.basepack/`，阅读包/批次等沿既有受忽略的工作位置，这些受管副本按本机私有运行材料保管，本批不迁库或搬迁工作包。完整备份沿既有恢复流程，同时覆盖数据库及必要原件、图片 assets、受管聊天等文件；数据库原生导出本身不包含全部文件。将来需要公开时再生成独立分享副本，按标记和依据剔除私有内容；可先仅带当前公开知识及必要公开快照，省去操作历史，不修改原库。

本批范围限于默认发现、轻量标记的写入/传播/返回及上述范围的存量补标，不建设通用公开导出工具。新增字段不意味着现有原生导出自动净化：原文快照、图片 assets、旧知识版本、`change.previous`、聊天/反馈/交付 context 都可能保留私有内容；未来分享副本须筛选实际携带的内容和引用，不能只删当前 `member` 的私有条目就宣称可公开。

### 实施顺序与完成依据

1. **确定首批范围与恢复方式。** 按已选定的 `private/` 与 C，明确首批真正机密的材料及备份方式。按拟迁清单核源/目标、附件、未提交工作、引用和既有 Git/记忆登记；公开记录只保存中性位置及处置状态。
2. **先建两仓边界和临时 B，再迁内容。** 配置公共忽略及适用的发行排除，检查已跟踪文件；初始化独立的 `private/.git/` 与私有忽略规则，以临时路径检查约束本批公共提交/发行。随后移动原件及相应机密副本，分别提交两仓相关内容，公开正文提炼到自足并修复引用。保留可恢复原件和必要版本映射，清理 ignored 内容须保留私有仓库；不自动推送私有材料。
3. **接入同一记忆并补标。** 按上述小范围修改默认发现、写入和返回；沿确认的迁移来源与已有依据做必要补标。本机完整查询/备份继续包含公私资料，不实现公开导出工具，不删除生产知识。
4. **扩展通用 skill。** 在 [file-structure](../../../skills/file-structure/SKILL.md) 增加选择条件和 `references/private-context.md`，集中写触发条件、最小结构、内容/版本边界、引用、迁移与验收；说明独立私有 Git 与迁移期临时检查，普通使用不要求安装永久门禁。开发文档/实验路线参考按需组合它。将“单套 devDoc”说明为单套公共维护源，允许私有依据树；通用技能由各项目确定公开口径，不继承本项目姓名/邮箱示例的授权。
5. **同步项目规则。** 更新 [文档维护](../../documentation.md)、记忆来源/字段说明及必要的 agent 入口，沿现有 skill 发现联接使用源码维护源；当前实现说明仅在实际落地后更新。项目纲领正文仍按其维护约定由用户决定修改。
6. **验收并撤除临时 B。** 用非敏感探针核公共忽略匹配、两仓各自的 Git 根/存储/索引/remote 和实际发行清单，确认公共树中没有私有路径或 gitlink；在临时夹具中证实检查能挡住误暂存与误打包，避免污染真实公共历史。用小样例核无需配置即可发现私有资料、尊重内层忽略、无 `private/` 及显式 `--scope` 的发现分支、同库检索/brief 带标记、公私混合与固定版本依据判定，以及补标保留知识身份、历史副本和未变向量。选一组实际迁移的原件/附件/公开结论核引用与内容边界，缺少私有区时按受影响的既有最短工程流程核公开文件可独立使用。满足本批迁移完成条件后撤除临时脚本及其调用，确认无遗留 hook 或全局配置；不增加完整新机模拟、技能收益对照或逐条隐私分类系统。

如拟迁材料曾提交或发布，单列历史暴露问题、受影响位置及处置选项；移动或取消追踪不能抹除历史，重写远端历史另按明确范围授权。当前不对任何仓库作“没有泄漏”的结论。Git 行为与历史处理依据见 [gitignore 官方说明](https://git-scm.com/docs/gitignore)、[GitHub 敏感数据移除说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。整目录压缩、显式导出、云同步及另行上传仍需按各自实际分享边界处理，忽略规则不覆盖这些通道。

完成以两仓独立且公共树无私有路径/gitlink、原件及机密衍生物留在约定边界、公开结论自足、引用可选、相关索引/发行清单与最短流程通过、私有资料默认入同库且标记/传播/历史保留可用、备份可定位、既有历史/记忆处置明确及临时 B 已撤除为准。公开记忆分享工具不在本批完成条件内。尚未检查的范围如实保留，工具成功或目录出现不能代替完成。
