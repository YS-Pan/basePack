# P0：SurrealDB 原生接入与数据合同

2026 年 11 月 9 日在本机 Windows 实测通过。首期采用 **SurrealDB 4.0.0**，继续 P1；本结果不代表真实智能分块、建图或 embedding 效果已验收。

## 接入决定

- 使用正式 Windows amd64 发行文件，实跑版本与发布 SHA256 一致。原始 exe 直接使用 `start/sql/mcp/export/import`；官网 `surreal db ...` 是新 launcher 的命令层级，不能直接套到原始 exe。
- 每个项目使用自己的 SurrealKV 目录，本项目的多聊天连接同一个本地 server。CLI、HTTP `/sql` 与原生 `/mcp` 交叉读写中文成功；两个独立 MCP 会话读取一致。实机 MCP 协商为 `2025-03-26`，不依赖猜测的协议版本。
- 一个 member 同时承载文件/章节/原文块身份、检索表示与图节点；摘要、智能边界、依据与更正持久保存。来源版本、表示输入版本和 embedding_identity 分开，外部向量只作为派生索引。实体/决定节点在 P1 按实际需要增加。
- 图边使用原生有属性 relation，依稳定 ID 独立新增与修改。来源快照和 change 记录显式保存历史；逻辑导出不代替原件及派生图片备份。
- 中文采用原生 `segment(chinese)` 全文分析器，另提供显式原文包含查询。词典分词不保证子串召回；`A-17` 的全文命中可能只是分散词项共现，编号仍须精确核原文。

## 实际行为

| 检查 | 结果与条件 |
| --- | --- |
| 多层与图文存取 | 固定 file/section/chunk/image 身份、范围、摘要及 2048 维向量往返；各层可命中并回查依据。异 identity 的同值向量排除，维度错误原生拒绝。均为预置接口夹具。 |
| 关系与局部更新 | 独立增边保留其它边；修改块使依赖的两级章节/文件摘要及相关边失效，未变兄弟与独立边保留；固定新摘要/依据写入后可查，旧输入向量先退出检索。 |
| 中文 | 水质、值班员、十五分钟、医疗及中英编号有真阳性；保留单字/词典边界和编号假阳性的反例，未宣称任意中文查询完整召回。 |
| 并发 | 20 个独立写入成功；同记录的竞争事务一项成功、一项返回原生 TransactionConflict，失败事务内标记整体回滚。 |
| 隔离与恢复 | A/B 为不同项目物理目录；原生导出到 B 的新库后五类记录逐条一致，全文/向量查询一致，另复制的原文及原图 hash 一致。 |
| 进程重启 | C 导入后经 Windows 强制终止并同路径重启，61 条记录快照 hash 一致；不称优雅停止。空库启动到 ready 约 793 ms，崩溃后重启约 232 ms。 |
| 小样本代价 | C 首查约 40.7 ms，六次热查询墙时中位 13.5 ms；查询后工作集约 155 MiB，数据库四文件约 339 KiB。只代表这份小样例与当时状态。 |

数据库所在 D 盘映射到 SATA ST4000VX016 4 TB 机械盘。本轮未清 OS 缓存，进程重启不等于冷介质测试；代表性规模、完整语义效果及全周期成本继续 P4。

## 依据与后续

选留原证在根 `artifacts/runs/20261109-memsys-p0/`：`runtime-evidence.json`、`protocol-evidence.json`、`result.json`、`supplement-result.json`、`concurrency-results.json`、`cold-start-evidence.json`，以及执行脚本、schema、固定夹具与最终逻辑导出。数据库、发行二进制及临时服务不进入 Git。
