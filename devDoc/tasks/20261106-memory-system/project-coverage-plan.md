当前缺口首先是资料覆盖：系统总览、架构、记忆模块、实际进度、产品使用文档、源码、测试及通用 skills 大多未进入项目记忆。节点数、向量数及 pending=0 均不能说明这些内容已经可用。已有评测未证明质量或全周期费用净收益，扩库后按实际任务重新判断。

`24dec2e` 截点的 `git ls-files` 共 196 件：现行维护树 91 件（40 份 Markdown、43 份 Python/SurrealQL、8 份配置/依赖声明/锁），历史正文 99 份，另有 6 件仓库元数据、占位与许可声明。这里的“现行维护树”仍含旧结果和历史段落，事实时效须按内容判断。执行时重算分母并纳入本计划等新增材料；许可和 Git 边界按发布/恢复需要保留入口，锁文件按精确依赖定位处理，不把 196 件等量转成语义来源。

## 覆盖如何计算

执行起点冻结一份项目文件清单，记录 Git 截点及必要的工作树变化；按上述范围分类，每份材料有纳入、历史或排除理由。执行中新增、删除和修改另列差量，收尾重新核对实际文件。清单从文件工具与现有数据库导出生成，正文只维护阶段结果和未处理范围，不另建一套持久状态系统。

分别报告下列状态，分母为对应批次中有实质内容的纳入材料；历史与现行分开统计：

1. **发现覆盖：** 纳入清单与配置范围一致；目录内新增可发现，显式文件范围的新增有登记责任和核查入口。
2. **阅读与表示覆盖：** 已实际阅读的范围，有依据的文件摘要、必要章节/原文块，以及尚未覆盖的范围。文件登记不能代替全文阅读。
3. **语义覆盖：** 已共读的跨材料主题、接受的关系与条件、未核候选或负结果。语义边数量不作为目标。
4. **索引与新鲜度：** 当前表示是否可文字检索、向量是否兼容及就绪、哪些内容 stale/pending；原有更正和历史保持可查。
5. **任务覆盖：** 实际任务是否取得并使用必要信息、是否回到原文、是否漏条件或引用旧事实。

最终要求现行范围内的实质正文全部读过并形成当前表示；有意排除和历史细节的未展开范围明确可查。历史资料至少保留可回源的主题/结论表示，涉及当前取舍的关键历史具备细粒度证据。不能把文件级概览算作全部细节已索引。

现有 `sources` 只返回来源元数据，brief 的缺口清单也不提供全库已读区间。首次执行以文件清单、批次实际阅读记录及原生只读 member/关系查询生成覆盖报告；按来源版本合并原文区间，单列摘要范围与实际证据范围，不把摘要首末行或“未声明缺口”推算成全文已读。报告是阶段导出，不引入第二份知识状态。

## 执行批次与完成条件

### C0 冻结范围、备份和基线

读取当前 `sources`、brief、配置与文件清单，补齐按范围的真实分母。使用原生 export 保留扩库前知识，带齐对应配置、原件和必要 assets；恢复仍使用另一物理目录/端口，正式项目库保持服务。

在入库前冻结约 10–12 个真实开发任务及独立预期要点，答案留在不参与发现的评估材料中。先测现有 6 源记忆与直接文件工具，核实际初始上下文；后续扩充组使用同一任务条件。选择约 8–12 份不同类型的材料作为首批，实测阅读、apply、编码及验证耗时，再估算后续批次投入。

**完成：** 有纳入/排除清单、可定位的备份集合、未泄露答案的任务基线和首批任务包；范围外资料与本轮不会处理的内容明确。此时不声明覆盖已扩充。

### C1 建立完整的现行项目地图

共读根入口、system、术语、文档约定、活动计划/进度及路线用户文档。先补环境、管理员说明的缺口，并纳入当前进度，避免仅凭计划推断实现。首次样本通过后按主题继续，完成这一层全部纳入正文。

同读生成文件/实际章节摘要、智能原文块、决定/条件节点及语义边。启动地图覆盖四项工具、当前路线、部署、主要未完成项和使用限制；保留现有 3 条 mandatory，新增强制保留内容须有明确指令依据，其余进入按需线索。

**完成：** 当前入口与文档层无未解释的阅读缺口；新任务能找到实现、操作及接续位置，能区分计划、已交付结果和未测条件；brief 实收线索可回源，未通过扩大常驻正文交付整套文档。

### C2 连接实现、配置、测试和 skills

按 project、memory、embedding、jobs 四个实现模块组织共读，配对对应文档、配置/模板、示例、关键回归和随包 skill。再共读两项通用 skills 及其参考。源码按职责、函数/类及连贯原文范围分块，短文件使用实际层次；不为代码虚造 Markdown 章节。

重点建立“公开操作受什么条件约束”“实现为何如此”“哪个回归保护何种失败”“源码与安装版本如何对应”等关系。关系依据必须包含实际核过的两端材料。测试文件只支持其断言范围，测试通过事实仍从对应运行结果取证。

**完成：** 各模块有实质内容的源码、schema、测试及手工配置全部读过并可回源；修改/诊断任务能定位实现和相关回归，并带出跨模块前提。以 UTF-8 原文接受 `.py`、`.toml`、`.surql` 等既有类型，只有实测阻断时才修最小缺口并保留回归。

### C3 补全历史脉络和跨主题关系

逐份处理余下调研、归档、变更和历史结果。短记录保留完整原文块；长材料先完整阅读，再保留结论、条件、关键证据和必要层级。重复叙述复用同一事实节点及各自依据，明确内容被何时、何版本的决定取代。

优先追溯 SurrealDB/多层表示的选择、R9 资源复用、ID/并发/失效修复、正式安装与源码边界、项目布局和评测收益边界。沿引用选择本项目必要运行证据，二进制/大日志保留定位与必要片段；图像按原图输入，不以文字描述替代。

协调者汇合跨批候选并共读两端，发现历史与当前的支持、约束、矛盾和修正。另从未配对的主题中随机共读少量材料，记录发现或诚实的负结果；首轮可用约十分之一共读投入，比例按实际产出调整，不做全关系两两枚举。

**完成：** 历史纳入资料均有实际阅读和可检索的主题/结论入口；关键决定能追到理由与适用条件；历史验收不会作为当前运行状态返回，仍未展开的细节和未可用原证有明确入口。

### C4 验证使用效果、增量和恢复

按冻结任务检验扩充后的记忆，与 C0 的现有记忆及直接文件工具对照。使用无答案历史的工作 agent，保持模型、任务条件及最终内容预算一致；自动必保内容正常交付。逐题记录实收并使用的前提、原文支持、漏项、过期结论，以及主 agent 往返、团队总耗时、内容量和可得用量。建库与维护投入单独报告；token/费用取不到时留缺。

在隔离副本完成一次代表性的新增、修改、移动/删除、关系更正和原生恢复：新增资料验证目录发现或显式登记流程；修改验证原文块、祖先摘要、依赖边及受影响向量更新，未变部分复用；恢复后 read/search/neighbors 可用。正式库只接受正常维护。复用已有回归，不重跑无关的 P0–P5 或资源设施矩阵。

**完成：** 纳入范围和余项对得上；current mandatory 完整，已完成范围无待核/待编码项；关键任务取得必要证据且不误用过期结论，未知前提题观察到信息实际被采用；增量与恢复可复现。未通过的任务定位缺口并修复对应批次，再复测受影响题，不以继续增加资料代替修复。无收益的题如实保留，扩库完成与收益判断分别结论。

## 团队、批处理和日常维护

主 agent 负责范围、关键取舍、最终检查和 Git 提交。广读阶段由 tier2 协调者持续负责分批、派工、跨批汇合、冲突和收尾，每位最多管理 4 位 tier1 reader；可从 1 位协调者和 2 位 reader 起步，按实测展开。派工前解析项目 AI 配置，不在计划中固定模型名。负责同一文件和最终摘要的 owner 唯一；独立审核默认省略，争议关系才批量复核。

reader 在一次阅读中完成分块、摘要和关系候选，不分成全库扫描、全库总结、全库建边三遍。每个数据库批次由一个写入 owner 统一 `prepare → 共读 → apply → embed → search/read/neighbors`；相关依据和关系端点一起核版本。不同 reader 并行阅读，重叠写入顺序整合；并发草稿冲突后重新 prepare 并阅读受影响范围。失败停止依赖步骤，保留原错与待处理范围。

`source_scope` 首先使用明确文件或经过核对的干净子目录。现有目录扫描仅跳过 `.git` 和 `.basepack`，不按 Git 忽略规则或后缀过滤；源码/测试目录实际已有 `__pycache__`，因此不直接递归项目根、整个实验目录或带缓存的源码目录。文档/skills 使用核对后的目录范围；源码/测试先用 Git 原生清单（含未跟踪且未忽略的新文件）生成显式 scope。新增源码的 owner 在提交前更新纳入清单与 scope，再运行变化检查；普通 brief 不会自动发现显式清单外的代码。若这一步在实际使用中持续漏项，再补最小目录排除能力。

批量编码复用已安装共享服务和兼容 identity，按真实输入限制分批；超限返回该 reader 调整语义边界，保留条件和覆盖。服务失败或超时如实交接，不重投、不截断，也不启动第二套模型；若后续编码批失败，已成功批次保持，按实际 pending 接续。首批测得的速度用于估算余量，不预先承诺总耗时或费用。

日常接续仍由 brief 快检和任务内小批维护驱动。每个完成批次更新现有进度中的已覆盖范围、验证与余项；阶段收尾刷新发现清单。深维护在阶段收尾、实际漏项或明确手动请求时执行，历史重访沿同一流程继续。

稳定结论留在本任务进度及后续结果；本地阅读包、批次、评分和数据库材料留在 `.basepack/memory/`，一次性盘点/评估留根 `tmp/`，需要长期复核的原证选留根 `artifacts/runs/`。不新增外部服务、后台语义 agent 或另一套项目知识台账。

以下用于选题，独立答案在 C0 冻结，执行时使用具体场景及必要要点判分。

| 整理文件或交接广读任务 | 带出材料寿命、唯一维护源、团队职责及共读两端的要求 |
| 准备发布或从备份恢复 | 区分计划与已执行、Git 内容与恢复集合、源码/安装验收及项目局部边界 |

以上主题覆盖已知定位、跨源取证、低字面相似关系和未点名前提；C4 另含失败/历史过滤及维护场景。首轮规模随实际范围调整，关键前提漏交付或旧事实冒充当前时，该题不通过。
