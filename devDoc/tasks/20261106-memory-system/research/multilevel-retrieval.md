# 多层次表示与检索调研

2026 年 11 月 9 日，按用户明确选择多层次表示后重新联网复核。仅使用原始论文、官方文档和源码；未安装、建库、调用模型或测试记忆功能。用户目标见 [纲领](../../../project-charter.md#记忆系统)，当前采用方案只在 [计划](../plan.md#多层次表示与跨层检索) 维护。

## 结论与证据边界

研究支持把宏观概括与原文细节同时保留为可检索表示，尤其有利于跨段与全局问题；不证明层数越多、每层重复建完整语义图或任何检索路由都更好。多层次已是本项目目标，样例评估用于收敛实现和代价；中文项目资料、现有共享 embedding、宿主订阅 agent 与机械盘的实际收益仍待验。

| 原始来源 | 已有证据 | 对本项目的限制 |
| --- | --- | --- |
| [DHR，Findings EMNLP 2021](https://aclanthology.org/2021.findings-emnlp.19/)、[作者论文](https://arxiv.org/pdf/2110.15439) | 文档用标题/摘要/目录表示，段落补祖先标题；两级训练检索器先找文档再找段落，在 Wikipedia 开放域问答上改善其基线 | 使用专门训练的文档/段落 BERT 编码器；索引搜索加速不等于端到端、更新或 HDD 更快，不能直接套用本项目模型 |
| [RAPTOR，ICLR 2024](https://arxiv.org/html/2401.18059v1) | 原文叶块经过语义聚类和递归摘要形成高层表示，在三类长文 QA 上改善对应检索基线；20 篇 QASPER 的策略比较中全层候选优于固定逐层遍历 | 摘要聚类树不是原文位置树。该检索比较很小，不能推广为混检普遍优于父层预筛；摘要生成与多层索引增加建设成本 |
| [GraphRAG](https://arxiv.org/html/2404.16130v2) | 实体关系图上形成社区与多级摘要，在两个约百万 token 语料的全局问题上改善全面性/多样性 | 主要由 LLM 评审全局答案；向量基线更直接，对照全文 map-reduce 的额外收益较小，不证明普通细节任务都受益 |
| [HiRAG](https://arxiv.org/html/2503.10150v3) | 低层实体、聚类后的摘要实体、跨层连接与桥接检索；层级消融支持多层贡献 | 采用另一组模型/API与高层问答集，索引开销增加；没有要求在每层重建完整横向语义边，不能作为本项目成本保证 |

DHR 与 RAPTOR 的路由结果来自不同表示和检索器，不互相否定。本计划保留各层直接召回并在 worker 内按需展开；父层预筛是可比较策略，不能让一个高层漏召回永久挡住原文证据。

另核 [Anthropic Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)：其针对片段补充背景的实验有收益，而通用文档摘要直接附到每个片段的收益很有限。因此文件/章节摘要单独作为检索表示，段落只补必要定位背景，不能把重复粘贴整份摘要当作有效多层实现。该结果也不证明本项目已取得收益。

## 成熟实现可复用什么

| 官方入口 | 可借鉴机制 | 不能直接当作已满足的合同 |
| --- | --- | --- |
| [LlamaIndex AutoMergingRetriever](https://developers.llamaindex.ai/python/framework/integrations/retrievers/auto_merging_retriever/) | 保存父子层，只对叶块建向量，命中后合并/读取父块 | 是“检索小块、读取大块”，不满足本次文件/章节/块各自进入向量候选的完整目标 |
| [RecursiveRetriever 与节点引用](https://developers.llamaindex.ai/python/framework/integrations/retrievers/recursive_retriever_nodes/) | 不同粒度或不同表示可索引，再沿引用取得原文 | 不自动提供跨层排名融合、父子内容去重、来源新鲜度或语义边维护 |
| [DocumentSummaryIndex](https://developers.llamaindex.ai/python/framework-api-reference/indices/summary/) | 摘要节点与原文引用、摘要 embedding | 默认摘要调用 LLM synthesizer；本项目摘要仍由宿主订阅 agent 提供，不因此引入额外 LLM API 或整套编排依赖 |

这些是机制参考。首期现已收敛为 [SurrealDB 接入验证](backend-review.md)，三者比较保留历史参考；没有把 LlamaIndex 增列为长期底座，也没有验证这些库在本机的行为。

按用户追加要求核查 [旧项目代码与原证](legacy-multilevel.md)：旧 Context 的原文分段/语义事实共索引与证据回源、退役路线的导航摘要或事实图回源都可借鉴，但在已查范围未发现本次完整三层方案；与仅在历史计划中提出的多表示实验分别记录。

## 设计决定如何落地

[计划](../plan.md#多层次表示与跨层检索) 已将文件/实际章节/原文块设为默认可寻址成员：粗层用有依据摘要，细层保留原文；依据用户新增纲领，agent 在同次阅读中决定智能块边界、摘要及节点/边。结构解析只供定位，结构包含、摘要依据和语义边分别维护，不复制论文中的社区聚类平台。摘要可导航，事实性结论和语义判断仍需对应原文；这项同读约定是用户要求，不冒充文献实验结论。

来源版本、表示输入版本、模型语义身份分开；已接受摘要/层级/依据为持久知识，向量为可重建索引。局部修改时重核依赖它的祖先摘要与语义边、复用未变表示；标题/父级背景进入输入时也计入变化。论文和上述工具没有验证本项目这一增量/恢复合同，P0–P3 必须用实际变更样例证明。

## 验证落点

- **P0：** 固定三层样例、边界、摘要和预计算向量，核 SurrealDB 映射、回源、局部失效及恢复；不是 agent 智能分块/建图验收。
- **P1/P2：** P1 真实 agent 同读智能分块、摘要和初步关系，跑多层文字闭环；P2 扩展图行为及各层/原图向量，层级树不替代语义关系。
- **P3/P4：** 修改/删除/改名/拆合，核有效性、复用与更新放大；固定上下文预算比较原文块、父级扩展和多层混检，分别记录质量、主动性、墙时/可得用量、摘要与维护成本、冷/热 I/O。

未测项目保留未验身份。消融用来定位多层实现的得失，不以某组问答分数撤销用户目标；若实际证据暴露目标间的冲突，带具体材料和代价交用户判断。
