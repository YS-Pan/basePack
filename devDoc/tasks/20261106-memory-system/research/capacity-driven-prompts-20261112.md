# 按配置并发上限生成维护组织与 prompt 的评估

2026-11-12（北京时间）。仅评估，方案待选，未修改实际配置、程序、prompt 或安装。接续[已选 T2 + N2 计划](../task-duration-and-worker-naming-plan.md)。

## 结论与现有基础

可以扩展现有机制。安装／项目接入 agent 取得宿主有效并发上限并写入 basePack 配置；运行时由程序计算队伍、人数、固定名称、权限和命令，再渲染具体 prompt。AI 仍负责 T2 的任务时长判断、原文理解和语义分批，组织规模的算术不再逐对话交给 AI 设计。

当前 [prompts.py](../../../../experiments/20261106-basepack/src/basepack/memory/prompts.py) 中，`prompt_dispatch()` 已解析 coordinator/reader 的模型、推理强度和渲染命令；`render_prompt()` 纯读配置、回执和英文模板，注入本批路径、依据提示及 apply 命令。当前没有宿主容量、队号和组织规划。[ProjectConfig](../../../../experiments/20261106-basepack/src/basepack/project/config.py) 已是公共配置唯一解析入口；[init_project()](../../../../experiments/20261106-basepack/src/basepack/project/init.py) 生成配置与入口，尚不接收宿主并发数。

## 三种落地方案

| 方案 | 安装／接入时 | 每次维护时 | 代价与限制 |
| --- | --- | --- | --- |
| S1：预生成固定组织 | 读取上限，按程序规则生成自动／手动组织布局并保存 | 只填回执、control、材料等本轮内容，再渲染 prompt | 初版直观；容量或其它占用变化后布局可能过时，需要刷新或减少实际派工；配置同时保存上限和派生布局，维护负担较多 |
| S2：保存上限，纯函数计算组织（推荐） | 读取并归一化上限，写一个容量值及必要来源说明 | 程序读取配置、模式及可取得的本轮额度，确定性生成布局和 prompt | 直接复用现有入口，支持 3 至 30 的任意整数，不保存重复的派生布局；安装快照改变后需显式刷新 |
| S3：保存宿主引用，运行时解析有效上限 | 记录宿主与配置引用，验证解析能力 | 宿主适配器解析当时有效配置，再调用同一规划函数 | 能跟随系统配置变化；需处理 profile、项目／会话覆盖、旧字段别名及默认值，不能只读一个 TOML 就声称得到有效配置；当前没有已核通用接口 |

推荐先选 S2。整数计算和模板渲染成本很小，无需为它增加缓存。S1 如果再加入运行时按容量裁剪，实际已接近 S2；S3 可在确有多个宿主或频繁改配置的需求后按宿主补充，不同时建设三套入口。

## S2 的具体合同

### 安装采集与配置

安装指准备客户端，接入指为某个项目生成配置；容量与实际使用该项目的宿主绑定，不假设一个 Python 安装只有一种宿主配置。由安装／接入 agent 读取有效配置或宿主明确报告的实际值，统一换算为“不含业务主 agent、包含全部后代”的 subagent 上限 C。若宿主未显式配置且无法取得实际值，在接入时一次性取得明确值，不猜 3、13 等默认数。

最小落点是现有项目配置 `.basepack/config.toml` 的 `[ai]`，例如以下拟议字段（不是当前已实现字段）：

```toml
[ai]
max_concurrent_subagents = 12
```

`ProjectConfig` 提供唯一解析，`config show` 可展示容量及简短采集依据。现有模型档位共用 `[ai]`，不把容量复制到各队模板。先不增加宿主 profile 目录；若未来多个项目确需共用同一宿主容量，可改为机器配置中的一个值、项目仅引用，不两处重复维护。

C 是安装／接入快照，宿主仍是实际准入权威。系统并发配置、所选 profile 或宿主发生变化后，在升级／接入刷新时重新采集；不宣称 S2 自动跟踪变化。同项目切换宿主时应刷新或显式选择相匹配的配置，不能沿用另一宿主的旧上限。

### 上限与本轮可用预算

安装上限 C 不等于本轮空闲席位。宿主若已提供可用额度或其它占用数字，机械传入即可，由程序计算维护预算 M；AI 无需据此重新选择组织。

一种明确口径为 `M = max(0, min(C, A) - R)`：A 是宿主报告的、已扣除其它占用但尚未扣本次维护预留的可用 subagent 数，R 是额外业务预留；均排除主 agent。不能把已包含业务预留的额度再扣一次。建议首版自动维护固定 R=1、手动维护固定 R=0，作为规划函数的模式规则集中定义，不逐任务临时猜；这两个默认值与 S2 一起待选择。

没有实时接口时，程序只能给出配置允许的组织上限；静态业务预留也不能保证所有业务并发都已被扣除。首版不要求为算组织额外增加一轮 AI 调查：已有可用数字就传入，否则明确结果仅为上限，创建仍受宿主准入约束。名额不足时停止新增派工、保留原错；取得可核额度后重新生成较小布局，不盲重试，也不新建全局调度器。

### 确定性组队规则

保留既定低并发、命名和权限合同，建议采用以下简单规则，覆盖所有整数预算：

1. M 为 0 时不派 worker；M 为 1 至 3 时只派 `bp_mem_coord_0`，由它兼做 reader。
2. 自动维护始终只用第 0 队；M 至少为 4 时，reader 数为 `min(4, M - 1)`。
3. 手动维护中，每个完整队占 5 席（1 coord + 4 reader）。对 M 除以 5 取整和余数：余 1 席留空，余 2 至 4 席再建一支不满队；低并发规则先执行。队号按 0、1、2 顺序生成，仍受已选 0 至 9 的命名范围约束；不为用满更大上限改变名称格式。
4. 固定命名仍为 `bp_mem_coord_t`、`bp_mem_read_tr`，仅第 0 队发布。空闲槽位不要求用满；没有可分配材料时不用创建相应 worker，这不需要重新设计组织。

下表以已扣占用和业务预留的维护预算 M 为输入，c/r 分别为 coord/reader 数，不把 M 混作系统配置 C：

| M | 自动维护 c/r | 手动维护 c/r | 手动未用席位 |
| ---: | ---: | ---: | ---: |
| 3 | 1 / 0 | 1 / 0 | 2 |
| 4 | 1 / 3 | 1 / 3 | 0 |
| 5 | 1 / 4 | 1 / 4 | 0 |
| 6 | 1 / 4 | 1 / 4 | 1 |
| 10 | 1 / 4 | 2 / 8 | 0 |
| 13 | 1 / 4 | 3 / 10 | 0 |
| 20 | 1 / 4 | 4 / 16 | 0 |
| 30 | 1 / 4 | 6 / 24 | 0 |

预算增加一席不一定值得增加一个 coord。例如 M 从 5 到 6 时保留一队，reader 仍为四名；避免为用满席位增加没有阅读收益的协调层。这套规则在 3 至 30 范围最多六队，与现有两位 reader 编号一致。它是可测试的初始策略，不宣称已经证明为性能最优。

### 接入现有 prompt 路径

`安装采集 C → ProjectConfig 解析 → 本轮模式／原始额度 → 纯函数生成 layout → prompt_dispatch / render_prompt → 宿主按结果派工`。

- 纯函数输出本轮预算、队号、父子关系、固定 task_name、reader 配额及发布权限，现有模型解析继续输出 model 与 reasoning_effort。
- `maintain` 在既有结果／回执中交付本轮布局，随后渲染命令沿用同一模式、预算和队号。子队不重新拿总上限为自己扩队，配置中途变化也不改写已开始的一轮。
- AGENTS 只要求按结果创建；AI 不再决定多少队、叫什么或各队分多少额度。材料分配与语义理解仍由协调者负责。
- `prompt_dispatch()` 保持无数据库访问的元数据生成，`render_prompt()` 保持纯读渲染；布局计算不调用 LLM，不另设计时器、持久队列或独立调度服务。

## 检索 worker 的同源派工扩展

用户后续要求检索 worker 也采用固定名称，已纳入[主计划](../task-duration-and-worker-naming-plan.md#三检索-worker-的固定命名与脚本派工)。当前检索只配置模型档位，没有固定名称或专用 prompt 渲染入口；拟增加独立检索派工输出，默认名称 `bp_mem_search_0`，并发独立任务按脚本分配 `_1`、`_2` 等槽位。

检索与维护共用名称生成及 ProjectConfig 的容量／模型来源，但检索输入是问题、范围和内容预算，不需要维护 receipt/control/owner，也不启动维护协调者。默认一名检索 worker 执行整轮 search/read/neighbors/评分/rank；它属于业务占用，维护规划不能把其席位再次使用。无可用席位时主 agent 直接完成检索，明确未派出 worker。具体合同和验收以主计划为单一维护源。

## 选择后的实施与验证

先选 S1／S2／S3 及业务预留默认值，再确定配置字段与命令参数。若选 S2，实施范围为现有 project 配置解析／安装接入、纯组织函数、派工元数据和英文角色模板；不是新建一套 agent 执行平台。

验证既有 prompt 的无副作用合同，以及容量 0、1 至 6、10、13、20、30、其它占用、快照刷新和未知容量；检查生成名称、总席位和唯一发布者。再用低并发单 coord 与一次高并发手动多队验证宿主实际派工和收尾。本文只核了当前源码并离线核算示例表，没有执行这些产品改造或验收。
