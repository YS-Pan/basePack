# 记忆系统实施计划

2026 年 11 月 8 日更新。本文是记忆工具唯一实施计划；本次将 [复用优先](../20261106-rebuild/plan.md#复用优先) 落实到 P0–P5，当前仍无记忆实现，状态见 [进度](progress.md)。目标以 [项目纲领](../../project-charter.md#记忆系统) 为准，接口名和数字预算仍是可调整的工程建议。

## 目标与范围

记忆工具帮助 agent 找到已知缺口，也在未主动检索时给出相关线索，使其发现尚未意识到的前提。初建、检索和维护都要低成本，项目资料与数据库局部独立，控制小文件读写并能在机械盘使用。

首个可用版本先包含短项目说明、文字检索、原文定位、一个廉价检索 worker 和最小增量维护；随后补齐本地向量、图片和实际语义图。这些后续能力仍属于完整交付范围。常驻信息中必须保留的指令与前提直接交付，按需信息参与筛选和评分。

本任务复用公共包和资源接口，实际安装与验收状态从 [资源进度](../20261107-resource-coordination/progress.md) 读取；记忆 P0–P5 的状态仅在本任务进度维护。P0/P1 使用已交付入口独立推进，资源 R9 的简化研究和实现不成为前置。各工具可独立使用和发布。[file-structure](../../../skills/file-structure/SKILL.md) 与 [agent-team](../../../skills/agent-team/SKILL.md) 沿用各自维护源；本任务使用它们，不承担独立的团队组织研发和广读对照验收。

旧项目仅提供明确需求、事故样例和经确认的小接口，不自动迁入数据库、业务授权、任务台账或验收结论。核实历史时按主题查 [调研依据](../20261106-rebuild/research/sources.md)、[近期历史](../20261106-rebuild/legacy-history.md) 与 [聊天调查](../20261106-rebuild/research/thread-survey.md)，不复制报告或要求接手者重读全部聊天。

共享资源不保存项目知识。来源、片段、节点、边与变化记录优先放 `.basepack/memory/` 内少量数据库/索引文件；底座采用 Markdown 等格式时，实测文件量和批量 I/O 后决定。项目操作入口为 `.basepack/instructions.md`，短地图、检索委托、派生图片、缓存和日志也收在 `.basepack/` 内；根 AGENTS 只留短指针。业务原件和显式导出保持业务归属。产品代码与 skill 各有一个维护源，实例问题回改维护源；开发验收材料仍放被忽略的 `artifacts/`。

资源阶段核共享环境、服务与预算，分别放行 embedding 和 Condor 两条链；记忆只补核变化部分。embedding 不以 Condor 认证成功为运行前提，小样例可先验证模型调用，正式并行遵守资源预算。完整资源生命周期和普通重任务验收由资源任务负责，不搬入本计划。

## 调用与最小数据合同

现成离线软件负责查询、持久化、事务、排序和可复用的变化检测，basePack 仅补必要胶水。理解、建图、图片识读、筛选和评分由宿主实际派发的 Codex 订阅 agent 完成，不调用其它联网模型 API；软件和模型可另行安装。准备任务包不能算作执行。

对外保留四种动作；优先用底座原生 CLI/MCP 加短 skill 组合完成，必要时再补命令封装：

| 动作 | 输入 | 紧凑输出 |
| --- | --- | --- |
| `brief` | 项目根、可选任务说明 | 核心目的、少量当前线索、变化或缺口、原文入口 |
| `search` | 问题、来源范围、结果预算 | 文字/向量/图候选、正文摘录、来源定位与可读图路径 |
| `read` | 来源 ID、版本、范围 | 指定原文/图片与定位；不存在或已变化时给具体结果 |
| `maintain` | 变更范围、候选批次、自动/手动模式 | 应用结果、错误或未完成位置，供宿主继续 |

一次检索委托：工作 agent 发目标与预算 → 一个廉价 worker 检索、按需扩展并读原文 → 对实际读到的候选打分 → 脚本排序截取 → 返回直接相关内容、来源和缺口。默认同一 worker 完成检索和评分；工作 agent 仍可自行深入。候选多时分批，在共享候选范围或有共同锚点的批次内评分，避免直接混用各批主观分数。建议普通返回不超过 6,000 个中文/英文字符，由调用者调整。

最小字段：来源有稳定 ID、路径/聊天定位、内容版本和类型；片段有来源及原文范围；节点有稳定 ID、简短内容和支持来源；边有独立 ID、两端、关系含义、必要条件和依据。修改记录时间、操作及宿主可取得的执行聊天/turn/根聊天信息；宿主不给的字段留空。字段复用底座原生结构，当前状态只存一处，修改使用其事务能力。

节点、边、人工更正、来源版本和修改依据属于持久知识；全文/向量索引等派生内容可重建。P0 确定备份集合、清理范围和路径迁移方式，优先使用底座现成备份/恢复工具；P1 用小样例核恢复后依据与更正仍可回查。Git 忽略和 `.basepack/migration/` 迁移备份不能代替知识库备份。

自动与手动维护共用流程：找变化 → 准备相关新旧材料 → agent 共同阅读，产出节点/边及必要分段 → 可选批量审核 → 一次提交 → 更新受影响索引。自动模式处理当前任务的小批变化，手动模式允许深读、重访旧图和随机共读。默认省略独立审核层，争议关系或专项评估可显式审核；检索中发现的问题能修正。大批建图按纲领使用协调者与廉价阅读者，每个协调者最多管理四个廉价 worker，团队规模随实际需要调整。

## devDoc 自用与读取轮数

本项目 `devDoc/` 是自用场景：验证主 agent 逐层读索引、找文件和补读造成的往返。它使用同一记忆流程，从 P1 文字闭环开始，不等待完整资源平台或三层组织。

- **P1：** 已知少量相关文件或章节由主 agent 同批读取；寻找和交叉取证时，一次说明目标、范围和预算，由 worker 完成内部检索、阅读、筛选与评分，返回可直接使用的内容、依据和缺口。宿主指令与必须保留的前提直接保留，链接供追溯和深入。
- **P3：** 文档或进度改变后，启动线索与检索结果及时反映变化。保留短入口与直接读原文能力，支持首次接入、错误定位和人工核对。
- **P4：** 加入“继续重建”或“修改开发文档”任务，对照直接文件工具与记忆辅助读取；检查必要指令、事实、来源的完整性和有效性，记录主 agent 串行往返、底层工具操作、返回材料量、补读、耗时及主/worker 合计可得用量。区分轮数下降与总成本下降，未验证前保持待验收状态。

## 阶段与完成条件

### P0 收敛边界和运行入口

**动作：** 复用已交付包、配置和初始化入口，以减少本项目自维护源码和胶水为选型首要依据。先核现成工具的已发布版本、Windows 支持、离线运行、项目隔离和向量接入，静态筛至最多两条路线，再用同一小资料集做小原型并选定唯一底座。

本机开发复用所选系统 Python 的 editable 安装，源码留在仓库；修改生效、重装和常驻服务重启规则见 [开发安装与正式部署](../20261107-resource-coordination/deployment-layout-plan.md#开发安装与正式部署)。业务配置仍只绑定 Python 与机器配置，不增加源码路径入口。

候选包括 [SurrealDB 本地 MCP](https://surrealdb.com/docs/build/ai-agents/mcp/embedded)、[SQLite CLI](https://www.sqlite.org/sqlite.html) 加 [FTS5](https://www.sqlite.org/fts5.html)/[sqlite-vec](https://github.com/asg017/sqlite-vec)，以及 [Basic Memory 原生 MCP](https://docs.basicmemory.com/reference/mcp-tools-reference)。这是一份静态筛选清单，不同时实现三套适配。优先直接调用原生能力；允许为减少代码调整批量写入、查询输出或维护入口，在底座决定和验收样例中写明实际行为。

比较覆盖全文、向量、关系遍历、原文定位、增量和备份恢复；中文全文、多聊天并发及机械盘读写用实际样例核对，图片向量先用预计算样例核入库/查询，真实图文语义留 P2。记录所需自写 Python/SQL、skill/配置、额外服务和数据文件维护。嵌入库的多进程限制通过底座现成服务器或短事务串行调用处理；比较必要胶水与运行代价后选型。

同时核底座原生 ID、字段和导入/导出能否保存来源依据、关系及更正；优先复用这些结构，不维护第二份镜像知识或自有中间格式。必要适配只补项目差异，长期取舍遵守 [维护简化](../20261106-rebuild/plan.md#后续维护的简化)。

共享设施的历史观察与适用范围见 [基础设施调查](../20261107-resource-coordination/research/infrastructure.md#agenttools-当前可复用部分)；当前核验限制见 [环境说明](../../system/environment.md)。共享路径、模型和公共骨架沿资源任务成果复用。

**交付：** 可安装运行的记忆骨架、一份不超过一页的底座决定与未选路线的主要理由、一个小资料集。决定写明原生复用、必要自写部分、行为调整和持久数据合同。资料集包含当前/旧决定、低字面相似度关联、跨材料关系、图片和待处理材料；人工预期结果单独保存，用于隔离评测。

**完成：** 新路径可安装运行，配置可指定项目根，测试资料不含旧业务授权；底座选型结束后只维护一套实现。开发验证与 P5 正式安装试用分别记录。P0 不全量读取旧库、不重复下载权重，环境和公共骨架沿资源成果复用。

### P1 文字记忆闭环

**动作：** 用选定底座原生命令/MCP 跑通来源登记、文字检索、片段与原文定位。通过项目指令/短 skill 在正常任务开始时交付最简 `brief`，以项目核心和少量人工确认线索提供主动提示。检索 skill 完成一次派工，先允许显式维护；仅为实际缺口补胶水。文件结构建议按需引用已有 skill，其它布局也能使用记忆。

**交付：** 文本可用版本、一次实际订阅 subagent 检索记录和简短使用说明。

**完成：** 新聊天的普通任务能收到短地图及一个有关线索，未主动检索也有发现信息的入口；同一真实问题能找到依据，找不到时说明具体缺口；主 agent 无须手动调度每轮查询，内容与定位对应；两个项目不混入彼此资料，小样例备份恢复后依据与更正仍可回查。此时可小范围日常使用。

### P2 本地向量、图片和语义图

**依赖：** P1 可用，资源任务所选公开本地 embedding 接口与向量语义合同确定；大规模处理前明确共享模型和预算。P0/P1 不等待资源 R9，P2 按实际交付接口接入。

**动作：** 复用公开本地 embedding 服务与底座的外部向量接入，类名和 HTTP/RPC 协议由最终方案确定。当前模型为 Qwen3-VL-Embedding-2B、2048 维，实施时核实际 revision、预处理与输入合同；行为调整在验收中明确。查询和资料使用兼容向量空间，索引保存向量语义身份（当前为 embedding_identity）；协议和部署身份仅用于诊断。语义变化时重建或隔离旧索引，纯部署变化保持语义兼容。

先支持图片文件和 PDF 必要页面。视觉 agent 实际看图，保存短描述、必要 OCR/表格及区域定位；识读文本标明是派生解释，结果仍能回到原图/页。

建图覆盖真实实体、决定、条件和材料关系，不只在“新洞见”时建节点。新增和变更时共同阅读相关片段、旧图邻域和检索近邻；手动深维护加入小比例随机共读与旧内容重访。先批量合并跨 worker 候选，再应用关系，避免只连到各自新节点。边独立增改，新边保留其它已有边。

分段是同次阅读的副产物，不能代替语义任务。普通原件先稳定地按结构分段，需要智能边界时复用同次阅读，不为全量智能分段延迟可用版本。

后续仅在代表性语料出现实际耗时或内存瓶颈时，启用底座原生近似向量索引、压缩或图查询优化，并用同一资料集比较召回与代价；不预写 ANN、图执行器或跨库同步层。

**完成：** 文字问题能召回图片并定位原图/页；低字面相似度任务沿至少一条有依据的跨材料关系找到关键资料；矛盾、更正、删除、节点合并和重复维护得到正确结果。报告有效关系例子、错误和未测范围，以实际发现验收，不用边数阈值结案。

### P3 主动提示与增量维护

**动作：** 短入口 skill/项目指令在任务开始或接续时调用 `brief`；任务内按变化触发小批维护，手动深维护使用同一入口。自动维护发生于任务过程中，不建设常驻后台 agent。

主动提示优先使用短项目地图、最近变化与相关决定/条件，再按有限预算轮换探索线索。启动不重新遍历全文；初建负责已声明范围的整体整理，后续按变化和重访扩充。已有项目可分批建库，明确剩余资料。

默认用文件清单、大小和时间等低成本信息找变化，实际读取时绑定内容版本；查询不遍历/哈希全部权重、原件和历史快照。已知变更影响的知识标为待更新或历史，更新前不作为当前结论。已登记、已读、已形成语义、已能检索四种覆盖直接从实际记录汇总，保持一条工作流。

“已知必读”仍是未确认的执行建议：如采用，将少量已确认前提直接交给工作 agent，补充探索性候选；预算不足时说明未交付内容。先用显式列表，不复制旧 map 平台或通用依赖推理器，不将此建议作为其它阶段前置条件。

**完成：** 未指示检索时，主 agent 经启动线索发现一个原本未点名的相关前提；任务内修改资料后完成一次真实增量维护；自动预算结束说明下次位置，手动处理可以继续；流程不要求反复完整载入长合同。

### P4 小型独立评估与机械盘检查

**依赖：** P2/P3 核心行为形成；P0 小样例从早期就用于回归，完整闭环不等到本阶段才首次运行。

这组公开行为与小资料集也用于底座、模型库和依赖升级；只补受变化影响的场景，局部真实故障回归继续保留，不把底座内部状态机复制成项目长期测试合同。

约 8–12 个固定任务覆盖主动未知提示、精准查找、跨材料关系、图片、更正/删除、范围隔离和失败，并包含 devDoc 自用。比较普通文件工具、短常驻信息加文件工具、完整记忆三组；需要时去掉图做一次消融，确认收益来源。起点无需建设聊天 fork；答案与评分材料放在被测不可见位置。固定模型配置、任务输入、资料范围，报告实际可观察配置。

| 维度 | 记录 |
| --- | --- |
| 质量 | 预列必要信息的找回/漏项、错误和过期事实、原文支持情况 |
| 主动性 | 未提示检索时发现的内容及适用条件；成功样例不代表解决所有未知未知 |
| 上下文 | 工作 agent 实收字符数、检索委托次数；宿主提供 token 时再记 token |
| 成本 | 初建、更新、主 agent 与 worker 的总墙时/可得用量；缺价格或计量则留空，不用字符冒充费用 |
| 维护 | 改动后正确性、重复处理量、待处理范围、失败定位 |
| 自维护量 | 本项目新增源码、SQL/skill/配置及必要胶水；现成能力覆盖、行为调整和额外服务代价 |
| I/O | 文件数、读写量与频率；真实机械盘或明确标注的替代条件，区分冷/热启动 |

**完成：** 核心行为样例通过，逐任务报告收益、无收益或未定条件及成本。即使未发现净收益也如实结束评估；质量无收益或维护过重时，先收敛问题机制，不扩大语料掩盖问题。证据不足则记录未定，不无限扩测拖延交付。

### P5 独立目录安装试用与发布

**动作：** 按 [正式部署合同](../20261107-resource-coordination/deployment-layout-plan.md#开发安装与正式部署)，在源码外项目正式安装 basePack 与选定底座；basePack 自有包使用普通 wheel，独立 CLI/MCP 按其正式安装方式交付。用公开/合成资料跑首建、检索、修改、任务内维护、手动深维护和恢复；另一个目录核隔离。真实业务资料待用户指定。

**完成：** 正式安装后换路径可用，不依赖 editable 映射、源码仓库路径或旧项目可变文件/数据库；实例问题回改唯一产品维护源，按实际发行方式重新安装验证；形成短试用报告。真实新业务项目效果待指定资料后验证，公开/合成试用不替代该结论。完成本任务即可发布第一版完整记忆工具，不等待其它工具全部完成。

发布前同步面向使用者的 README、安装/接入说明和短示例，说明启动提示、一次检索、维护、失败定位与共享 embedding 接入；系统文档只写实际落地行为。联合场景是资料问题 → 检索返回证据 → 项目变化后增量维护 → embedding 经过共享服务 → 新知识仍保留项目局部；普通短文件读取和每次 agent 派工无需进入重任务队列。

发行内容、体积预算与远端发布检查遵守 [总体计划](../20261106-rebuild/plan.md) 的共性要求；本任务以新路径安装、完整记忆闭环和发布清单通过作为独立发布条件。公开/合成资料试用与真实业务效果分别报告。
