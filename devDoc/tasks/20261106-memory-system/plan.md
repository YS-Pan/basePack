# 记忆系统实施计划

2026 年 11 月 9 日按已提交纲领 `2f55a56` 更新，现已获用户授权执行；2026 年 11 月 11 日同步现行查询与发布合同。本文是记忆专项实施源；日常接续读本计划与 [进度](progress.md)，跨工具取舍/联合发布再读重建总览。实际接入证据见 [P0 结果](p0-result.md)，项目数据关系与阶段依赖见 [方案框图](diagrams.md)。

## 目标与范围

记忆工具既要回答已知缺口，也要在 agent 未主动检索时交付相关线索，使其发现尚未意识到的前提；初建、检索和维护都要低成本。项目知识、来源、状态和数据库留在各自项目，通用工具、模型与机器资源可以显式共用。机械盘可用性属于交付要求。

首期仅采用 SurrealDB 基座，优先原生 CLI/MCP、查询与事务，不建设多后端适配。P0 的本机原生接入已通过，证据与边界见 [结果](p0-result.md)；历史工具比较按需追溯，只有实际目标阻碍才重新讨论替代路线。

多层次表示进入默认摄取与检索：长文件的文件、章节、原文块分别可寻址、检索并作为图节点。订阅 agent 在同次阅读中完成智能分块、摘要和节点/图边总结。先交付多层文字、初步语义关系、启动线索、一次检索委托、增量与恢复；P2 扩展图行为及本地图文向量。早期文字版本不代表完整目标完成。

当前唯一 active 工程是 [20261106-basepack](../../../experiments/20261106-basepack/README.md)。资源 R9 已交付 0.5.0 并归档，[R9 结果](../../archive/20261107-resource-coordination/r9-result.md) 支持共享 embedding 与 Condor 的既有验收；它们不证明记忆行为。实施基线的 `init`、配置和模板可复用，0.5.0 当时的 `memory.data_dir` 仅是路径预留；新增能力与实际阶段从进度接续。

## 最小行为与数据合同

### 多层次表示与跨层检索

多层次是用户已选定的目标；底座与评测用于收敛实现和成本。默认长结构文件保留文件—实际章节—原文块，各层具有稳定身份、父子关系、原文范围和可检索表示；只有叶块附带文件名不算完成。短文件、无标题材料、聊天和图片采用实际存在的层次，P0 记录映射，不虚造章节。

| 成员 | 默认检索表示与回源 |
| --- | --- |
| 文件 | 标题及有依据的全文摘要；指向该文件、所覆盖章节与必要证据 |
| 章节 | 标题路径及本章摘要；指向章节范围和子块 |
| 原文块 | agent 智能划定的段落或连贯原文片段，保留必要文件/章节背景与准确范围；长块由同一阅读者调整边界以满足输入限制 |
| 图片/必要 PDF 页 | 原图向量与独立标明的识读文本；定位原图、页或区域，并关联所属材料 |

脚本提取标题、段落等结构单元供定位和备读；最终用于图/向量的文字块，由订阅 agent 在阅读并总结节点/图边的同一批次决定。边界落到原文范围，不改写原文；同批产出块边界、文件/章节摘要、节点/关系及依据，未发现关系时如实记录，不另排全量智能分块或全量建图阅读。

摘要保留主题、结论、条件、例外和已知矛盾；长材料可分批阅读后汇总，部分覆盖显式写明缺口。摘要文字和依据持久保存，不把超长原文截断冒充完整文件向量。P1 各层文字与初步关系可查，P2 将各层表示编码并验完整图文行为；不要求所有实体/决定节点也生成向量。程序核原文定位与实际输入限制，超限回到该批调整边界，不静默截断或用机械分块替代最终边界。

默认查询取得原文块与文件/章节摘要的跨层候选，保留细节直接召回通道；使用底座原生查询、排序/融合或短 skill 批量查询，不增加独立 LLM 路由服务。worker 根据问题向上补背景、向下找证据，并按语义边扩展；粗层命中不成为读取细层的唯一门槛。按实际返回内容与原文范围消除父子重叠，保留同文件的互补证据；不把摘要及其全部子级同时塞入结果。父层预筛、候选份额与融合参数留作受测优化，不改变各层可直接检索的合同。

图中区分三种连接：脚本可确定的包含关系；摘要表示到被概括材料的依据连接；agent 共读建立的支持、反驳、依赖、修正等语义边。连接可复用原生字段/链接，不强制另造边表。实体、决定、条件等知识节点与来源层级共存；跨材料语义关系就是图的语义边，可连接不同粒度。高层关系保留适用范围，具体事实与关系判断回到原文证据；包含树和摘要数量不代替语义图验收。

### 启动与一次检索委托

以下是行为名，不要求新增四个 basepack 子命令：

| 动作 | 输入 | 实际交付 |
| --- | --- | --- |
| `brief` | 显式项目配置、可选任务说明 | 必须保留的项目核心/指令/前提，少量相关或探索线索，已发布知识的待核与覆盖缺口，原文入口；不检查原件变化 |
| `search` | 问题、项目内范围、结果预算 | 候选的相关内容、依据与定位，必要图片路径，未解决缺口 |
| `read` | 成员 ID、可选依据版本与范围 | 已发布或指定依据版本的原文或图/页快照；不查当前原件，快照缺失或损坏时报错 |
| `maintain` | 变化范围、自动/手动模式、预算 | 已应用内容、具体失败和剩余范围，供下一次接续 |

启动分两层：必须保留的信息直接交付，不参加筛选和评分；相关与探索线索按任务及预算选择。P1 先用短项目说明和显式线索清单，P3 再扩充自动选择。根 AGENTS 的短指针指向项目 `.basepack/instructions.md`；宿主按该入口读取信息或执行 `brief`。MCP 注册、skill 存在和指针存在都不能算信息已到达。P1 必须在实际新任务中观察到启动读取与线索交付；没有通用启动 hook 时，以项目指令驱动宿主，不能宣称后台自动注入。

工作 agent 发出一次含目标、范围和预算的委托 → 一个 worker 检索、读候选、必要时多轮扩展 → 对实际读到的内容给分 → 脚本按分排序并截取 → 返回可直接使用的内容、来源和缺口。默认同一 worker 完成检索与评分，使用项目配置的检索等级（默认 tier1）；记录实际可得的模型信息，宿主不提供时写未取得。工作 agent 可任意补读。跨批候选用共同尺度或一次汇总评分，底座的词法/向量距离不冒充 agent 分数。

检索预算由任务决定，不把旧字符数当硬门槛。先交付必要证据，再安排补充内容；被预算省略的相关材料留下精确补读入口。必须保留的信息不因检索预算消失，超额或缺失时显式报告。派工包、候选列表或打分回执都不能替代最终内容交付。

### 项目知识与恢复

| 对象 | 最小合同 |
| --- | --- |
| 来源/多层成员 | 来源 ID/版本、成员稳定 ID、实际层级、父级及原文范围；路径或可访问聊天定位，图片/PDF 包含页/区域 |
| 检索表示 | 关联成员、原文/摘要/识读类型、表示文字与输入版本、所依赖材料版本及覆盖缺口；复用底座字段，不重复维护一套镜像 |
| 节点/边 | 复用 SurrealDB 原生记录/关系 ID 稳定定位和独立增改，保存两端、简短含义、条件、支持来源及版本 |
| 更正/变更 | 当前与历史的区别、必要旧依据、操作与时间、宿主可取得的执行聊天/turn/根聊天信息；缺失字段留空 |
| 索引 | 可重建的全文/向量派生数据；向量绑定具体表示 ID、输入版本及 `embedding_identity`，使用兼容的查询空间 |

复用 SurrealDB 原生记录/关系、字段与事务，持久知识只维护一份。已接受的智能块边界、agent 摘要、层级/依据、语义节点/边、人工更正和不可重新取得的识读结果均属持久数据；恢复已接受表示及对应版本的原件后可重建向量，无须重新调用 agent 总结。来源版本、表示输入版本、模型语义身份分别维护：源文件变化不必使所有未变块重编码，模型身份不变也不代表摘要仍新鲜。版本号/哈希只能识别内容；旧依据由业务版本系统或必要片段/快照保留，P0 明确方式。原件继续由业务项目保管，不自动复制整库，也不从旧项目承接数据库、任务或授权。

来源、知识、索引和运行记录保持项目局部，优先收在 `.basepack/memory/` 的少量存储文件。同一项目的多聊天复用一个项目本地 SurrealDB 进程，通用程序共用，库文件仍留在对应项目；查询/维护绑定显式项目配置，P0 验连接与隔离。移动项目后稳定 ID 和项目内相对定位应继续有效，外部来源失效要可见。

P0 确定一致性备份集合、恢复命令及清理边界：持久知识、来源依据、必要项目配置和重建索引所需信息必须可恢复；业务原件纳入对应项目的备份责任。使用底座原生备份/导出或停写快照，不能运行中只复制一个可能依赖日志的数据库文件。P1 在另一目录恢复后核各层身份、摘要/依据、更正与查询，P2 再核跨层图和向量恢复/重建。Git 忽略、工具缓存和历史 `.basepack/migration/` 备份都不能代替知识库备份；长期备份目的地和保留周期在正式业务接入前确定。

### 共读、变化与 I/O

创建与维护共用：维护入口检测新增/修改/删除 → 取相关新旧原文、旧图邻域和检索近邻 → 程序准备可证明的机械等价内容，其余由 agent 同次共读、智能分块、摘要并总结节点/边 → 准备候选内容与匹配向量 → 同一短事务发布。作者生成并由程序提交后本批完成，默认不增加批量审核、发布后回读或独立审计；仅用户明确要求记忆系统审计时按授权范围做手动审计。提交前核对本批来源、改写目标及实际使用知识的版本；材料或知识已变时停止该批并重读，冲突保留原错。向量准备或版本核对失败时不发布本批，查询继续读取上次已发布知识及其依据快照。

建图覆盖实体、决定、条件和跨材料关系；结构解析只供定位，智能分块与关系理解同次完成，分段量不能代替语义工作。跨 worker 候选先汇合，共读两端及依据后再应用，避免只连接各 worker 的新节点。边可独立新增、更正、失效或合并；新增关系保留其它有效边，来源删除后按剩余依据判断有效性，历史依据和人工更正仍可回查。检索中发现错误可以进入同一修正流程。

自动维护由业务任务承载，从已声明项目来源的新变化和历史待核按来源小批推进，业务结束停止；手动维护由用户发起，允许深读、旧图重访和随机共读。积压多不退出正常自动小批，派工纠偏与程序化预检沿[综合计划E](../../archive/20261110-onboarding-simplification/plan.md#e脚本优先的增量维护优先实施)接续。首建对已声明范围完成整体阅读与整理；已有大项目可按主题分批，报告未处理边界，避免全关系两两比较。跨作者整合必要共读属于作者工作，不是额外审核阶段；争议关系保留条件和未决，不自动追加审核，使用中问题走反馈。大批建图按纲领采用 tier2 协调者与 tier1 阅读者，每个协调者最多管理四个 tier1 worker，团队规模按实际任务调整。

brief、search 和 read 只读已发布知识及对应依据快照，不扫描原件或触发维护。变化检测由显式 changes/maintain 承担，优先文件清单、大小/时间、已知编辑或原生同步；实际读取时绑定内容版本，显式深检查核实低成本检测可能漏掉的变化。发现变更只形成维护候选，已发布版本继续可查；对当前原件的判断须另行核实。已登记、已读、已形成语义、已能检索的覆盖从实际记录汇总，报告剩余位置；不建立重复台账。

多层增量按实际依赖处理：段落变化将该表示、依赖它的祖先摘要/向量及相关语义依据列入维护候选，再局部共读、更新摘要并重审关系，复用未变兄弟材料。发现变化不即时撤下已发布态；接受批次时发布替换内容，并按显式更正、退役及实际依赖处理受影响记录。摘要经重核而输入文字未变时，可更新依据版本并复用向量；只有定位变化且输入未变时无需重编码。标题、父级背景若进入表示文字，改名/移动也要按输入变化更新。拆合章节/段落后保留可追溯映射；接受删除时处理其包含、摘要依据与语义关系，仍有其它依据的知识不盲目删除。用原生引用查询找受影响范围，保留既有失效与恢复验收，不预建通用依赖调度器。

各层是逻辑对象，不要求每段每层另建物理文件。原生写入/事务按批处理，索引按受影响范围更新；控制逐片段文件、日志、重复快照和全库复制。P0 即测小规模冷/热启动、批量维护和并发，P4 在代表性语料与真实机械盘检查放大后的成本。出现实际瓶颈才采用底座原生 ANN/压缩/图查询优化，记录召回与代价；不预建索引执行器或跨库同步平台。

## 阶段与完成条件

依赖为 P0 → P1 → P2、P3；P2 的语义图和多层/图片向量可分开推进。P3 文字流程从 P1 开始，语义图与向量维护分别在对应能力启用后验收，不等待图片分支完成。评估从 P1 开始积累，P4 汇总完整行为，P5 验正式安装。每阶段按用户行为结案，阶段编号与规模预算均可随证据调整。

### P0 收敛底座与数据合同

**动作：** 仅验证 SurrealDB 正式发行版和原生 CLI/MCP 接入，记录实际版本、Windows/离线运行、项目内数据路径、同项目多聊天连接与必要 SQL/skill。按 [接入依据](research/backend-review.md) 用单个项目本地 server 保持显式连接，通用程序可共用；不把跨项目 namespace 当作项目数据物理局部。使用预计算向量核存取，不为本阶段切换共享模型服务，也不安排 Basic Memory/SQLite 安装或对照原型。

同一样例含实际章节的长文件、预置语义块边界、固定摘要、跨材料依据、图片及旧/新决定，预期结果与被测资料隔离。核三种粒度寻址/过滤、中文全文、外部向量、父子/语义关系查询、局部失效/更新、未变材料复用、两聊天并发、两项目隔离和新目录恢复。固定边界/摘要仅是接口夹具；真实同读智能分块/摘要/建边在 P1 验，本地多层及图片编码在 P2 验。

**交付与完成：** 留下简短 SurrealDB 接入决定与可重复样例，明确多层成员/表示/关系的原生映射、必要 SQL/skill、事务、持久数据/备份集合、并发及恢复方式；新路径完成上述往返。关键缺口未解决时报告具体失败，不宣称适用性已通过；需要更换基座时再依据实际阻碍决策，不提前保留多后端抽象。

### P1 文字最小可用闭环

**动作：** 在 active 工程接入 SurrealDB，以公开/合成资料及本项目 devDoc 自用。订阅 agent 在同次阅读产出智能块边界、文件/章节摘要、节点/关系与依据，按原生事务落库；用 CLI/MCP 加短 skill 完成多层文字检索、父子/初步语义展开、启动线索、一次检索委托、增量与恢复，不等待 embedding、Condor 或三层组织。

**完成：** 实际记录证明同一阅读批次产生可回原文的智能块边界、摘要和有依据的初步关系，不能拿机械分段或只准备任务包结案。新任务实收必保留信息及相关线索；一次委托取得多层正文/定位，能父子展开和沿样例语义关系找到依据，记录真实阅读/给分与脚本排序，避免重复交付。至少一次原文修改后，同批完成块边界、摘要与相关关系更新，并重新检索到新结果；其余未处理范围明确标待更新。两项目隔离，含边界/摘要/关系/更正的小库恢复后可查。此时只声明多层文字版与初步关系可用，完整语义图和向量行为继续 P2。

### P2 语义图与本地图文向量

**依赖：** P1 可用。图分支只需底座关系能力与宿主 agent；向量分支复用已交付的公开 HTTP `EmbeddingClient(machine).embed(inputs, timeout=...)` 或同一 `/predict` 接口，不需要再次放行资源 R9。

**图分支：** 扩展 P1 同读产出的关系，覆盖跨层/跨材料的非结构化文档、图片与决定；继续在维护共读中同时修正智能边界、摘要与节点/边，避免为 P2 重读全部材料。试跨 worker 候选汇合及随机共读/旧内容重访，记录发现或未发现的结果。用矛盾、更正、删除、节点合并和重复维护验完整关系行为；结构包含与摘要依据不算语义关系发现。

**向量分支：** 现有 EmbeddingClient/HTTP 编码各层表示，向 SurrealDB 写入外部向量，不另起模型或协议服务。查询和资料使用兼容空间，索引记录 `embedding_identity`，同维数不能证明兼容；身份变化时隔离/重建受影响向量，纯部署变化不触发语义重建，权威见 [资源模块](../../system/modules/resources.md)。客户端超时只结束等待；失败保留原错与待处理范围，不自动重投或停止共享服务。沿 [资源使用](../../../experiments/20261106-basepack/docs/resources.md) 的真实输入限制分批，不依赖已退役接口。

先支持图片文件和必要 PDF 页。视觉 agent 实际看图，保存短描述、必要 OCR/表格和页/区域定位，派生解释与原图依据区分。描述文本可以辅助检索，不能代替多模态向量验收。

文件/章节摘要与原文块分别通过当前本地服务真实编码、存储并进入默认查询；标题路径与必要背景作为显式表示输入记录版本。长文件使用完整覆盖的摘要表达，不为本阶段改变服务输入限制。层级表示复用同一兼容空间，保留原文块直接召回及各层候选身份，不把只给叶块编码的 parent retrieval 当作各层向量完成。

**完成：** 用文件概览、章节主题、精确细节问题分别核实际命中相应层次，摘要命中能回到原文，摘要漏掉的细节仍能直接检索；低字面相似任务沿有依据的跨层/跨材料语义边找到关键内容。另核文字经原始图片向量召回并打开原图/页。更正/删除/合并/重复维护正确；恢复后各层图可查，向量可恢复或从保留表示重建，表示/模型身份不兼容可定位。报告有效关系、误召回和未测范围，不以层数、边数或向量维数结案。

### P3 主动探索与任务内维护

**动作：** 在 P1 显式流程上扩展任务开始/接续时的线索选择，由独立维护入口进行低成本变化检查，需要时在任务内小批自动维护；手动深维护沿同一流程继续。启动可从已发布文件/章节摘要和语义关系选取短地图、相关决定/条件及探索线索，按需核原文；不重新读全库或建设常驻后台 agent。必保留前提沿 P1，依赖更新沿本计划的局部维护合同。

**完成：** 普通任务未指示检索时，经启动线索发现未点名的相关前提；独立维护发现真实段落编辑后，完成该块与祖先摘要局部维护，对已启用的向量和语义依据同时验依赖更新，未变兄弟复用，发布后 brief/search 反映新版本。标题/位置调整按实际输入依赖处理；预算结束仍可见待处理范围，手动深维护能接续和重访。已声明范围、摘要覆盖及索引新鲜度可查，人工更正保留，流程无需反复完整载入长合同。

### P4 独立评估与机械盘检查

**动作：** 从 P1 留存小样例回归，P2/P3 形成后做一组小型独立任务。起始可用约 8–12 题，按覆盖需要调整；包含已知查找、未点名线索、低字面关系、图片、更正/删除、隔离、恢复与明确失败。把普通文件工具、短常驻信息加文件工具、完整记忆三组对照；针对图、向量或评分的疑问再做相应消融。预期答案对被测 agent 不可见，测试初始上下文核实实际启动信息，避免“新聊天”继承答案或已有记忆。

多层专项加入文件概览、章节主题、跨段证据、摘要漏掉例外而细层可召回、父子重复、章节移动/拆合、局部更新与恢复。固定语料、模型和最终上下文预算，对照仅原文块、原文块加父级扩展、多层摘要/原文混检；父层预筛按实际疑问追加。消融用于改进多层实现，不把用户已选目标降成开关；同时记录各层召回与实收、原文核实、摘要生成成本、重复展开和更新放大，质量与速度/费用分别下结论。

| 维度 | 必须区分的证据 |
| --- | --- |
| 质量与主动性 | 必要信息找回/漏项、原文支持、过期事实/错误；未点名信息实际到达并被使用，不能只看候选命中 |
| 上下文与成本 | 主 agent 串行往返、底层工具操作、实收字符、补读、主/worker 合计墙时及可得用量；缺 token/价格留空，轮数下降不等于费用下降 |
| 维护与恢复 | 初建/增量耗时、摘要生成量、未变表示复用、更新放大、失败与待处理范围；恢复后各层内容与依据可查 |
| 自维护与 I/O | 本项目代码/SQL/skill/配置、额外服务代价；数据文件数、读写量/频率、冷/热启动与批量更新条件 |

#### devDoc 自用与读取轮数

本项目 devDoc 自用包含“继续重建”“修改开发文档”，核必要指令、事实、来源是否直接交付，以及寻找/交叉取证是否减少主 agent 往返；已知少量文件仍可同批直接读。P1 开始用同一文字流程，P3 核文档变化后的启动与检索新鲜度，P4 与直接文件工具对照。

普通检索与初始化要在真实机械盘运行，记录盘与资料规模；替代条件只能形成局部结论，不能代替机械盘验收。已测范围及未测条件见 [P4 结果](p4-result.md)。

**P4 完成：** 核心行为样例通过，逐任务给出收益、无收益或未定及其全周期代价；不同组记录实际可观察的模型、输入、范围和配置。未见净收益时保留结论，先修已定位机制，不扩大语料掩盖问题；证据不足标未定。真实机械盘未测可结束该次实验，但不能声明完整交付已满足机械盘要求。这组公开行为复用于依赖升级，只补受影响场景和真实故障回归。

### P5 正式安装试用与发布准备

**动作：** 按 [正式部署合同](../../system/deployment.md#环境与服务)，在源码外项目普通安装 basePack wheel 及底座正式版本，跑多层首建、启动线索、跨层检索/语义展开、修改、任务内维护、深维护、移动与恢复；恢复保留的摘要/层级/依据后重建向量，第二目录验隔离。实例问题回改唯一维护源并重装，真实业务资料待用户指定范围。

**完成：** 全闭环可复现，不依赖 editable、源码路径、旧项目可变文件或 tmp；已有真实 HDD 可用性验收，P4 的质量、成本及机械盘条件随短试用报告交付，HDD 未测时只报告局部试用。同步 active 工程 README、docs、短示例和专用 skill，说明当前能力、启动交付、一次检索、维护、恢复、失败和共享 embedding 接入，根 system 只记录实际落地行为。公开/合成试用与真实业务效果分别报告。

完整记忆工具可独立发布，不等待其它工具全部完成；发行内容、体积和远端检查遵循 [总体计划](../20261106-rebuild/plan.md#p8-联合交付与轻量发布)。联合场景核“问题→证据→资料变化→增量→共享 embedding→项目局部知识”，不重复 R9 的服务故障/回退矩阵，普通读取和 agent 派工无需进入重任务队列。
