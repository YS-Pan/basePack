2026 年 11 月 9 日重评，基线为 main `5d72275`。本文维护工程方案，目标以 [项目纲领](../../project-charter.md#记忆系统) 为准；实际阶段只在 [进度](progress.md) 维护。本次交付限于计划与开发文档，未开始 P0 原型或记忆功能实施。项目数据关系与阶段依赖见 [方案框图](diagrams.md)。

## 目标与范围

记忆工具既要回答已知缺口，也要在 agent 未主动检索时交付相关线索，使其发现尚未意识到的前提；初建、检索和维护都要低成本。项目知识、来源、状态和数据库留在各自项目，通用工具、模型与机器资源可以显式共用。机械盘可用性属于交付要求。

先交付可日常试用的文字闭环：短项目说明、真实启动线索、文字检索与原文定位、一次订阅 agent 检索委托、最小增量和恢复。完整版本继续交付本地图片/文字向量、agent 创建的语义图、主动探索及深入维护。早期文字版本不代表完整目标完成。

当前唯一 active 工程是 [20261106-basepack](../../../experiments/20261106-basepack/README.md)。资源 R9 已交付 0.5.0 并归档，[R9 结果](../../archive/20261107-resource-coordination/r9-result.md) 支持共享 embedding 与 Condor 的既有验收；它们不证明记忆行为。现有 `init`、配置与模板可以复用，`memory.data_dir` 仅是路径预留，尚无记忆命令、底座或数据库。

## 最小行为与数据合同

### 启动与一次检索委托

以下是行为名，不要求新增四个 basepack 子命令：

| 动作 | 输入 | 实际交付 |
| --- | --- | --- |
| `brief` | 显式项目配置、可选任务说明 | 必须保留的项目核心/指令/前提，少量相关或探索线索，变化与覆盖缺口，原文入口 |
| `search` | 问题、项目内范围、结果预算 | 候选的相关内容、依据与定位，必要图片路径，未解决缺口 |
| `read` | 来源 ID、版本、范围 | 对应原文或图/页；版本已变或原件缺失时明确返回该事实 |
| `maintain` | 变化范围、自动/手动模式、预算 | 已应用内容、具体失败和剩余范围，供下一次接续 |

启动分两层：必须保留的信息直接交付，不参加筛选和评分；相关与探索线索按任务及预算选择。P1 先用短项目说明和显式线索清单，P3 再扩充自动选择。根 AGENTS 的短指针指向项目 `.basepack/instructions.md`；宿主按该入口读取信息或执行 `brief`。MCP 注册、skill 存在和指针存在都不能算信息已到达。P1 必须在实际新任务中观察到启动读取与线索交付；没有通用启动 hook 时，以项目指令驱动宿主，不能宣称后台自动注入。

工作 agent 发出一次含目标、范围和预算的委托 → 一个 worker 检索、读候选、必要时多轮扩展 → 对实际读到的内容给分 → 脚本按分排序并截取 → 返回可直接使用的内容、来源和缺口。默认同一 worker 完成检索与评分，优先采用宿主可用的廉价模型；记录实际可得的模型信息，宿主不提供时写未取得。工作 agent 可任意补读。跨批候选用共同尺度或一次汇总评分，底座的词法/向量距离不冒充 agent 分数。

检索预算由任务决定，不把旧字符数当硬门槛。先交付必要证据，再安排补充内容；被预算省略的相关材料留下精确补读入口。必须保留的信息不因检索预算消失，超额或缺失时显式报告。派工包、候选列表或打分回执都不能替代最终内容交付。

### 项目知识与恢复

| 对象 | 最小合同 |
| --- | --- |
| 来源/片段 | 稳定 ID、项目内路径或可访问的聊天定位、内容版本、类型、原文范围；图片/PDF 包含页或区域定位 |
| 节点/边 | 节点稳定 ID；关系可稳定定位和独立增改，保存两端、简短含义、条件、支持来源及版本；优先原生边 ID 或笔记中的关系定位，不预设边表 |
| 更正/变更 | 当前与历史的区别、必要旧依据、操作与时间、宿主可取得的执行聊天/turn/根聊天信息；缺失字段留空 |
| 索引 | 可重建的全文/向量派生数据；向量绑定来源版本及 `embedding_identity`，使用兼容的查询空间 |

复用底座原生 ID、字段与事务，持久知识只维护一份。语义节点/边、人工更正、不可重新取得的识读结果、来源版本及其依据属于持久数据。版本号或哈希只能识别内容；旧依据要么可从业务原件的版本系统回查，要么保留必要片段/快照，P0 明确采用哪种方式。原件继续由业务项目保管，不自动复制整份资料库，也不从旧项目承接数据库、任务或授权。

来源、知识、索引和运行记录保持项目局部，优先收在 `.basepack/memory/` 的少量存储文件；原生 Markdown 底座若更合适，以实际文件量和批量 I/O 决定。同一项目的多聊天可复用一个项目本地数据库进程，通用程序共用，库文件仍留在对应项目；查询/维护绑定显式项目配置，按底座实际连接方式验隔离。移动项目后稳定 ID 和项目内相对定位应继续有效，外部来源失效要可见。

P0 确定一致性备份集合、恢复命令及清理边界：持久知识、来源依据、必要项目配置和重建索引所需信息必须可恢复；业务原件纳入对应项目的备份责任。使用底座原生备份/导出或停写快照，不能运行中只复制一个可能依赖日志的数据库文件。P1 恢复至另一目录后核原文、更正与查询，P2 再核图和向量的恢复/重建。Git 忽略、工具缓存和历史 `.basepack/migration/` 备份都不能代替知识库备份；长期备份目的地和保留周期在正式业务接入前确定。

### 共读、变化与 I/O

创建与维护共用：机械检测新增/修改/删除 → 取相关新旧原文、旧图邻域和检索近邻 → agent 共读并提出节点/边/必要分段 → 可选批量审核 → 按底座原生写入/事务边界提交知识 → 更新受影响索引。提交前核对本批来源版本，材料已变时停止该批并重读，冲突保留原错；文件型底座按原生提交结果接续，不承诺跨文件事务。知识已提交而索引失败时，明确待更新范围，成功重建后才按新版本交付。

建图覆盖实体、决定、条件和跨材料关系。普通分段先按结构完成，智能边界复用同次阅读；分段量不能代替关系理解。跨 worker 候选先汇合，共读两端及依据后再应用，避免只连接各 worker 的新节点。边可独立新增、更正、失效或合并；新增关系保留其它有效边，来源删除后按剩余依据判断有效性，历史依据和人工更正仍可回查。检索中发现错误可以进入同一修正流程。

自动维护发生于当前任务的小批变化，手动维护允许深读、旧图重访和随机共读。首建对已声明范围完成整体阅读与整理；已有大项目可按主题分批，报告未处理边界，避免全关系两两比较。默认省略独立审核；争议关系可批量审核。大批建图按纲领采用协调者与廉价阅读者，每个协调者最多管理四个廉价 worker，团队规模按实际任务调整。

变化检测优先文件清单、大小/时间、已知编辑或原生同步；实际读取时绑定内容版本。启动/普通查询不遍历哈希全部原件或权重，提供显式深维护检查低成本检测可能漏掉的变化。已知变更影响的结论先标为待更新或历史，不能继续冒充当前事实。已登记、已读、已形成语义、已能检索的覆盖从实际记录汇总，报告剩余位置；不建立重复台账。

原生事务批量写入，索引按受影响范围更新；控制逐片段文件、日志、重复快照和全库复制。P0 即测小规模冷/热启动、批量维护和并发，P4 在代表性语料与真实机械盘检查放大后的成本。出现实际瓶颈才采用底座原生 ANN/压缩/图查询优化，记录召回与代价；不预建索引执行器或跨库同步平台。

## 阶段与完成条件

依赖为 P0 → P1 → P2、P3；P2 的语义图和图文向量可分开推进，P3 的文字流程从 P1 开始，图维护验收依赖 P2 图分支，不等待图片向量。评估从 P1 开始积累，P4 汇总完整行为，P5 验正式安装。每阶段按用户行为结案，阶段编号与规模预算均可随证据调整。

### P0 收敛底座与数据合同

**动作：** 将 Basic Memory、SQLite 方案和 SurrealDB 按 [同一记忆工作流](research/backend-review.md#按记忆工作流比较) 比较：Basic Memory 计入现成应用能力与适配成本，SQLite 计入必要 SQL 和部署简洁收益，SurrealDB 计入原生图/向量/MCP 与实例代价。记录已发布版本、本机 Windows/离线入口、必要自写代码/SQL/skill 和配置；按不确定性选择最短原型，不预设赢家或固定两个候选。当前公开 embedding 合同已定；优先用预计算向量检查底座接入，不为选型切换共享模型服务。Basic Memory 的自动文本索引行为须先核清，明确模型/provider 及新增依赖代价，避免隐式下载或重复加载共享模型。

样例覆盖中文精确项、旧/新决定、低字面相似关系、跨材料依据、图片及待维护材料，预期结果与被测资料隔离。用原生命令/MCP 实跑写入、中文全文、显式关系查询、外部向量入库/查询、来源定位、增量、两个聊天连接及一致性备份恢复。并发和中文分词不能只由“支持 SQL/MCP/Unicode”推断。P0 的边由小样例显式提供，真实 agent 建图留 P2。

**交付与完成：** 留下一份简短底座决定和可重复小样例，说明原生复用、未选理由、行为调整、原件/持久知识/派生索引归属、并发与恢复方式；从新的项目路径能用选定工具完成上述往返。选定后只维护一套产品接入。尚未通过的关键能力明确列为缺口，不能以“后续再补”结束选型；候选均不合适时记录具体冲突后再调整方案。

### P1 文字最小可用闭环

**动作：** 在 active 工程交付最短接入，用原生命令/MCP 加短 skill 完成来源登记、文字检索、原文定位、启动说明与线索、一次检索委托、显式小批维护及备份恢复。接入使用当前 init/配置；以公开或合成资料及本项目 devDoc 自用，不等待 P2 图文向量、Condor 或三层组织。若选 Basic Memory，沿 P0 核定的 provider 与自动文本索引方式运行，已有上游能力直接复用。

**完成：** 实际新任务收到必须保留的信息及一个相关线索；工作 agent 一次委托后取得可用正文和定位，记录证明 worker 实际检索/阅读/给分且脚本排序截取；找不到时说明缺口。修改并删除样例资料后更新检索和启动线索，旧结论不再作为当前答案。两个项目实际检索/维护互不混入；含更正和旧依据的小库备份恢复至另一目录后仍可查询、回查。这一阶段通过才可声明“文字版可试用”。

### P2 语义图与本地图文向量

**依赖：** P1 可用。图分支只需底座关系能力与宿主 agent；向量分支复用已交付的公开 HTTP `EmbeddingClient(machine).embed(inputs, timeout=...)` 或同一 `/predict` 接口，不需要再次放行资源 R9。

**图分支：** 用真实订阅 agent 共读、创建并检索跨材料节点/边，覆盖现有非结构化文档、图片与决定的关系。试一次跨 worker 候选汇合及一次随机共读/旧内容重访，记录发现或未发现关系的实际结果。用矛盾、更正、来源删除、节点合并和重复维护核独立边及依据保留。

**向量分支：** 查询和资料使用兼容空间，索引记录响应的 `embedding_identity`，同维数不能证明兼容。身份变化时隔离/重建受影响向量，服务地址、路径等纯部署变化不触发语义重建，字段权威见 [资源模块](../../system/modules/resources.md)。底座若仅接 OpenAI/Ollama 格式，先比较原生外部向量写入和最薄接入的成本，不新增无必要的协议服务。当前服务是常驻模型，客户端超时只结束等待；失败保留原错与待处理范围，不自动重投、不通过停共享服务取消任务。沿 [资源使用](../../../experiments/20261106-basepack/docs/resources.md) 的真实输入限制分批，不依赖已退役的取消、tokens_only、私有 RPC 或代码指纹。

先支持图片文件和必要 PDF 页。视觉 agent 实际看图，保存短描述、必要 OCR/表格和页/区域定位，派生解释与原图依据区分。描述文本可以辅助检索，不能代替多模态向量验收。

**完成：** 分别保留真实图遍历和真实本地向量查询证据：低字面相似任务沿有依据的跨材料关系找到关键内容；文字查询通过图片向量召回并打开原图/页，图文语义确实有用。上述更正/删除/合并/重复维护结果正确，恢复后图可查询、向量可恢复或重建，身份不兼容可定位。报告有效关系、误召回和未测范围，不以边数或向量维数结案。

### P3 主动探索与任务内维护

**动作：** 在 P1 显式流程上扩展任务开始/接续时的线索选择与低成本变化检查，需要时在任务内小批自动维护；手动深维护沿同一流程继续。启动使用短地图、当前相关决定/条件、最近变化，并在有限预算中安排探索线索；不每次重新读全库，也不建设常驻后台 agent。少量显式必保留前提已是 P1 要求，通用依赖推理器仍无建设必要。

**完成：** 普通任务未指示检索时，经启动线索发现一个未点名的相关前提；实际任务内一次资料修改触发维护，后续 brief/search 反映变化。预算结束时剩余范围可见，手动深维护能接续并覆盖旧图重访/随机共读；已声明范围、语义覆盖及索引新鲜度有据可查。流程无需反复完整载入长合同。

### P4 独立评估与机械盘检查

**动作：** 从 P1 留存小样例回归，P2/P3 形成后做一组小型独立任务。起始可用约 8–12 题，按覆盖需要调整；包含已知查找、未点名线索、低字面关系、图片、更正/删除、隔离、恢复与明确失败。把普通文件工具、短常驻信息加文件工具、完整记忆三组对照；针对图、向量或评分的疑问再做相应消融。预期答案对被测 agent 不可见，测试初始上下文核实实际启动信息，避免“新聊天”继承答案或已有记忆。

| 维度 | 必须区分的证据 |
| --- | --- |
| 质量与主动性 | 必要信息找回/漏项、原文支持、过期事实/错误；未点名信息实际到达并被使用，不能只看候选命中 |
| 上下文与成本 | 主 agent 串行往返、底层工具操作、实收字符、补读、主/worker 合计墙时及可得用量；缺 token/价格留空，轮数下降不等于费用下降 |
| 维护与恢复 | 初建/增量耗时、重复处理、失败定位、待处理范围；恢复后内容与查询正确 |
| 自维护与 I/O | 本项目代码/SQL/skill/配置、额外服务代价；数据文件数、读写量/频率、冷/热启动与批量更新条件 |

#### devDoc 自用与读取轮数

本项目 devDoc 自用包含“继续重建”“修改开发文档”，核必要指令、事实、来源是否直接交付，以及寻找/交叉取证是否减少主 agent 往返；已知少量文件仍可同批直接读。P1 开始用同一文字流程，P3 核文档变化后的启动与检索新鲜度，P4 与直接文件工具对照。

普通检索与初始化要在真实机械盘运行，记录盘与资料规模；替代条件只能形成局部结论，机械盘要求仍待验收。

**P4 完成：** 核心行为样例通过，逐任务给出收益、无收益或未定及其全周期代价；不同组记录实际可观察的模型、输入、范围和配置。未见净收益时保留结论，先修已定位机制，不扩大语料掩盖问题；证据不足标未定。真实机械盘未测可结束该次实验，但不能声明完整交付已满足机械盘要求。这组公开行为复用于依赖升级，只补受影响场景和真实故障回归。

### P5 正式安装试用与发布准备

**动作：** 按 [正式部署合同](../../system/deployment.md#环境与服务)，在源码外项目普通安装 basePack wheel 及底座的正式发行版本，用公开/合成资料跑首建、启动线索、检索、修改、任务内维护、手动深维护、备份恢复与移动路径；第二目录验数据隔离。实例问题回改唯一维护源，再按实际发行方式重装。真实业务资料待用户指定范围。

**完成：** 全闭环可复现，不依赖 editable、源码路径、旧项目可变文件或 tmp；已有真实 HDD 可用性验收，P4 的质量、成本及机械盘条件随短试用报告交付，HDD 未测时只报告局部试用。同步 active 工程 README、docs、短示例和专用 skill，说明当前能力、启动交付、一次检索、维护、恢复、失败和共享 embedding 接入，根 system 只记录实际落地行为。公开/合成试用与真实业务效果分别报告。

完整记忆工具可独立发布，不等待其它工具全部完成；发行内容、体积和远端检查遵循 [总体计划](../20261106-rebuild/plan.md#p8-联合交付与轻量发布)。联合场景核“问题→证据→资料变化→增量→共享 embedding→项目局部知识”，不重复 R9 的服务故障/回退矩阵，普通读取和 agent 派工无需进入重任务队列。

## 下一步与待决事项

下次获得实施任务后从 P0 开始：固定同一小样例和预期结果 → 核三者的完整能力与接入差距 → 按不确定性做最短原生往返 → 比较总维护量并写唯一底座与数据/恢复决定 → 通过后交付 P1。保留 Basic Memory 的应用复用收益，也保留未解决的图文向量与关系合同缺口；只维护选定的一套接入。执行结果更新 [进度](progress.md)，接口落地再更新 system，不提前把方案写成现有能力。

当前无阻塞本轮计划交付的用户决策。底座、CLI/MCP 接法、具体字段和预算由实施验证收敛；若证据表明必须牺牲纲领目标，带具体冲突交用户决定。正式业务接入前仍需用户指定资料范围（含聊天/图片及是否保留历史原件）、允许的首建/维护投入、长期备份位置与保留要求；P0/P1 可先用公开/合成资料，不以这些输入为前置。
