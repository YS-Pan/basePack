# P1–P3：真实阅读、图文检索与维护试验

2026 年 11 月 9 日在 Windows 上以合成的河湾站项目试验。P0 的固定边界只验证存储合同；本轮另由实际订阅 agent 阅读原件并产出边界、摘要和关系。下面是本次样例的行为证据，不以成员或边的数量代替效果验收，也不外推真实业务、代表性规模或完整产品交付。选留的短收据位于 [artifacts/runs/20261109-memsys-p1-p3](../../../artifacts/runs/20261109-memsys-p1-p3/)；该目录不纳入 Git，数据库、大批向量及凭据未复制。

## P1：同读、启动与一次委托

首建 reader 实际共读四份中文 Markdown，同一阅读批次提交文件、章节、原文块的边界、摘要、节点、关系及依据；阅读回执只暴露 Codex agent based on GPT-6，精确服务变体未取得。文件/章节/块各自可检索并按来源版本、范围回读；语义边可扩展到另一材料和其证据。这次结果是小型合成材料上的真实阅读，不代表所有关系均被发现。

新任务启动实际读取必保信息；一次委托由 `gpt-6-luna`、`max` worker 检索、回读候选及邻域、评分，再返回带来源的实际内容和缺口。周六接待任务得到试点、水质底线、医疗应急限制和预约职责等线索；材料没有周六具体日期、时段或授权，不能承诺接待。记录了调用次数，但 token 和费用未取得；一次委托不等于只发生一次底层查询，也不证明成本下降。见 `initial-reader-result.json`、`initial-reader-batch.json`、`startup-trial-result.json`。

## P2：图文表示、回源与恢复

reader 实际查看两张原图并记录视觉识读。水量图 B 柱最高，按刻度估读约 51 m³，图上没有精确数值标签或 A/B/C 与日期的映射；巡护便笺另说最高柱不是最近一次，不能据柱高编造日期。几何图无业务用途说明，未强连到水量图。水量图与手册图件说明建立有条件的 `illustrates` 关系并回查两端；图像快照打开检查通过。识读文字是单独标记的 agent 描述，不能当作原始图片向量。

使用本机共享 Qwen3-VL-Embedding-2B 服务编码文件、章节、块和原图，回执记录 `embedding_identity`。分别用水量柱图与几何形状的文字查询时，对应原图向量排在另一张之前；记录 `embedding_kind=image` 与原图输入版本。该小样例说明真实原图向量存取与近邻行为，并非广泛图片召回率评估；描述文本搜索和视觉读取是另行观察。见 `visual-reader-observation.json`、`visual-reader-result.json`、`project-embedding-receipt.json`、`water-image-query.json`、`shapes-image-query.json`。

一次过长摘要编码请求中，服务实际报告 2523/2522 tokens 超过 2048 上限，未执行模型前向；HTTP 返回 500。接受的摘要仍保留，未写部分向量，未索引成员明确报告。需调整该批表示后重试，不能静默截断或把此失败称为已重建成功。见 `overflow-evidence.json` 及服务原始错误。

原生备份恢复到另一项目目录后，收据记录各业务记录逐条一致、原件严格核对，恢复后重建 38 个向量且业务记录不变；两张图片的原图向量查询仍能区分，待处理为零。该备份与恢复属于本次样例，原件及必要配置仍需纳入项目备份责任。见 `restore-result.json`。

## P3：发现变化与深维护

启动按声明的 `memory.source_scope` 做低成本元数据检查，新任务并未点名 `incoming/增补确认.md`，仍报告新增来源；未阅读时不将发现等同理解。一个 `gpt-6-luna/max` worker 随后读取并维护，返回现有夜间试点须当日水质复核通过、补充确认不授权临时延长，以及延长须提前一天站长书面确认等依据。启动后的处理曾因使用绝对路径、来源 revision 为 null、CRLF/LF 不一致而被拒绝；改为相对路径、实际版本和精确原文后提交成功。可得 token/费用为空。见 `auto-startup-trial-result.json`。

对手册的真实修改把浊度停供门槛由连续两次改为三次，并新增临时延长规则。reader 共读新旧材料与相关邻域，更新受影响块、祖先摘要、节点及关系；回执记录 30 个既有未变成员未重写。巡护便笺仅说两次读数越线，未说明指标且复测未完成；它不足以确认三次浊度触发，也不足以断言可继续供水。检索和 brief 返回更新后的规则，旧表述不作为当前答案。见 `maintenance-reader-result.json`。

在恢复副本中删除补充确认后，人工深维护从声明范围内仍存在的四份已登记文本中随机不放回抽两份，并共读旧图邻域及删除前快照。其余材料支持的试点、水质底线和手册中的延长规则被保留或收窄；补充确认独有的试点每日复核约束不再作为当前事实，无法由剩余证据支持的延长范围关系退役，旧成员、旧边及依据可按历史回查。原件已缺失时 `read` 明确报 FileNotFoundError，不能把历史快照冒充现行原件。抽样没找到可信新关系时未为了数量造边；本次没有需要重编码的新增表示。见 `deep-maintenance-result.json`。

## 回归边界与余项

针对真实 SurrealDB 的集成测试覆盖了局部更新使祖先和受影响语义依据失效、未变兄弟复用、追加例外、删除原件和历史回查；节点更正使关系待重核，旧知识版本草稿被拒绝，独立变更仍可提交。节点合并测试保留其他边，删除一份依据后用剩余依据重核并保留有效关系。错误批次与项目绑定检查覆盖事务回滚和错误项目拒绝；并发读取时来源变化的回归检查位于 `tests/test_memory_content.py`。本轮完整源码检查 107 项通过，补上已确认删除不再保留启动义务后，维护定向检查 8 项通过；正式 wheel 的检查另见 P5。P0 的原生竞争事务实测另见 [P0 结果](p0-result.md)。

本结果不含 P4 独立对照的质量、代价或代表性机械盘规模结论，也不含 P5 正式安装验收。小语料、少量原图及单次随机深读不能证明全面召回或低成本；模型变体、token 和费用不可得之处保留未知。后续按 [实施计划](plan.md) 比较实际交付、遗漏、过期事实和全周期代价，并独立验证安装与真实业务范围。
