## 三种检索机制消融

[脚本](../../../artifacts/runs/20261109-memsys-p4/ablation.py) 在同一业务库进行只读比较，一次 `EmbeddingClient.embed` batch 编码八个问题，三模式共用八个 2048 维查询向量、既有成员向量及同一返回的 `embedding_identity`。数据库为 41 个成员、7 个来源；成员含向量及来源修订的前后快照 SHA256 一致。身份由服务回执取得，本分支没有独立重核权重/profile；协调者声明共享服务实际 profile 未变。

三模式均用 SurrealDB 原生 `vector::distance::cosine` 精确排序，未混 BM25、语义图展开或 LLM 评分：

1. 仅原文块：原生 chunk top-12。
2. 原文块加父级：复用同一 chunk 命中及其实际入选叶块，再按首次叶块、最近祖先顺序补章节/文件摘要；不替换叶块。
3. 多层混检：对 file/section/chunk/image 做一个全局 top-12，保留 chunk 直接召回，不先以父层门控。

每题正文上限 2,000 Unicode 代码点，包含正文间双换行；整条入选或整条省略，不截断条件。只按重复 ID、同源同版本已覆盖的原文去重，不因不同来源碰巧同文而丢弃独立依据。引用元数据不计入正文上限，另报完整呈现开销。同上限不等于同实际长度或同费用。

| 模式 | 正文字符 min–max；均值 | 额外 metadata min–max；均值 | 完整呈现字符 min–max；均值 |
| --- | --- | --- | --- |
| 仅原文块 | 724–789；762.25 | 1,777–1,822；1,804.50 | 2,540–2,593；2,566.75 |
| 原文块加父级 | 1,503–1,717；1,660.875 | 3,450–4,074；3,834.875 | 4,953–5,771；5,495.75 |
| 多层混检 | 668–836；745.00 | 1,702–1,775；1,739.75 | 2,415–2,554；2,484.75 |

展开组 8/8 题都补入父级，共增加 78 个章节、38 个文件摘要，严格保留原 96 个叶块；最终每题 24–28 条。top-12 限制的是向量命中列表，展开组另有结构祖先候选，不能说三个最终候选池都只有十二条。混检组共选择 42 个 chunk、38 个 section、16 个 file。

**三模式均未选中 image 成员，混检 top-12 候选也没有 image。** 本轮不打开原图，只允许记录来源、路径及已接受视觉描述，不能据此证明图片召回或看图能力。完整问答组三组实际看图的结果属于上一项实验，不能移作消融证据。

一次查询 embedding 调用为 0.392 s；16 次原生 SQL 客户端往返合计 0.607 s，单次 17.78–49.07 ms。chunk 查询均值 34.38 ms，混检均值 41.51 ms；展开复用 chunk 查询，父级处理没有独立计时。`Memory._execute` 不保留服务器 statement time，以上含 HTTP 与项目检查，不能冒称纯引擎耗时。本轮未清缓存，且协调者说明可能有 P3 回归尾部短请求。

逐题入选 ID、类型、正文、来源范围、去重/省略、完整 SQL 和共享查询向量见 [消融原证](../../../artifacts/runs/20261109-memsys-p4/ablation-result.json)。本结果只说明实际候选与上下文机制差异，尚无这三种上下文的独立覆盖评分或最终 LLM 问答结论；更长的展开上下文也带来显著元数据开销。

## HDD 合成存取负载

硬盘位置沿用 [P0 已核映射](p0-result.md)：D: 为 SATA ST4000VX016 4 TB 机械盘。本次 [回执](../../../artifacts/runs/20261109-memsys-p4/hdd/evidence.json) 及 [README](../../../artifacts/runs/20261109-memsys-p4/hdd/README.md) 引用协调者提供的映射，没有另留一份原始 OS 映射回执。

SurrealDB 4.0.0 Windows x86_64 在独立 18076 实例运行。CPU 用 seed `20261109` 生成 1,000 条 2048 维归一化随机向量，每条附 750 B 合成中英文字；输入 payload 共 32,380,552 B。**这些不是模型 embedding，没有 Qwen 向量身份，不测试语义效果。** 原生精确 cosine 全表排序，无向量/全文索引、无 ANN；63 批事务、每批至多 16 条，未重试。

| 观测 | 本次结果 |
| --- | ---: |
| CPU 生成 | 1.925 s |
| 空库启动至 `/ready` | 825.8 ms |
| schema 创建墙时 | 149.7 ms |
| 分批写入墙时 | 10.921 s |
| 写后物理文件 | 4 个，17,370,706 B |
| 强制终止后重启至 `/ready` | 228.1 ms |
| 重启后首次 exact top-10 客户端墙时 | 52.98 ms |
| 随后六次 exact 客户端墙时 | 17.86–41.19 ms；中位 27.42 ms |
| 热查询服务器 SELECT 回执 | 4.30–5.17 ms；另有 LET 0.93–1.12 ms |
| 最终停止后物理文件 | 4 个，17,371,216 B |

重启前后均有 1,000 条记录；第 0、499、999 条的完整向量、文字和 payload hash 一致，十次查询 top-10 一致，自身均排第一。两次停止都是 `TerminateProcess`、退出码 1，验证的是崩溃恢复；实例最终已停止，端口关闭。没有复制活库，也未更改共享模型服务。

写阶段 Windows 进程计数为 2,133 次 write、17,366,562 write bytes；重启后七次查询为 1,000 次 read、17,298,745 read bytes。`psutil` 进程计数包含缓存及非文件 I/O，不能换算为物理 HDD 吞吐。**未清 OS 缓存，进程重启后的首次查询也不是冷介质测试**；同期共享模型工作可能影响墙时。

真实语义消融在 D: 的小业务库运行，合成负载则验证另一实例的存取、精确扫描和崩溃恢复。两者合起来仍不证明大语料图文语义、全文/ANN、并发压力或维护 I/O 的实际性能。

## 验收范围与余项

本次取得了冻结小语料的三组实际答案及盲评、统一上限的三种检索上下文、真实 HDD 上合成向量存取与崩溃恢复证据。质量小幅分差没有伴随本次耗时/工具减少，且 Q4 的共同前提遗漏仍在；结论保留为有限样本下未证明净收益，不以扩大语料掩盖问题。

尚未由本轮证明：严格同实际模型的重复评测、完整输入与 tokens/费用、三模式证据覆盖及最终问答质量、图/评分各自贡献、分组全周期建库与更新成本，以及 devDoc“继续重建/修改开发文档”的公平往返对照。大语料、冷介质和并发压力也未测。P1–P3 的功能证据保留在各自结果，本页不将其改写为本轮成本对照。
