# 遗忘与知识更新：联网调研及方案重评

2026-11-12（北京时间）。用户认为普通／历史召回分层仍不够优雅，要求联网查实现并比较更好的做法。本文保留调研结论和新建议；未改产品、项目纲领、外部项目或其知识库，未将建议记为用户已选方案。

## 结论

建议将 D 从“给可召回条目分普通／历史身份”重评为：**保留原证，持续整理当前知识表示；按命题、适用条件及替代／更正关系维护演变，现行与历史成为查询视图。** 普通／历史标识可以作为内部派生索引，但不应成为唯一语义依据或要求用户维护的分类。

当前计划已有保留原证、替代依据和维护沿用的正确边界；不足是尚未说明新证据到来后怎样重写一份可直接使用的当前理解，以及一段原文同时含多个不同状态命题时如何处理。改名或多加状态值不能完成这项工作。

## 调研依据与机制差异

| 路线 | 已核机制 | 适合借鉴的部分及边界 |
| --- | --- | --- |

| 明确替代与合并：Mem0 Platform Dream | Supersede 连接旧新记忆；Merge 指向 canonical 项；Synthesis 形成带源链接的新表示 | 变化有承接关系，不要求删除旧记忆。默认 search 仍返回 superseded；只有 `latest_only=true` 才排除，不能声称成熟产品都默认只搜当前 |
| 时态事实：Graphiti／Zep | 原 episode 与派生事实分开；事实记录现实适用期和系统记录／失效时间 | 可表达当时与现在，保留改变依据。OSS 默认无时间过滤；Cloud 官方上下文也允许历史事实。时间字段不证明事实真实 |

| 访问／时间降权：Mem0 Decay、Generative Agents | 以最近访问、重要性或相关性调整排序 | 只控制优先读什么，不决定事实是否适用，更不等于物理遗忘 |

## 三个可实施方向

### A：主题当前表示＋版本历史

按项目目标、科学假设、部署现状等主题维护简洁当前表示，原件与旧表示留存；新证据到来时重写主题，不累积相互冲突的当前说明。它容易给用户直接、清楚的结果，也契合当前 mandatory。若仅靠主题文档，细粒度条件及跨主题依据可能被摘要压掉，不能代替整个多层记忆和原文检索。

### B：有适用范围与替代关系的知识＋当前视图（推荐主体）

把“用户要求”“当前实现事实”“实验观察”等不同职责的命题分清；对同对象、同主张和同范围的变化，记录替代、细化、纠正或未决冲突，并保留原证。现实有效时间是适用条件之一，版本、研究阶段、观测方式也可能更重要。当前概况是由这些知识整理出的工作表示；历史查询沿演变和依据回溯。

这比全局二分普通／历史更适合科学项目。它不要求把所有文本强制拆成固定三元组，也不要求给每个 chunk 配四个时间戳。确有时间事实时才表达有效时间；系统接受历史继续复用已有 source_version/change。双时间模型能区分“何时适用”和“何时知道”，但任意时点完整复原须另有明确版本合同，不能仅凭四列时间保证。

### C：追加保存，主要由检索 worker 当场整合

写入保留新旧事实，worker 在同一问题内读取竞争候选，依时间、条件、来源作回答。它适合探索问题和变化尚未被维护接受的情况。作为唯一默认会让每次检索重复理解同一变化，且漏召回一方时容易误判；当前 mandatory 仍需要可靠的更新表示。

推荐 **B 维护知识演变，A 提供紧凑工作表示，C 处理查询需要的补充和未决差异**。这是一套表示、更新和查询的职责组合，不是建设三份互相同步的数据库。

## 推荐行为合同

1. **稳定原证与派生理解分开。** 原文、图片及来源版本保留；允许摘要和结论被合并、重写、替代。复用现有原证／依据机制，不另建事件仓库或外部原证数据库。
2. **对命题判断变化，不对整份材料判新旧。** 一段旧报告可同时含已替代假设、仍真的实验观察及现有代码事实。原文块直接检索能力保留；不能把整段标历史后全部排除。
3. **先核适用性，再判替代。** 新消息较晚、内容相似不自动构成替代。明确用户决定、真实代码状态和实验观察各有证据职责；条件不明或证据相互冲突时保留未决，不强造唯一当前真值。
4. **更新时形成完整的当前理解。** 同一维护批次处理变化命题、所依赖摘要／mandatory 和关联关系，并保存变化理由及依据。已被新原则吸收的冗余现行表述可合并，不只追加“请注意旧条目过时”。程序负责版本和原子提交，作者负责原文理解。
5. **默认给当前任务适用的认识及证据。** 过去、前后比较、指定条件由 worker 在同一委托中选择相应视图；用户不必选“开哪个库”。历史实验仍可支持当前工作，不能按材料年份过滤。
6. **约束所有召回路径。** basePack 目前直接检索 summaries/chunks，而不只检索语义边；因此新知识身份必须能影响摘要投影、原文命中解释及关系展开。仅给 edge 加时间字段无法避免旧断言从父摘要重入。
7. **处置可跨维护和恢复持续生效。** 复用现有来源／知识版本、依据和处置记录；同一原件不因退出现行视图而反复首建，条件或依据变化时重判，恢复后演变关系仍可查。物理擦除另按用户实际保留需求处理，不将其混入语义替代。

例：`0.1 dB／1°` 可以同时出现在“旧科学假设”“当前普通 CLI 默认”“旧实验的真实条件”中。更新研究目标只替代第一项；第二项作为实现差距继续保留，第三项作为条件化实验事实继续可检索。当前样本未证实所有旧参数条目均错误，不能据此批量撤销。

## 与旧计划的差别及验收

旧 D 的普通／历史身份可保留为实现细节，但不再作为预设最终方案。主问题由“此条搬到哪层”改为“当前应该理解什么、旧认识因何改变、不同条件下哪些仍成立”。C 的旧 mandatory 修正仍须先完成，不能靠新状态模型掩盖未发布；E 的业务验收继续有效。

补充验收：同一来源混合新旧命题；后来的错误摘要不覆盖较早原证；不同观测条件下结论并存；变化比较能回读前后依据；默认当前问题采用适用认识；历史实验继续影响新计划；后续维护与恢复不错误复活旧现行要求。分别观察最终回答、依据选择、维护放大和团队实际成本，不以新字段数量或模型返回成功结案。

仍待决定：主题和命题的身份／条件格式、派生视图发布合同、原文命中如何携带适用性、存量迁移及未决冲突表达。调研未证明某个现成产品在本项目优于自有实现；是否复用引擎应以完整原证、多层图文、订阅 agent 接入和上述真实案例作对照，不因本轮机制借鉴而自动迁库或新增模型 API。
