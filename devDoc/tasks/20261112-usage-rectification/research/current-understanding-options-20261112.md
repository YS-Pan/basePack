# 当前理解的存储、更新与检索选项

2026-11-12。用户要求更新维护计划，结合访问调权与历史图，并给出“持续整理当前理解”的具体方案。本文是三个主选项及查询缓存补充，**尚未选定或实施**；共同维护合同以[计划 D/I](../plan.md#d持续整理当前理解图中保留演变)为准。

## 什么算当前理解

当前理解是已接受知识在主题和适用条件下的可用工作表示。例如当前研究目标、已有可靠结果、实现差距、尚未解决的问题。它不是最后一次对话摘要、最近使用最多的材料或所有新消息的拼接；用户要求、实现事实、实验观察各有证据职责。

“旧目标 A 被新目标 B 替代”“代码默认仍为 A”“旧实验在 A 条件下取得某结果”可以同时成立。所有选项都保留原证及变化依据；冲突未决时给条件分支或缺口，不强行整理成唯一结论。

默认在项目同一数据库保存，不要求用户额外维护 Markdown 文件。可按需导出；若选择可编辑文件界面，必须指定它和数据库谁是维护源，不能默认双向双主。主题由维护作者依材料提出、合并或拆分，不要求用户预先手工分类，也不只按访问热度建立主题。

一个当前理解表示至少能辨认：表示类型、主题／条件、依据知识及原证版本、实际覆盖、已知待更新／冲突。主题指针或条件视图确认它在什么范围是当前；stale=false、文件名和最近更新时间都不能单独证明这一点。字段和存储类型属于待定数据合同。

## A：agent 直接维护主题当前条目

每主题在库内保存一份可读短文，作为工作理解的编辑单元。图连接它的来源、前后版本和变化理由；不要求先把所有句子拆成命题网络。

接受影响主题的新材料或反馈时，原维护作者共读新旧依据，直接合并、改写或替换当前条目，同批更新相关历史关系及 mandatory。旧版本仍可回读；普通检索能直接找到当前短文，再按需展开原证和历史。无语义变化的重新编码不触发重写。

优点是文章直观、编辑单位少，容易给人和 agent 一份完整理解。代价是主题较长时反复改写，段内的条件和证据关系容易被压缩；跨主题复用和精确查询也较弱。适合主题较少、重视连续叙述的项目。

## B：带条件知识图，程序生成当前视图

以有独立身份的命题、适用条件、原证和替代／更正／冲突关系为权威记录。程序按已接受关系和问题条件选出当前适用断言，输出列表或简短模板，不另维护一份 agent 主题文章。

agent 仍须判断命题对应什么、条件是否相同及何种变化成立；程序仅解释明确字段和关系，不自行理解任意自然语言条件或判真。能机械判断的版本范围等可直接筛选；无法决定的条件保留并存、交 worker 判断。

优点是跨主题复用、结构查询和历史解释强，避免长文章与知识图同步。代价是记录和建图更细，输出可能碎片化；规则不会自动写出连贯的研究认识，也不能靠“最新节点”决定当前事实。适合事实结构明确、条件查询较多的领域。

## C：知识图为依据，agent 整理主题理解

图保存命题、条件、证据和演变；同库保存主题短文作为**带依赖版本的派生表示**。事实及关系在图中维护，短文负责把目标、发现、条件、实现差距和未决事项组织成可直接使用的理解。二者不是两套独立事实源。

程序根据新增知识、已声明依赖及反馈定位受影响主题；原维护作者共读所需原证，改写相关短文及启动线索，其他主题不动。一个有界批次提交图与受影响投影；无法同步的已知投影明确待更新，不继续称为已同步。程序可以核版本，无法保证作者已声明所有语义依赖，未知漏项仍依真实使用反馈处理。

brief 直接交付已发布的必要理解／索引；包括启动概况在内的相关检索仍由 worker 完成。worker 可直接找到主题短文，也能独立命中细粒度原文、命题和图片，不要求先命中主题才能读细节。历史问题沿图访问旧认识及原证，不从当前短文猜过去。

优点是兼顾人类阅读、agent 少往返和复杂科研条件；代价是要实现投影身份、依赖与发布合同，并付出局部整理成本。维护作者需要把影响判断的条件留在短文正文，仅在 basis 中藏条件不够。

**推荐长期采用 C，程序承担 B 中已明确可机械判断的部分。** 不要求先形式化所有领域条件，也不必先建一套独立 A 再迁移到 C。这是建议，仍待用户选择。

## D：查询结果缓存，作为补充

worker 在一次委托内完成跨材料整理，结果连同问题／条件、范围、表示版本及原证存在同库缓存。等价问题可复用；失效则交 worker 重新整理，不默认新建文件。

缓存须跟随语义发布版本／受影响范围失效，不能只检查旧依赖是否改变：新接受的反证即使没有出现在旧依赖里，也可能使答案失效。访问 G 的增长不代表事实变化，不作为语义失效事件；无须时间 TTL 参与遗忘。

它适合反复问同类问题，可以叠加 A/B/C。但无人提问时不会产生主题理解，也不能独自承担稳定 mandatory 和“发现不知道自己不知道”。因此不作为第四种独立事实组织方式，更不把一次回答直接提升为项目当前真值。

## 访问权重与三种主选项的共同接入

程序按最终交付事件计算 G/S/L/w，不读取经过时间。实际交付哪个表示版本，就强化哪个；主题短文引用许多依据，不意味着所有依据都交付过。新语义版本的继承规则在 I 统一确定，不将旧版使用自动奖励给新版。

检索时把当前／历史身份、条件、证据入口和 access_weight 一并交给现有 tier1；以当前问题和证据价值为主，价值接近时参考历史使用偏好。tier1 输出综合分，rank 排序、去重、预算选择，首版不再做脚本二次加权。这不增加额外模型调用，也不保证固定的分差预算；固定公式仅作对照研究。

例如历史提问交付了旧目标 A，它的权重上升；图中“B 替代 A”的关系不变。下一次问当前目标，沿关系找到 B；旧实验仍在其条件下有效，可以被正常引用。A 的高权重不会把它重新变成当前要求。

## 现有基础与实施缺口

复用 source_version、basis、knowledge_revision、change、expected 原子发布及单维护 owner。现有 member 受 source/path/range 约束，类型为 file/section/chunk/image；跨源主题不能伪装成某文件的原文块。node 已支持跨源文本及 basis，semantic 已有 conditions 字符串，但 node 目前不是默认 search／brief 的直接候选，任意条件也没有自动解释合同。

因此任何选项都须明确新增派生表示或扩展 node 的索引／检索／启动交付，补齐知识历史版本定位和投影发布。它们不是现有摘要改个名称就能交付，也不要求制造一个 Markdown 业务原件来绕过数据类型。

选定方向后，用混合新旧命题、不同条件并存、错误新摘要、跨主题更正、首次出现反证、原文旁路及导出恢复验证。普通维护仍在作者生成和程序提交后结束，不为投影再增加逐层语义审阅或默认全库审计。
