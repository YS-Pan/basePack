# basePack 实际使用整改计划

2026-11-12（北京时间）。依据聊天[“梳理 GitHub 发布剩余工作”](codex://threads/01a1cdb6-cd05-7310-bc84-f139afd74ce4)、阵列项目的问题记录及当前 0.11.0.dev1 实现制定。**本轮交付调查和计划，尚未实施产品整改。** 逐项依据、反证及观察版本见[调查记录](research/observations.md)。

目标是让现行要求和相关旧成果进入业务判断，完成一次可用的检索委托，并减少重复启动与失败接续的负担。项目纲领、当前唯一 active 路线及既有版本保护不变；待实施方案不写入系统现状。

## 产品设计的已确认约束

2026-11-12 用户在后续讨论明确要求：

1. 采用“长远来看最好的做法”，考虑项目未来仍有不少改进。
2. 重点考虑“从用户的视角看最优雅的做法”，用户包括人类和 AI agent；开发者多做工作以换取使用方便可以接受。
3. 所有命令都有默认参数，且默认参数应当“好用”。

后续方案比较以这三条为约束，不以保留当前 CLI 或开发改动最小为首要理由。A–I 保留问题与验收边界；具体入口、参数和内部动作在产品方案收敛时统一重评，现有二十四个平铺子命令不作为不可更改的接口要求。

当前讨论的统一工作流内核、人类 CLI／agent 结构化工具及宿主适配是推荐方向，尚未选定或实施；默认值合同需要覆盖无参数调用、当前项目／任务／自有运行的绑定，以及缺少业务输入时的正常交互。不得把上述建议写成用户已经选定的具体接口，也未据此修改项目纲领。

2026-11-12 用户另明确希望加入**纯访问驱动的权重**：最终检索交付强化实际返回材料、降低其余全项目材料，不按经过多久变化，不增加 AI 降权判断。功能方向已确认；[算法与接入比较](research/access-only-weights-20261112.md)给出三个方案及推荐，具体公式、数值、空结果计数、粒度与版本继承尚未选定，产品未实施。

本轮按用户要求结合[“比较相关记忆系统”](codex://threads/01a1cee9-f91b-7cf0-82d0-2e8c8a570a1e)六轮讨论（含新增 turn `01a1cf6a-d16c-7751-99da-dd32e1e629f9`）更新 D/I：访问状态由程序更新，历史图保存条件与演变；当前理解的具体表示提供选项而不擅自选定。新增讨论使排序主路径收敛为**现有 tier1 参考访问线索后给综合分，rank 不再二次加权**；固定融合公式留作对照。此为计划更新，未实施产品，未将仿真“选用方案二”解释为已选定全部产品默认。

后续评估：用户认为独立“当前理解”层对高速迭代项目性价比低，倾向去掉。评估后从本轮建设范围移除跨来源主题短文／投影及其主题身份、自动同步／刷新、专用缓存；不另以工作摘要或其他名称加回。现有文件／章节摘要、mandatory、原证和知识图继续沿各自合同维护，查询时由已有 worker 整合本次认识。[选项记录及退出理由](research/current-understanding-options-20261112.md)保留历史，不再作为待选实施项。

## A：把 scope 固定为路径前缀

沿现有搜索合同，检索请求的 `scope` 表示**项目相对路径前缀**，空字符串表示全项目；业务范围、问题与语义限制写入 `question`。不引入自然语言范围解析器或第二套检索服务。

- 同步 `memory/SKILL.md`、检索请求示例、`docs/memory.md`、CLI 帮助及 `prompts/retrieval.md`；渲染结果直接呈现实际路径过滤条件。示例必须包含全项目与一个真实路径前缀。
- 保留程序渲染命令的职责。worker 在同一委托内可调整检索条件，明确说明扩大了哪一过滤范围；配置、模型及索引错误继续原样暴露。
- **完成条件：** 用本次问题和中文/带空格路径，证明空 scope 能找到跨目录证据，合法前缀只返回范围内资料；默认生成的请求不会再把业务描述塞入 `--scope`。现有测试补渲染回归，真实 tier1 委托完成原文阅读、评分及 rank。

## B：按任务启动，按业务问题委托

将本机入口的“shell 变量/UTF-8 初始化”与“任务开始时 brief”拆开。新 PowerShell 进程只需初始化该次命令所用参数；同一任务继续读文件、写文档、stop/release、报反馈时沿用已获得的 brief。任务目标或上下文发生实质变化时才按需补取。生成模板是维护源，随包 skill 和使用文档链接它，不复制一套流程。

按前述入口讨论，计划让 brief 只直接读取已发布的必保留信息、由已有文件／章节摘要提供的概况／索引和已知缺口，不新增跨源主题理解条目，本身不执行任务相关搜索；包括启动时了解任务及项目概况在内的检索，统一交检索 worker。宿主统一入口负责必要派工与结果接收，不把步骤转给使用者；零席位及无宿主派工能力的行为在入口实施时明确，不把渲染命令误称为已派工。当前安装的 brief 仍包含检索，此处仅为待实施目标。

涉及“当前目标、过去要求、为何改动、已有实验是否做过”的跨历史发现，交给检索 worker 完成同一问题的多轮检索、回源、评分和 rank；已知少量文件仍直接同批阅读。结果区分用户要求、助手提出的工作假设、代码默认、已执行实验与适用条件。读到大离散结果后仍忽略它，是整合失败，不能用“派过 worker”结案。

worker 使用宿主实际可用的写文件工具或本机 Python 保存 UTF-8 评分文件；避免假定工具运行时具有浏览器全局对象。若宿主写入失败，保留原错和已读证据，明确尚未完成的阶段；主任务可据原文继续业务，不能把该轮称为完整检索闭环。反馈说明知识 `observed_revision` 与软件版本的区别，后者放 issue；无具体知识目标时提供查询和来源线索。

**完成条件：** 一个文档任务跨多次 shell 只在启动时 brief；stop/release 不依赖再跑 brief；跨历史问题一次委托得到可用证据和实际 rank 结果。评分未保存的故障路径明确报告未完成，不伪造产物。只做相关入口检查与真实使用验证，不建立通用技能测试框架。

## C：先让现行前提可靠进入启动

外部后续 brief 仍含“2026-11-10 当前纲领：本次只迁移……”并显示 `stale=false`、`mandatory_pending_count=0`；0.11 修正批次因证据文件版本不匹配拒绝。这是需优先复现的实际症状，不先把它归因于遗忘机制或错误的冲突保护。

1. 在隔离小样本重现“来源登记推进、原文变化、旧 mandatory、修正拒绝”的顺序。当前发布态合同允许来源已登记而旧摘要仍可查，已有相关回归；不能据 `stale=false` 推定原件已同步。核实实际候选与处置是否遗漏；利用已有版本/候选给出已知未同步信号，未做发现则保留未知，brief 不逐次扫原件。
2. 将已知现行 mandatory 修正作为维护前部工作。只带相关现行依据；历史问题记录确实参与断言才进入依赖，减少无关变化阻断关键批次。
3. 遇 `Evidence source revision mismatch for <path>`，把**报错的证据文件**显式加入下一轮 prepare，阅读当前/旧原文，重新接受证据与目标，或先发布证据后重新 prepare 依赖。本次外部批次已有 expected，但两次 prepare 都只带旧 evidence 快照，未带报错文件的当前原文；单独刷新纲领不足以修复。业务结束前未完成则保留明确待办及原错，复用现有 receipt/反馈/待核机制，避免新建平行任务表、盲目重试或绕过 expected 检查。
4. 在可观察结果中分开报告来源已登记、知识已接受和 mandatory 修正是否发布；不能用向量兼容数量或 source hash 代替语义同步。

**完成条件：** 实际更新后的 mandatory 直接交付现行研究方向；旧迁移授权以历史身份保留。冲突回归仍拒绝旧草稿且无部分发布，显式加入报错证据原件并重读、重新接受后可以成功提交；未发布的修正明确可接续。brief 仍读取发布态，不为每次启动扫描原件。

外部阵列库的修正由其项目任务按已有授权执行；本轮仅观察和制订计划，没有修改该库。

## D：知识演变与历史追溯

本轮替换原“普通／历史二分”的预设实施方式；调研依据见[遗忘与知识更新](research/forgetting-options-20261112.md)。用户已要求将访问调权与历史图结合；独立当前理解层经成本评估退出本轮，原[选项记录](research/current-understanding-options-20261112.md)不再作为前置。保留一张统一知识图的条件、依据和演变，在检索时判断本次适用性。

### 历史图与访问记录共用身份

1. 原文、图片及来源版本保留。知识表示及其版本有可寻址身份，语义图表达带条件的替代、更正、细化、合并、支持与未决冲突。关系由维护作者共读依据后接受；程序不能凭日期较新、文本相近或权重较高自动判断替代。复用 source_version/basis/change/expected，不建设第二份原证库。
2. 把“用户要求”“实现事实”“实验观察”及其适用条件分清；同一原文可含不同状态命题。新研究目标替代旧目标，不自动使旧条件下的实验或当前代码默认失真。条件未知或冲突未决时保留分支与缺口，不强造唯一当前答案。
3. 图的历史端点能定位所指的**知识版本**，不是只指向会被覆盖的当前 member；原证另带 source_version／行范围／图片定位。现有 change.previous 可复用，但必须补齐检索与回读合同，不能假定 read 的旧原证就是旧摘要。当前部分关联边失效路径会推进版本而未逐边保存前像，需在今后的版本推进前保留本轮所需历史；存量缺口如实保留，不声称可完整复原。
4. I 的程序交付事件引用同一批表示身份和实际观察版本，形成“这个版本何时被交付”的可追溯记录。它是使用出处，语义边是认识演变；可统一查询，不将每次交付伪造为需 agent 审阅的语义边。只强化实际交付表示，不沿依据、父子、主题或图邻居传播，不因替代边将旧热度整份转给新知识。
5. 更正、合并及替代通常产生新语义表示版本，其访问状态建议从基线开始；纯位置／编码变化而表示内容未变时可按稳定身份复用。具体单位、等价判据、同批新旧并发交付及恢复策略在正式数据合同一次确定，不把 source_revision 当全部知识版本。

### 检索时如何结合

worker 围绕本次问题，结合已接受关系、任务条件及必要原证判断适用性；历史／前后比较问题沿演变取证，不要求先生成或刷新全局主题理解。遇到旧要求命中，可沿已知替代关系找到现行承接，再决定交付哪些版本及解释。历史查找仍可强化旧表示，但不改变其适用身份，下次当前问题不会仅因它热门就当作现行。

将候选的适用条件、演变身份、可回源依据及 I 的 access_weight 一起交给现有 tier1。tier1 一次完成筛选、综合评分；rank 只按该分排序、去重和预算选择。相关性候选保留独立入口；低权重不是准入门槛，访问状态不推翻明确替代／撤销关系。相互冲突的证据和仍有效的旧实验可成为当前回答需要的内容，不能整份旧文件一律排除。

当前 rank 输入仍采用 member 的路径／原文范围形状。若独立交付 node／关系，须明确对应候选、版本、去重和预算合同，不能伪造来源路径与行号来套用旧格式；最终交付清单记录真正选中的表示及观察版本。

### 沿用现有内容维护，不新增理解同步层

保留文件／章节摘要、智能块、图片及知识节点；来源、依据版本、实际覆盖、已知未同步／冲突继续可查。当前适用性由已接受关系、条件和必要回源判断，不由文件名、stale=false 或最近访问定义。脚本发现版本变化只说明依据变化，不能据此认定语义结论已经失效；原依据未变也不能排除新反证。

新证据／反馈仍进入原有维护批次，作者共读后更新有明确变化的断言、关系及必要现有摘要。用户目标／授权及 mandatory 有明确承接变化时仍须及时定点更正；已知未同步如实提示，不能借移除主题层而无限推迟。原有版本、依赖与发布保护保留，不增加“必须先同步全部主题理解”才能发布知识的条件。

不建设主题短文、主题身份／头指针、主题依赖传播、自动刷新或专用问答缓存。已知依赖的局部维护和未知影响的使用反馈按原合同处理，不新增默认审计。查询 worker 同次整合已有摘要、关系及相关证据，直接交付回答，不要求保存为全项目当前真值。代价是重复问题可能重复整合，未摄入或未召回的新证据仍可能遗漏；不承诺零成本或始终最新。

**完成条件：** 同一语料含新旧要求、未改代码默认、仍有效旧实验、错误摘要及未决条件：当前回答使用适用认识，历史回答沿图回读前后依据；高访问旧要求不会复活，旧实验仍能影响当前计划。原文命中、父摘要和图展开都保留身份，不从旁路把旧断言注成现行。后续维护不因退出现行视图反复首建，恢复后版本／关系／访问归属保持；任意历史时点完整复原另按实际版本覆盖声明，不凭几个时间字段保证。

不按年龄或访问次数自动撤销／删除知识，不新建物理历史库，不恢复历史运行授权。历史可以记录事件日期或事实适用期，访问权重公式始终不读取经过时间。

## I：按最终交付自动调整访问权重

用户已确认功能目标；详见[三个算法及集成方案](research/access-only-weights-20261112.md)。推荐候选为当前权重加稳定度，按项目最终交付事件序号作超曲线下降，命中恢复并巩固稳定度；先快后慢、反复交付更耐遗忘。事件全局推进，未交付材料按需精确计算，无须逐轮写全库。

实施先统一实际交付的宿主边界、材料粒度、版本继承和空结果口径，再确定公式。宿主自动给出实际交付清单与稳定事件 ID，程序原子去重、推进事件及强化；内部 search/read/rank 不计交付，不让用户或 agent 逐条调权。权重独立于知识及向量输入版本，mandatory 无条件保留；全项目降权不得被悄改为只降候选或 scope 内材料。
