# basePack 实际使用整改计划

2026-11-12（北京时间）。依据聊天[“梳理 GitHub 发布剩余工作”](codex://threads/01a1cdb6-cd05-7310-bc84-f139afd74ce4)、阵列项目的问题记录及当前 0.11.0.dev1 实现制定。**本轮交付调查和计划，尚未实施产品整改。** 逐项依据、反证及观察版本见[调查记录](research/observations.md)。

目标是让现行要求和相关旧成果进入业务判断，完成一次可用的检索委托，并减少重复启动与失败接续的负担。项目纲领、当前唯一 active 路线及既有版本保护不变；待实施方案不写入系统现状。

## 产品设计的已确认约束

2026-11-12 用户在后续讨论明确要求：

1. 采用“长远来看最好的做法”，考虑项目未来仍有不少改进。
2. 重点考虑“从用户的视角看最优雅的做法”，用户包括人类和 AI agent；开发者多做工作以换取使用方便可以接受。
3. 所有命令都有默认参数，且默认参数应当“好用”。

后续方案比较以这三条为约束，不以保留当前 CLI 或开发改动最小为首要理由。A–H 保留问题与验收边界；具体入口、参数和内部动作在产品方案收敛时统一重评，现有二十四个平铺子命令不作为不可更改的接口要求。

当前讨论的统一工作流内核、人类 CLI／agent 结构化工具及宿主适配是推荐方向，尚未选定或实施；默认值合同需要覆盖无参数调用、当前项目／任务／自有运行的绑定，以及缺少业务输入时的正常交互。不得把上述建议写成用户已经选定的具体接口，也未据此修改项目纲领。

2026-11-12 用户另明确希望加入**纯访问驱动的权重**：最终检索交付强化实际返回材料、降低其余全项目材料，不按经过多久变化，不增加 AI 降权判断。功能方向已确认；[算法与接入比较](research/access-only-weights-20261112.md)给出三个方案及推荐，具体公式、数值、空结果计数、粒度与版本继承尚未选定，产品未实施。

## A：把 scope 固定为路径前缀

沿现有搜索合同，检索请求的 `scope` 表示**项目相对路径前缀**，空字符串表示全项目；业务范围、问题与语义限制写入 `question`。不引入自然语言范围解析器或第二套检索服务。

- 同步 `memory/SKILL.md`、检索请求示例、`docs/memory.md`、CLI 帮助及 `prompts/retrieval.md`；渲染结果直接呈现实际路径过滤条件。示例必须包含全项目与一个真实路径前缀。
- 保留程序渲染命令的职责。worker 在同一委托内可调整检索条件，明确说明扩大了哪一过滤范围；配置、模型及索引错误继续原样暴露。
- **完成条件：** 用本次问题和中文/带空格路径，证明空 scope 能找到跨目录证据，合法前缀只返回范围内资料；默认生成的请求不会再把业务描述塞入 `--scope`。现有测试补渲染回归，真实 tier1 委托完成原文阅读、评分及 rank。

## B：按任务启动，按业务问题委托

将本机入口的“shell 变量/UTF-8 初始化”与“任务开始时 brief”拆开。新 PowerShell 进程只需初始化该次命令所用参数；同一任务继续读文件、写文档、stop/release、报反馈时沿用已获得的 brief。任务目标或上下文发生实质变化时才按需补取。生成模板是维护源，随包 skill 和使用文档链接它，不复制一套流程。

涉及“当前目标、过去要求、为何改动、已有实验是否做过”的跨历史发现，交给检索 worker 完成同一问题的多轮检索、回源、评分和 rank；已知少量文件仍直接同批阅读。结果区分用户要求、助手提出的工作假设、代码默认、已执行实验与适用条件。读到大离散结果后仍忽略它，是整合失败，不能用“派过 worker”结案。

worker 使用宿主实际可用的写文件工具或本机 Python 保存 UTF-8 评分文件；避免假定工具运行时具有浏览器全局对象。若宿主写入失败，保留原错和已读证据，明确尚未完成的阶段；主任务可据原文继续业务，不能把该轮称为完整检索闭环。反馈说明知识 `observed_revision` 与软件版本的区别，后者放 issue；无具体知识目标时提供查询和来源线索。

**完成条件：** 一个文档任务跨多次 shell 只在启动时 brief；stop/release 不依赖再跑 brief；跨历史问题一次委托得到可用证据和实际 rank 结果。评分未保存的故障路径明确报告未完成，不伪造产物。只做相关入口检查与真实使用验证，不建立通用技能测试框架。

## C：先让现行前提可靠进入启动

外部后续 brief 仍含“2026-11-10 当前纲领：本次只迁移……”并显示 `stale=false`、`mandatory_pending_count=0`；0.11 修正批次因证据文件版本不匹配拒绝。这是需优先复现的实际症状，不先把它归因于遗忘机制或错误的冲突保护。

1. 在隔离小样本重现“来源登记推进、原文变化、旧 mandatory、修正拒绝”的顺序。当前发布态合同允许来源已登记而旧摘要仍可查，已有相关回归；不能据 `stale=false` 推定原件已同步。核实实际候选与处置是否遗漏；利用已有版本/候选给出已知未同步信号，未做发现则保留未知，brief 不逐次扫原件。
2. 将已知现行 mandatory 修正作为维护前部工作。只带相关现行依据；历史问题记录确实参与断言才进入依赖，减少无关变化阻断关键批次。
3. 遇 `Evidence source revision mismatch for <path>`，把**报错的证据文件**显式加入下一轮 prepare，阅读当前/旧原文，重新接受证据与目标，或先发布证据后重新 prepare 依赖。本次外部批次已有 expected，但两次 prepare 都只带旧 evidence 快照，未带报错文件的当前原文；单独刷新纲领不足以修复。业务结束前未完成则保留明确待办及原错，复用现有 receipt/反馈/待核机制，避免新建平行任务表、盲目重试或绕过 expected 检查。
4. 在可观察结果中分开报告来源已登记、知识已接受和 mandatory 修正是否发布；不能用向量兼容数量或 source hash 代替语义同步。

**完成条件：** 实际更新后的 mandatory 直接交付现行研究方向；旧迁移授权以历史身份保留。冲突回归仍拒绝旧草稿且无部分发布，显式加入报错证据原件并重读、重新接受后可以成功提交；未发布的修正明确可接续。brief 仍读取发布态，不为每次启动扫描原件。

外部阵列库的修正由其项目任务按已有授权执行；本轮仅观察和制订计划，没有修改该库。

## D：增加历史层，保留证据

2026-11-12 接续：用户认为下面的普通／历史身份方案不够优雅，已完成[联网调研与重评](research/forgetting-options-20261112.md)。新推荐以原证、带条件／替代关系的知识及当前状态视图为中心，普通／历史作为查询视图；下列原方案保留作问题和验收依据，尚不按其字段假设直接实施。新建议未视为用户已经选定，也未修改产品或数据。

建议在现有库中给**可召回表示**增加最小的普通／历史召回身份，并保存降级理由及替代依据；具体字段及枚举在实施时与现有 schema 收敛。`stale` 继续表达版本/依赖状态，`retired` 继续表达撤销/退役，不复用它们表示“仍真实、只是退出日常召回”的历史知识。

- 默认 brief/search 过滤历史表示；显式历史检索能发现它们，返回历史身份、适用条件及可用的替代依据。历史提问由 worker 在同次委托中启用历史范围，不要求用户记住命令名。
- 默认召回的现行摘要保留简短替代线索，使 agent 知道有历史可追溯。有效旧实验仍可作为当前研究证据参与普通召回；其日期较早或位于 archive 并不是降级理由。
- 维护作者依据明确后续决定、当前用途和原文共读作出处置；程序负责状态过滤、版本与依赖约束及原子发布。明确失效的断言仍用既有退役/更正，普通历史不批量删除。
- 同批处理被替代现行断言、依赖摘要、mandatory 和相关关系；已有 mandatory 义务有现行承接后再降级旧表达。检索展开与评分保留身份，避免父摘要或关系绕过历史过滤而重新把旧要求当现行。
- 历史处置随现有来源版本/覆盖记录参与后续维护；原件未变时不反复提为“初始无知识”，原件或替代依据变化时重新判断。升级、导出恢复和重建向量保留这些身份。

**完成条件：** 同一语料同时含被替代旧要求、现行要求、仍有用的旧实验及错误撤销项：默认当前目标回答采用现行要求；历史问答可发现旧要求并回读依据；当前研究仍能利用旧实验；撤销项不会因开启历史搜索重新活跃；下一轮维护不把已降级历史重新收回普通层。

不按目录名、年龄或最近访问次数自动撤销或删除知识；I 的访问权重只影响排序偏好，不代替语义生命周期。不新建物理历史数据库，不删除原件，不恢复历史运行授权。

## I：按最终交付自动调整访问权重

用户已确认功能目标；详见[三个算法及集成方案](research/access-only-weights-20261112.md)。推荐候选为当前权重加稳定度，按项目最终交付事件序号作超曲线下降，命中恢复并巩固稳定度；先快后慢、反复交付更耐遗忘。事件全局推进，未交付材料按需精确计算，无须逐轮写全库。

实施先统一实际交付的宿主边界、材料粒度、版本继承和空结果口径，再确定公式。宿主自动给出实际交付清单与稳定事件 ID，程序原子去重、推进事件及强化；内部 search/read/rank 不计交付，不让用户或 agent 逐条调权。权重独立于知识及向量输入版本，mandatory 无条件保留；全项目降权不得被悄改为只降候选或 scope 内材料。

**完成条件：** 不读取时钟，闲置不变；重试幂等、并发不丢更新，多轮一次交付只记一次；新材料从当前事件基线开始；旧版交付不误奖新版；全库语义与懒计算等价。最终排序能体现访问偏好，低权重高相关材料仍可重新进入并恢复；验证访问记录不触发 embedding 重建、导出恢复保持状态。实际宿主交付不可观测时如实报告，不把排名文件生成当成已送达。数学检查已完成，产品及真实检索质量验收待实施。

2026-11-12 已按用户要求完成方案二的[合成数值仿真](research/access-only-weights-20261112.md#方案二的合成仿真2026-11-12)：覆盖强化曲线、跨主题与委托粒度、排序翻转、配对随机反馈、交付误记及候选缺席。稳定价值下有收益、独立变化及过强偏置下有代价；这些结果不选择产品默认值，也不代替本项完成条件。脚本和图在 `tmp/20261112-access-forgetting-sim/`，原证已选留。

## E：用真实问题验收信息是否被采用

复用现有独立评估入口，选择以下业务任务，以资料和预期结果隔离的新上下文执行；仅为本次整改补样例，不扩成常规发布审计。

| 任务 | 必须实际影响回答或计划的信息 |
| --- | --- |
| 现在的科学目标是什么？ | 用户已要求较大全阵正常离散；0.1 dB／1°是旧基线/仍存的代码默认；精确实验分布不是已确认芯片统计 |
| 已有实验是否需要重做？ | 大离散、弱模态、K4 条件阳性及失败边界已存在，先列当前缺口，避免从头重跑 |
| 历史要求如何演变？ | 找到旧要求、否定/替代依据与现行条件，清楚保留各自身份 |
| 只询问已知文件的一个参数 | 直接阅读能完成，不增加维护、历史全查或多余委托 |

同时记录主 agent 串行往返、实收文字、补读、团队总耗时和可得用量；未知费用留空。不以扫描量、节点数、反馈 resolved、满队派发或评分文件存在代替正确采用。对比使用相同资料的直接文件路径，分别报告质量、成本和未定项，不预先承诺全面提速或省费。

## F/G/H：按实际故障补齐交付

- **F：** 选留八源失败 batch、准确编码输入、版本与服务日志，先查 HTTP500 原因，再有界复现。区分输入合同、服务内部故障及客户端错误呈现；在实际处理边界保留有用的无秘密错误正文和原异常。保留“候选向量失败则知识/向量均不发布”的回归；不自动重投、重启共享服务或把 0.11 其它成功批次当作本样本修复。
- **G：** 核 BP-T22 当前版，若仍将目录当文件报 PermissionError，只在文件输入边界明确拒绝目录并写清帮助，暂不增加递归扫描。BP-T26 已有原生事务分消息与旧超限批次成功证据，复用现有回归，不重新设计 HTTP 手工分批。沙箱无法打开 Codex 状态库时保留宿主归因、owner 和发布状态，按实际权限接续；失败收尾能独立于数据库 brief 执行，不吞错伪装为采集完整。反馈的合法参数用一个现有示例说明。
- **H：** 对代码/模板升级、schema/数据迁移和共享设施变更分别列受影响的恢复集合与相关检查。评估本次约 1.13 GB artifacts 的逐份复制是否必要，保留原件和可用恢复链，不由本计划授权清理。区分安装兼容验收与之后的语义维护；知识积压如实交接，不扩成每次升级的全库语义验收。

## 实施组织与进度

主 agent 统一维护接口决定、计划与最终提交。A/B/C 可由同一实施分支接续，形成最短可用闭环；F 作为独立查因分支并行。D 的状态合同由主 agent 确定后再实施，E 由干净上下文执行限定业务样例。按项目配置解析模型，不新增 LLM API；共用数据库仍只有一个维护 owner。

本轮已完成：目标主聊天十轮及失败检索子聊天两轮读取、外部文档/选留原证检查、当前实现定点核对、证据选留与计划编写；后续补充纯访问权重算法及数学等价检查。A–I 均待实施；尚未复现 HTTP500，未做成本净收益测量，未改外部数据库或批量退休知识。调查分支模型为 tier3 / gpt-6.1-sol / ultra；团队用量未知，不以调查规模作为效果证明。

每批实现、对应真实故障回归、必要使用文档与 change_log 同交付，完成相关检查后在 main 提交。完成 A/B/C 后先交普通安装包及一个真实检索闭环；D/E 完成后才宣称现行／历史分层交付。公开发布沿用户后续授权，不是本轮计划交付动作。
