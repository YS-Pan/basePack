**入口与skill：** `AGENTS.md`由宿主注入；`.basepack/instructions.md`是独立本机入口；随包`SKILL.md`对应`basepack-memory`通用使用/维护skill。主agent启动从instructions取得必要参数与brief/派工入口，检索和维护worker按渲染prompt直接取得skill定位；不把主agent每次完整阅读skill列为前置。同一执行者确需多份资料时，提供一次工具调用内批量读取的定位，不要求逐级导航。有效规则沿上下文复用。一次读取资料与实际执行brief/检索是不同动作，不承诺完整业务只需一次工具调用。

补齐薄的安装/升级skill入口，按所选能力指向现有README、项目接入、管理员和配置维护说明；使用/维护继续由现有skill负责。安装入口负责解释器与安装位置、设施准备、项目绑定、凭据/恢复与实际启用检查，命令细节保留现有单一维护源。不新建安装器或复制整套文档；只核受影响的安装/生成入口，不在本机组织新机收益或部署评测。

**本轮采用指令触发＋检索时按需补查：**

1. 项目现状、剩余工作、待决策和历史要求的判断，先复用一次完整检索委托核已有决定，再形成选项。已点名的聊天直接读取；对影响结论的后续发布任务沿引用核实。触发条件在现有AGENTS/instructions与使用skill分工中集中维护。

## 二、统一member ID，并将作业生命周期交给Condor

### 成员身份与引用

现有新member的永久ID由作者填写；程序把同批成员放入按ID索引的字典，重复身份可能在提交前覆盖。用户进一步选择只保留新机制：**存量成员一次性迁移为程序生成的UUID，切换后统一读写，不长期保留历史编号、旧写入协议或别名解析。** 新建与更新仍是同一机制下的两个动作，迁移后更新继续使用该成员的UUID，不随每次修改换号。

目标写入合同：

1. 新对象草稿不由agent自取永久ID。作者描述对象、内容和关系，批次内用结构位置或受草稿身份限定的局部引用区分对象；不能把重名问题转移到另一套作者自取全局临时名。
2. 程序在草稿转换为待提交批次时为每个不同新对象分配UUID，生成一对一映射，再统一解析parent、evidence及边端点。跨reader草稿先保留各自引用作用域再合并；复用现有UUID能力与批次文件，不新增发号服务或全局登记库。
3. 更新对象只引用`prepare`返回的迁后UUID及expected。映射写入现有发布批次并冻结，重试或结果核实复用同一批次和ID，不能每次apply重新发号。source/expected/父项/依据及原子发布保护沿用；同一对象的冲突更新和错误引用仍在接收边界明确报错，不静默覆盖或自动猜测合并。
4. 作者prompt、prepare/批次转换/apply合同及说明同批更新；正常运行只保留新写入协议。旧payload和未迁移库明确拒绝，不在普通启动或apply中自动迁移，不保留双轨写入或旧ID到新ID的在线解析层。

一次性迁移按项目执行，步骤如下：

1. **停写并保留恢复集合。** 收尾语义维护和发布，暂停访问记账、检索交付确认及其它已知客户端写入；结清或明确作废未决旧批次/回执。保留数据库原生导出、配置、原文/图片、必要资产/身份回执和可用旧客户端，再建立隔离工作副本。外部项目沿各自升级任务迁移，不自动一并改写。
2. **冻结完整一对一映射。** 盘点当前、退役以及仅存于历史/引用中的全部member身份，生成旧身份到新UUID的映射；原来的字符串/整数身份按实际底座身份分别映射。映射与转换结果选留为本次迁移/恢复材料，正常新系统不读取它。
3. **转换结构化引用和派生键。** 按同一映射重写成员、parent/parent_version、依据basis、原生图端点/endpoint_versions、历史快照、change.previous/target、来源处置与待细化引用、feedback目标、delivery清单及access_state。重算依赖成员身份的knowledge_version/access_state主键和清单顺序，保留原delivery_id、知识版本、出生事件、访问事件序号与计数。只转换相关内部引用，不做原文的全局字符串替换；source、source_version、node、semantic等自身身份不因本轮member迁移额外换号。
4. **保持事实与索引含义。** 原始文件、聊天、图片及其版本/hash保留原样；已有摘要/原文块文字和向量输入未变时保留向量。迁移不走会重新接受知识的普通apply；结构化写入和图边重建须避免触发保留事件而伪造新知识版本、重读、重新编码或访问强化。数据装载后恢复正常约束、索引与事件。
5. **验证后单次切换。** 核一对一映射和悬空引用，以及当前/历史原文与图片回读、父子/图版本端点、反馈、来源处置、已有交付去重与访问状态。切换前处理持有旧ID的已知客户端、工作批次及外部未决回执；重放验证使用迁后等价清单，不能靠旧ID别名兼容。副本验证通过后切换到新库/客户端，再恢复写入；失败则保持未开放新库并回到原恢复集合。
6. **退役迁移路径。** 验证切换成功后从日常运行入口移除旧写入分支、旧ID解析兼容和自动迁移分支。一次性迁移入口按当前调用方处理完后退役，必要工具版本、映射和报告只留恢复资料或Git历史，不形成常驻第二套系统。

完成条件：存量与新建成员均使用新UUID合同，正常读写没有按旧/新来源分叉的代码；并行草稿同名不导致身份覆盖，引用解析正确，同一冻结批次重试不额外创建对象；迁前可用的历史、原证、图、向量及访问/交付状态保持迁后等价，冲突更新被拒绝且无部分写入。以上是迁移一致性与真实故障回归，不是全库语义审计或收益评测。反馈`677ef790e3aa44d1879c83e151537489`在产品修复和迁移通过前保持pending。

### Condor原生职责与必要封装

2026-11-14用户已选择：**接受Condor原生限时策略的生效时效，停止和清理由Condor负责，取消额外PID回收确认；保留必要的参数保真与提交恢复。** 本节替代此前“PID＋创建时间确认”及客户端重复执行作业时限的方案。原生能力、当前代码量与适用边界见[职责调查](research/condor-boundary-and-code.md)，不据此扩大共享GPU策略或重做部署。

| 职责 | 目标合同与改动 |
| --- | --- |
| 作业排队/执行超时 | 沿用submit已有的`periodic_remove`、`allowed_execute_duration`及相关原生策略；接受周期评估和状态转换延迟，不承诺精确秒级停止。删除客户端`enforce_limits`重复计时、相应超时自动cancel及`run`的额外overall自动取消；作业政策不依赖调用者持续在线 |
| 停止、清理与结果 | 显式取消调用`condor_rm`，状态/结束依据来自queue、history或原生事件。取消请求成功和已观察到终态分别报告；held单独报告，普通held不一律自动取消。业务成功仍按退出码及所需产物判断，removed、held或等待命令返回0均不等于业务成功 |
| 取消额外PID确认 | 删除`_confirm_cleanup`、`_worker_pids`、psutil后代枚举/轮询和worker的PID回执责任；不改为PID＋创建时间，也不把它保留为默认诊断。移除`cleanup_confirmed`及依赖它的CLI判定，统一更新当前返回合同，不保留旧字段兼容层。结果只说明Condor所报告的状态，不另作操作系统进程族回收保证 |
| 调用者等待 | `jobs wait --timeout`只限制本次观察，不是作业排队/执行时限；到期返回job ID、当前状态与`observation_expired`，作业可仍在运行，不取消或重新提交。优先让原生等待承接预算，去掉会提前打断它的重复短子进程期限；接受整数秒、命令启动和状态查询开销，不承诺严格墙钟截止。核清`condor_wait`到期与命令错误的区别，未知`TimeoutExpired`和真实命令错误保留原错。`run`组合一次提交与等待，观察到期沿同一返回合同，不把旧的排队＋执行＋余量预算当作原生停止保证 |
| 参数保真 | 保留JSON传递完整argv的小型worker，正确传播子进程退出码；stdout/stderr及生命周期沿Condor现有机制。删除只供PID确认使用的receipt/字段；其它环境或退出回执若无实际消费者也一并移除，保留应用真正需要的环境配置 |
| 提交恢复 | 保留唯一submission token及提交响应不确定时按该token查询queue/history的恢复；只恢复已确认的提交，不盲目再submit，无法确认时保留原始失败。成功空查询与坏JSON按现有明确边界处理 |

实施时统一调整`jobs/client.py`、`submit.py`、`worker.py`、CLI、相关测试及资源使用skill/用户文档/系统说明；删除失用的超时ClassAd、回执参数、PID测试和仅剩这些用途的依赖。psutil是否移除以剩余消费者为准。本站原生共享显存记账与JOB_TRANSFORM保持；结构化事件读取可按实际必要性复用，不为替换少量文本解析强加新Python绑定或部署依赖。
