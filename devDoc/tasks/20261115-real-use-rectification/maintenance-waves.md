# 有限任务池与两段式Terra维护

2026-11-17用户经聊天`01a1e9a3-6e72-7f80-a061-6c6ee021f6de`明确授权本调整。0.18有限池和两段生命周期已实现并通过程序、宿主及真实发布验证；真实语义处置仍继续验收。原N0—N5、剩余真实维护、验证及完整恢复交付继续，不以本次小批代替全范围完成。现行[进度](progress.md)、[执行记录](execution.md)与[实际部署](../../system/deployment.md)保持事实截点。

## 组织与边界

Terra一次规划有限的一波语义来源组，按共读关系和共享图写目标指定归属；每项记录目标、拟写来源paths、额外只读read_paths、写目标和输出要求。paths授权这些来源及其成员的必要修改；write_targets协调共享节点／关系归属，空列表不使已授权路径的成员只读。无stage时沿receipt固定workset授权，有stage时沿remaining来源边界；共读不自动扩大接受范围。空paths可用于图或feedback调查，无法定位的原件或需新增来源／共享写目标留明确余项。任务数支持多轮领取，长组先发，差异明显的工作分组。首版任务可独立阅读写稿；依赖前一波新发布知识的任务留下一波，不建通用依赖平台。

程序在项目本地单一维护源保存任务、worker和结果引用，沿原owner/control/固定receipt边界。Terra按实际容量和配置启动固定Luna池，保留自身收尾恢复名额；不为余量增设无reader的Terra。通用prompt由脚本生成，不让Terra反复抄完整prompt。

Luna自主循环：原子领取 → 脚本生成本任务prompt → 原文阅读、分块、摘要、关系判断及普通修稿 → 提交固定稿/覆盖/错误引用 → 再领。任务与worker预登记并封口启动，活动数来自程序，不从瞬时agent列表计算。无任务的正常退队和活动数更新在同一原子操作；最后正常退队核全部任务状态、保存整波执行回执、取得唯一正常通知资格。启动未封口不得提前结束整波，未启动/失败/残留claimed均显式保留。

## 宿主生命周期

第一段Terra规划、预登记并实际启动Luna、交初始化回执后结束当前turn。Luna首turn先在宿主事件等待中等带wave标识的go；未封口不能领取或退队。原父任务实际确认Terra初始化turn已结束、登记的成员已启动或明确失败后，调用seal并向已启动Luna发送一次go；早到消息留邮箱、晚到消息唤醒等待须用本任务实测。seal本身不证明宿主Terra已空闲。零启动或全异常保留回执交原父恢复，不伪造最后正常通知。

初始化完成只表示任务池启动；原父任务继续持有所有权、stop权限和所有实际句柄，保留Terra恢复名额。正常执行期间Terra不用wait_agent、轮询队列或逐组续派。

普通Luna无任务后自然结束，其完成消息留在空闲Terra邮箱，不主动恢复Terra。最后正常退队者保存波回执后，对同一非根Terra实际调用followup_task，传稳定wave标识、固定回执路径及摘要，恢复原身份、上下文、档位和父子关系。其他聊天的可行性探针仅是依据，不复用其句柄或把它当产品验收。

第二段Terra按汇总固定引用、覆盖和异常沿现有编译/唯一publisher合同发布；成功不增加逐稿全文重读或额外语义审计。固定发布意图、frozen和结果引用保持幂等；确定拒绝与未知提交分开，后者不得重冻或被新波覆盖。必要共读、普通修稿由对应作者承担，形成有限修复波。波执行终态、知识接受和维护完成分别报告。

最后Luna的followup受理写回可能晚于Terra第二段。Terra完成固定发布后直接交结果并结束，不等待通知ack或为此追加turn；原父观察Terra终态及最后Luna通知写回/宿主终态后机械close。通知受理不明时保留pending和原错，原父用实际宿主事实恢复。

领取、回调处理和发布均核当前owner/control/wave及stop。通知资格与宿主followup受理不是同一事务：保留待通知和实际宿主结果，稳定wave标识和幂等收尾防重复处理；失败保留原错，由原父任务恢复，不盲重试、超时抢回或依赖最后正常退出一条路径。停止后的回调资格不得取得；已在途宿主调用无法与stop原子提交，迟到唤醒的第二段必须先核状态并拒绝发布，不能假称宿主绝不会唤醒。原父任务根据宿主终态处置异常worker、全体意外消失和未受理通知。

## 实施与验证

真实样本发现的不可得证据另由source版本记录`unavailable_gaps`：作者明确给出member、knowledge_revision、原gap和理由，绑定同raw revision的fresh、未退役成员。它只确认当前取证条件，不代表读过缺失内容或解决缺口；原coverage_gaps仍展示。与已读粗层覆盖、暂缓细化的`deferred_refinement`分开，只有同版本精确匹配的coverage_gaps理由被抑制，其他未覆盖范围、变化、stale和反馈独立保留。raw或引用知识版本改变须重新判断；外部状态独自改变需新反馈或明确复核。公开来源不能承接私有成员派生记录，私有转公开时非空旧记录须显式复核/清空。该元数据不产生行为交付、不改成员或历史pin，也不对旧frozen补空字段。

先在自然来源组边界结束0.17.4旧团队，固定接受/未发稿、范围与发布终态；不把新合同套给旧worker。若必须新轮次，先正确stop/release旧轮并完整交接。

实现按本地状态机、现有CLI/prompt/lifecycle集成、必要回归和文档安装分工，主任务统一检查提交。计划客户端0.18，数据库schema/行为算法不随本调整变化。启动封口和Terra真实空闲的衔接、通知受理记录及异常恢复须以实现/宿主证据明确，不能依赖时间猜测。

验证顺序：

1. 并发领取不重复，退队无丢失最后通知，未封口不早结；失败、claimed、停止及晚到回调保持owner和原错。
2. 最小宿主闭环证明早退Luna不新增Terra执行轮次，最后Luna实际恢复同Terra/档位/上下文；父任务区分初始化、执行终态、发布与维护完成。
3. 以尚未处理的真实材料小批运行，明显偏差先修实现及相应回归再续批，保留全部未完范围。
