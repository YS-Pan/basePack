## 启动器所在目录就是运行根

设脚本所在目录为 R。用户当前选择的 R 是 `D:/AgentTools/state/codex-usage`，脚本只从自身位置计算 R：

```text
R/
  启动用量统计.cmd
  codex_usage_settings.json     GUI 数据源、时区、归档选项
  cache/
    codex_usage_cache.sqlite3
    codex_usage_query_cache.sqlite3   仅实际增量查询使用时创建
  reports/                     图片、动画、CSV、JSON、gui_run.log
```

现有 `migration/` 及必要恢复原证按原职责保留。本次“cache 随脚本”覆盖用量工具自己的统计／查询缓存。

该 cmd 只启动 GUI 及其 report／cost 子进程，不执行 query。独立 CLI query 不继承已经结束的 `setlocal`；只有为 query 明确提供同一状态根或 `--cache-file` 时，才会使用 R 内的查询缓存。

优先复用已有路径解析，在脚本 `setlocal` 范围内明确设置：

```bat
set "CODEX_USAGE_STATE_DIR=%~dp0"
set "CODEX_USAGE_REPORT_DIR=%~dp0reports"
```

这两项覆盖保存的全局目录选择，也覆盖调用方遗留的同名环境变量；不把本次选择写回全局 `paths.json`。GUI 及统计子进程继承它们，脚本结束后调用方环境恢复。无需把 `CODEX_USAGE_CONFIG_FILE` 另绑一份目录注册表。

继续用所选系统解释器，从无关 cwd 加载安装包。分离前以同一 console Python 运行轻量 `gui --help`；用同目录 `pythonw.exe` 无等待启动 GUI，让双击产生的 cmd 退出。已成功 `pushd` 的成功／失败分支都须 `popd` 后 `exit /b`。缺解释器、pythonw、包或 Tk 时显示原错与操作指引，不自动安装或改用别的环境。

`start` 返回只证明派出进程；实际窗口验收确认 GUI 存活。沿用现有无控制台统计子进程，不另建握手、监护或重试协议。

移动整个 R 会带走已有设置、缓存和报告；只把 cmd 复制到一个空目录，会在那里使用新设置和新缓存，不自动寻找或搬运旧目录。两份脚本在不同目录运行时，各有自己的运行数据，仍使用同一个已安装包。版本维护源保留在项目根，更新时从该源替换运行副本。双击项目根脚本也会在项目根生成 `reports/`、`cache/` 与设置文件，这些是 Git 忽略的本机运行数据；日常使用 AgentTools 副本可保持开发目录不产生这批输出。

相应在根 `.gitignore` 明确忽略 `/reports/`、`/cache/` 和 `/codex_usage_settings.json`；旧 `/codex_usage_report/` 在固定展示媒体移出后整体按生成目录忽略，不再保留四媒体例外。

## CLI 方案 A：平台默认与本机接入

**用户已选择 A。** 未显式覆盖时，report 写入调用方 cwd 下的 `codex_usage_report/`；统计缓存按用户复用。默认缓存采用平台的应用缓存目录，AgentTools 作为用户主动指定的覆盖项，不成为发行包默认或探测前提：

| 平台 | 默认缓存目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%/codex-usage/cache/` |
| macOS | `~/Library/Caches/codex-usage/` |
| Linux | `$XDG_CACHE_HOME/codex-usage/`；未设置时 `~/.cache/codex-usage/` |

这是应用缓存的常见平台约定，可对照 [platformdirs 的平台说明](https://platformdirs.readthedocs.io/en/latest/platforms.html#user-cache-dir)与 [XDG 规范](https://specifications.freedesktop.org/basedir/latest/)。继续由现有 `paths.py` 统一计算，不为路径管理另造配置框架。GUI 设置和用户偏好保留在状态／配置位置，不跟随缓存清理而消失。

- 报告位置：显式 `--output` → `CODEX_USAGE_REPORT_DIR` → 用户显式保存的 `report_dir` → `cwd/codex_usage_report/`。相对参数相对调用方 cwd，不从包 `__file__` 找运行数据。
- 缓存位置：显式 `--cache-file` 最高；已有 `CODEX_USAGE_STATE_DIR` 或显式保存的状态根仍可按原合同选择其 `cache/`，否则用上表默认。两种缓存文件继续分别为 `codex_usage_cache.sqlite3` 和 `codex_usage_query_cache.sqlite3`。
- 可复制 cmd 显式设置脚本根 R 和 R/reports，因此其图片缓存仍为 R/cache，独立于通用 CLI 默认；不改全局偏好。平台默认与可复制入口可以各有一份缓存，不会自动同步；需要复用时显式指定同一缓存文件。
- `report` 生成报告，`cost`／`animate` 默认读取同一有效报告目录，允许显式指定；直接 CLI 启动 GUI 也用同一解析合同。
- `query` 默认 JSON 标准输出、只读扫描且不建缓存；仅 `--incremental` 采用对应的独立查询缓存，显式路径仍优先。不因整改令只读查询开始写报告／缓存。

- AgentTools 中原缓存、设置和报告继续供该处可复制 GUI 使用，不因 CLI 接入而删除或搬空。只修改本工具配置；路径以实际使用账户的解析结果为准，不能用编制宿主的重定向路径代替普通桌面路径。

## 缓存体积整改与性能验收

2026-11-15 只读分析的有效图片缓存为 740,651,008 B（740.7 MB／706.3 MiB），包含 414,872 条 token 事件、37,750 条运行区间及 7,810 份日志检查点。主要保存计数、时间、模型、会话／回合 ID、路径和增量解析状态；事件表约 557.7 MB，两个事件索引约 105.1 MB。当前没有重复 fingerprint 组，不能以删除历史事件作为缩减办法。

主要冗余为：JSON 内重复的日志路径、六项可由原始计数重算的 token 构成字段，以及独立 fingerprint 中重复的 ID／时间／模型／计数。隔离副本保留全部四个索引，仅移除这些可重建表示：

| 隔离实验 | 文件大小 | 相对原库 |
| --- | --- | --- |
| 原库副本 | 740,651,008 B | 基线 |
| 仅 VACUUM | 696,766,464 B | 减少 5.9% |
| 最小去冗余原型 | 419,110,912 B | 减少 43.4% |

原型按原读取顺序逐条恢复完整事件／fingerprint 和运行区间，全部零差异；原 sequence／路径及日志检查点一致。三轮旋转顺序的热读取中位 3.127 → 2.735 秒。写入 4,096 事件的三轮序列化／提交测试，原库为 5.885／3.250／1.603 秒，原型为 2.819／2.360／14.528 秒；长尾原因尚未确定。**已证明当前快照可明显缩小且恢复结果等价，尚未证明所有工作流性能无损。** 实验未覆盖冷缓存、完整统计／绘图、峰值内存、文件追加／删除／归档及异常恢复。

执行时优先实现这一最小去冗余方案；约 43% 是当前样本结果，不是所有缓存的固定压缩率保证。两个排序规则不同的索引分别承担删除／级联与稳定有序读取，先保留；暂不扩大成路径整数化、全库压缩或改变统计保留范围。

- 在目标仓正式代码和已有缓存回归中实现读取还原，保留所有原始计数、身份、顺序、检查点及无 ID 时的路径回退；字段缺失／损坏仍按已有错误合同报告。
- 缓存格式升级提供一次性无损迁移：保留一致性旧库、在新文件迁移并验证后切换。当前代码遇到不支持格式会保留 invalid 备份并重建；不能仅通过改版本号触发全历史重扫来宣称迁移完成。
- 以相同快照比较实际读取结果和代表性能：无变化的增量读取、新事件追加、单文件重建／删除／归档、完整缓存读取及完整报告流程。重复并交替执行，检查内存和写入长尾；将当前 14.528 秒异常作为需要解释的观察，不因中位较快就忽略。
- 数据必须等价；性能不得出现稳定可复现的退化。若候选仍有未解决的性能回退，保留现用格式并记录缓存优化未完成，不用删事件、缩短历史或取消必要索引换取体积数字。
- 切换后实际区分“活动数据库变小”和“总磁盘占用减少”；恢复旧库及先前 invalid 备份应单独列出，验证完成前不删当前有效原库。
