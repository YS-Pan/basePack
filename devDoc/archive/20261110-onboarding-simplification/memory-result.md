# 记忆维护与聊天来源结果

2026-11-10。实现基线为 active 路线 0.8.0 源码；最终普通安装与整体回归以本任务进度为准。本轮均使用隔离数据库和测试目录，未写本项目正式库或升级共享客户端。

## 机械维护

`memory maintain` 默认合并声明范围、已登记来源及既有待核，先做确定性比较，完整材料留在项目 memory 目录；只有剩余语义候选需要宿主派 worker。纯元数据不重新编码；全文件换行等价可复用已接受语义，但原始快照和 hash 保持原字节。局部未变块须有唯一完整行定位及父级上下文证据；已证明的位置直接提供给后续维护，变化的摘要、条件和关系仍待语义处理。查询保持只读。

隔离 SurrealDB 4.0.0、确定性编码器回归中，最终维护组 30 项通过，另有 store 13 项及内容和定位 37 项通过。独立 reviewer 对原漏项与跨版本 X/Y 两个真实数据库探针复测，并对 9 个相关回归复核通过。全文件换行等价样例中 4 成员中的 2 个摘要向量复用、2 个块按真实变更输入重编码；两个节点及 node→member、node→node 关系保持 fresh 并指向旧 basis，旧 snapshot 按版本可回读。局部前插及章节末追加例外样例自动复用 1 个未变块、编码 0 次，受影响摘要、章节与关系继续列为语义候选；来源前移后即使 changes 为空，下次仍可发现。后续先仅接受来源、首次部分接受、连续多版本只接受一部分、空行和缩进变化时，当前原件未被新鲜成员范围或经唯一映射证实的旧原文块覆盖的行继续列为未读；当前版本全文件摘要被接受后不二审其语义。stop 先到、来源并发改变、知识更正并发均沿现合同拒绝批次。旧 stale 无足够证据证明自接受以来的更正、退役和依赖均已排除，保留语义待核，不仅凭最后的 detected_change 恢复。

对选留 267 块的只读回放中，固定 Git `ebd9d6cc1427ee4f4f6fff209cfe9c9ce6a9ee35` 的 32 份比较视图 hash 与既有原证一致，267/267 exact/context spans 与原记录一致，复现 110 个唯一完整行和 86 个完整前后文匹配。该次前后文长度为 16 字符，产品默认 64；它们均为定位证据，不是自动恢复数量。实施期间工作区已有 15 份变化，同一回放得到 102/76。脚本与结果保留于 `artifacts/runs/20261110-onboarding-simplification/memory/anchoring-replay*`；另有中文、emoji、重叠与 Unicode 边界回归。

## 检索与接口

vector/hybrid 的 Python 和 CLI 输出统一为 `{matches, vector_coverage}`；brief 删除恒空变化字段和重复向量字段，保留实际覆盖与只读状态。删除无调用方的 `MemberContent/read_member`，原文件改写、删除后仍可按指定旧 source_version 回读。编码两处承担不同的 stop、图片 hash、HTTP 错误批次和事务职责；仅抽取单次调用需额外模式/异常上下文，净维护收益不足，故保留必要重复。已有的身份变化、数量、复用、图像、stop 和冲突回归作为边界。

## Codex 来源与尚未完成的范围

通过本机桌面使用的同一 Codex CLI/App Server，active/archived 和完整受支持 sourceKinds 的分页列表共 3909 项，projectId 与父子字段均为空。指定历史聊天通过 `thread/turns/list(itemsView=full)` 和 `thread/items/list` 全部分页得到一致的 179 items；其 5 条 typed userMessage 与桌面读取的 turn、item 和正文校验逐项一致。只读原始日志对照中另有 1 条 AGENTS/environment 注入，未出现在该样本的 typed userMessage。不能将此样本推广为所有来源的 provenance 证明。

宿主提供当前 project ID 与完整注册项目根清单后，显式 ID 优先；缺失 ID 以实际 root 与 Git worktree/common-dir 为归属证据，其他项目根冲突、不可用 cwd 和失效 worktree 留待核；列表归属与读取前归属不一致时保留旧导出、不读取正文。这是有边界的物理归属推断，不能声称宿主项目 ID 本身完整。采集使用受支持接口逐页至截点、以长度帧保存原样 UTF-8 正文和身份，失败不覆盖已保存原件。受管来源显式进入同一维护链；原快照保留消息定位，采集和语义接受各自可见。隔离库回归在受管原件更新并删除后，按旧 source_version 核对中文/emoji 正文、聊天/消息身份和 UTF-8 字节位置（4 项通过）。未取得宿主绑定时报告缺口，文件维护仍可用。

真实历史聊天采集初次得到 22 个文本 part，重复采集未改写原件。主聊天公开引用的子代理不在列表；直接 `thread/read` 可取得 parentThreadId，沿显式引用且父级一致、项目不冲突时递归采集。该样例共取得主线程和 6 个经父级证实的子线程，7 个来源、33 个文本 part，0 gap；无法核实或取得的部分保留缺口。分页内相同 turn/item 身份重复时去重，内容冲突直接失败，不同 ID 的重复正文保留。两对真实分叉及一对主/子代理的消息 ID 和 user clientId 无重叠，无法据此证明跨分叉继承副本身份，未按正文去重。可读取的 localImage 按 hash 保留为独立受管来源并传入现有图片维护；模拟 PNG、版本变化和缺失已验，真实聊天附件尚未实测。分叉/继承身份与真实附件取得尚未证明，不能将相关内容或全部项目聊天宣称完成采集，也不能把向量 pending=0 当作聊天已入库。候选普通 wheel 在真实宿主默认发现与隔离采集：122 条列表归属匹配，经显式子代理引用得到 492 份来源、6161 个文本 part、约 5.75 MB；重复采集 492 份的 hash 与 mtime 均不变。10 个 gap 为 6 项无可导出消息和 4 项父级不符引用（后者为 2 个不同 ID 各出现两次）。这些是发现与原文采集，不是语义接受。另有指定历史聊天结合真实共享编码服务的普通安装闭环：22 个主线程正文 part 与受支持 API 全字节一致，stop 后接续及旧 snapshot 回读通过；重复重交未变成员实际编码 0 次。另以真实用户对 README 英文化的要求与计划 G 共读，在共享服务编码 2 个成员后，英文查询经 vector 和 hybrid 找到该原句，核对精确消息定位、两个快照、带两项 basis 的决定及计划到用户消息的关系。回执及设施条件见总体验证。
