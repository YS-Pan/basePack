# 记忆 worker prompt 与全项目默认维护

2026-11-11。用户已审阅示例 prompt、更新计划与逻辑框图，并明确要求实施。基线为普通安装 0.8.1，本轮目标 0.9.0；实际交付与验证在 [进度](progress.md) 接续。

## 目标与已定约束

1. coordinator、reader 的可复用 prompt 使用英文，随 wheel 分发。subagent 从上级收到一条命令，自行执行并读取完整任务说明；路径、角色、tier 等由程序替换。
2. role 决定职责，tier 经唯一项目配置解析模型及推理强度；默认 coordinator tier2、reader tier1。宿主在创建 agent 时设置真实模型，CLI 不调用模型 API 或自行启动 agent。
3. 自动维护默认覆盖整个受管理项目，当前业务只影响优先级；普通调用沿默认入口。特殊情况允许 main 调整范围、组织或直接派临时英文 prompt，简述原因、实际范围和余项，不增加审批流程。
4. tier2 持续组织分批、整合、发布和验证；tier1 完成单批阅读后返回。完成一批不等于维护任务结束。业务结束先 stop，再取消协调者及全部 reader；已获得发布资格的短事务按实际回执记录。

## 实施

### 英文模板与纯渲染 CLI

在 active 工程 `memory` 包内维护两份英文模板，通过 `memory prompt --receipt <receipt> --control <control>` 渲染 coordinator；reader 指定 `--role reader --paths ...`，可显式覆盖 tier。沿现有 JSON 输出合同返回完整 prompt 和宿主派工元数据；模板与项目配置是单一维护源。

命令只读取配置、模板和本轮输入，不创建工作目录，不连接数据库、读取密码或调用 embedding。render 与执行分离。按平台正确引用命令，覆盖空格、中文和引号路径。模板需从普通 wheel 安装位置取得。

### 全项目默认与持续派工

默认发现使用项目内 Git tracked 与非忽略 untracked 清单，合并配置显式包含；非 Git 项目使用声明来源。继续接续所有已登记来源、历史待核、未接受范围及可归属本项目的聊天/支持附件。忽略缓存与运行状态；支持类型和未支持材料的缺口明确报告，不能以无差别扫描项目根代替设计。

保留 `--scope` 的来源发现范围覆盖语义，不把它冒充排他的全局维护过滤。按默认规则发现的候选由 coordinator 按来源与依赖分小批；reader 共读新旧原文与邻域，制作有版本和证据的草案，coordinator 作为唯一发布者整合、共读跨来源关系、按同一 control 发布并核内容。

`maintain` 仅在需要语义工作时提供 coordinator 的 tier/model/reasoning_effort 与渲染命令，主 agent 不必先读取完整 prompt。队列尚有可推进候选且业务仍存续时继续派下一批；候选耗尽、停止或真实阻塞时报告实际原因。本轮以采集/发现截点为界，不递归追赶当前聊天增长。

### 文档与交付

同步随包 skill、生成 instructions、产品说明和现行模块/部署合同；role 细节由英文模板维护，skill 保留入口与生命周期，不重复整份 prompt。主 agent 统一 bump 版本、整合、普通安装及 main 提交；源码与用户文档保留在 active 工程，开发计划/进度/结果在本目录。临时验证在根 `tmp/20261111-memory-worker-prompts/`，选留原证归根 artifacts。

## 验收

- 普通安装能渲染两个 role；变量完整替换、tier 覆盖不改变 role；缺密码或数据库不可用不妨碍纯渲染，渲染不产生状态写入。
- 默认发现 Git 已跟踪与非忽略新文件，忽略缓存，保留显式包含及非 Git 声明范围；历史待核和关联依据仍可发现。真实错误不变为空成功。
- 在独立项目以真实订阅 coordinator/reader 执行生成命令，连续完成至少两个语义批次，并以内容、依据和关系核对验收；不能只以调用成功或记录数代替。
- stop、并发版本冲突、失败依赖、未发布草案及已发布批次沿既有合同；普通主线不因历史积压而等待清零，特殊临时派工仍可用。
- 跑必要源码回归、完整 wheel 测试和源码外安装核验。共享客户端普通升级前停止本轮正式维护；不迁库、不改用户原有知识来伪造完成，不发布远端 Release。
