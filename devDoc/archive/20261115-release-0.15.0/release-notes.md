# basePack 0.15.0

basePack is under development. This release targets Windows and Python 3.13+.

- Publish completed memory drafts through the new `memory publish` command or the shared `basepack.memory.publish` Python helper. It checks the ordered draft references and file hashes, freezes and validates the batch, saves the frozen file exclusively, and calls the existing atomic apply operation. A compact response accompanies the detailed local receipt. Existing `prepare`, `read`, `neighbors`, `freeze` and `apply` operations remain available for agent-directed workflows.
- Resume a fixed publication with its original frozen file, batch ID and UUIDs. If writing the local result fails after the database accepts a batch, resume that same frozen file to recover the receipt. The database receipt remains authoritative; changed source material or revised drafts need a new prepare/read/freeze cycle. See the [publication workflow](https://github.com/YS-Pan/basePack/blob/v0.15.0/experiments/20261106-basepack/docs/memory.md#最小闭环示例).
- Use explicit cuDNN attention on CUDA and accept up to **32768 actual tokens per item**, including model templates, instructions and image tokens. Inputs retain their full content. Over-limit items return HTTP 422 with the original request indexes and actual counts before their inference batch enters the model. The former separate text-byte ceiling is removed.
- Treat embedding `gpu_memory_mib` as an adjustable **soft target**, with 9216 MiB (9 GiB) in the machine template. The service releases unused cache after a request when reserved memory exceeds a positive target; it no longer installs an allocator hard limit or requires a positive GPU budget to start. Text batches start at four items and requests containing images use one. Legal inputs can still exceed available memory; original resource errors remain available to the caller. See the [embedding contract](https://github.com/YS-Pan/basePack/blob/v0.15.0/experiments/20261106-basepack/docs/resources.md#共享-embedding).

`memory freshness` now selects native capture-receipt filenames, so custom command-output files no longer shadow valid receipts. Malformed native receipts still report their original errors; five targeted checks cover this fix and native receipt generation.

**Upgrading from 0.13 or 0.14:** finish active writes, preserve the full recovery set, install the new client and run `memory init` to refresh generated entry points. Member-identity version 2, project UUIDs, configuration schema 2 and existing databases remain compatible; no database migration or full vector rebuild is required. Unchanged inputs retain their embedding identity and can reuse existing vectors. Changed chunking or inputs require fresh encoding.

The new embedding behavior takes effect when the **shared service** is upgraded, independently of the client. Remove the retired machine `embedding.max_length` setting and verify `/info` reports the expected backend, 32768-token limit and `soft_target` memory semantics. A 9 GiB target is adjustable and is not a guarantee that every valid input or batch fits. See the [service upgrade instructions](https://github.com/YS-Pan/basePack/blob/v0.15.0/experiments/20261106-basepack/docs/administrator.md#升级与回滚) and [configuration maintenance](https://github.com/YS-Pan/basePack/blob/v0.15.0/experiments/20261106-basepack/docs/project-config-maintenance.md#按变化边界准备恢复集合).

**Older 0.12 databases:** retain the separate offline member-identity migration and isolated validation before switching database and client together. The unchanged `basepack-member-identity-v2-tools.zip` attachment targets the documented eleven-table knowledge/access schema and SurrealDB 4 native exports; older schemas need their own preparation. `memory init` does not perform that migration. See the [upgrade instructions](https://github.com/YS-Pan/basePack/blob/v0.15.0/experiments/20261106-basepack/docs/setup-project.md#版本升级).

Feature validation has passing records for 654 tests, with the five facility-dependent cases rerun against their actual dependencies, plus 123 embedding and 155 publication checks. An isolated GPU run exercised actual 32768-token success, 32769-token rejection and cuDNN execution. Real HTTP checks covered text, mixed lengths and images; existing-index queries and sampled vectors remained usable. An ordinary-wheel publication run exercised the helper, CLI, fixed-file resumption and original atomic tools. These checks do not establish every-input success, identical floating-point rankings or long-term memory-use percentiles. See the [implementation delivery record](https://github.com/YS-Pan/basePack/blob/v0.15.0/devDoc/archive/20261115-runtime-and-maintenance/result.md).

Attachments: `basepack-0.15.0-py3-none-any.whl`, unchanged `basepack-member-identity-v2-tools.zip`, and `SHA256SUMS-0.15.0.txt`.
