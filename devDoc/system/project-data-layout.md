# 项目本机数据目录约定

2026-11-11。供配置、生成入口、维护过程及清理本机 `.basepack` 时使用。既有通用约定见[文档维护](../documentation.md)，实现和安装边界见[部署合同](deployment.md)。

0.10.0.dev1已落实维护工作包进入根tmp，持久owner/控制/收据仍在项目memory目录；历史保留例外见下文。以下为职责示意，memory.data_dir、jobs_dir及password_file按实际配置解析，不预建可选目录，也不为统一名字迁库。

```text
项目根/
  .basepack/
    README.md                 本机目录说明入口
    config.toml               项目配置
    instructions.md           实际 Python、配置、设施与 agent 入口
    memory/
      store/                  数据库引擎管理的完整存储
      assets/                 已接受来源的原图快照
      codex/                  保留的聊天原件及已有身份记录
      codex-attachments/      采集到的附件原件（存在时）
      password.txt            本项目既有凭据，或配置指定的位置
      serve.ps1               管理员按部署说明准备的数据库启动入口
      logs/                   运行日志
      maintenance/            维护必要控制、收据及来源身份
        owner.lock            owner状态读写的短时互斥
        owner.json            项目唯一持有者、control、运行及发布状态
    jobs/                     作业运行与项目记录，按资源合同管理
  tmp/<任务或运行标识>/       可重建的reading、batch、探针与一次性验证
  artifacts/runs/<运行标识>/  选定的长期原证和清理/迁移清单
```

配置和已有实际路径优先，不为统一名字移动数据库、改凭据或改旧依据位置。现有 runtime.json 等外部定位文件若确实在用则保留，不作为客户端必备生成物。maintenance 保存仍在使用的控制/回执及恢复所需出处；控制可早于回执存在，stop/apply 仍使用时不能放到会自动清除的位置。owner.json保存全生命周期所有权，owner.lock保护其短时读写；同任务control另仲裁stop与发布准入，三者职责不同。

使用反馈记录已保存在项目记忆库feedback表，属于持久运行状态并纳入原生导出/恢复。它不是tmp工作包，也不必另建反馈文件目录；清理不得丢失未决报告，发现流程不得把内部报告再当业务原件摄入。

tmp/artifacts 的职责约定不自动意味着其中内容可以删除：source_scope 显式纳入会绕过 Git ignore，已登记来源和历史依据也继续参与维护。本项目已有 artifacts 来源，新实验的受管源码/README 也在默认 Git 发现范围，清理与统计必须按真实来源范围判断。临时包转入 tmp 不代表未接受的业务原件也可被临时清理。

## 生命周期与清理

| 内容 | 处理原则 |
| --- | --- |
| store、assets、聊天/附件原件、配置与原凭据 | 生产状态，保留引用及历史回读；不以“缓存”名义删除 |
| 活跃控制、收据、采集身份 | 在使用或恢复仍需时保留；结束后核引用，不凭时间或停止标记整批删除 |
| reading/batch、临时导出、试验/覆盖率验证 | 新工作包生成在根tmp/basepack-maintenance；历史保留例外另列。任务结束前选留独有原证，并核它们是否也是受管来源 |
| 备份 | 由项目明确恢复目标、输出位置与保留规则；不默认在生产目录长期积累多套完整 export 和 records JSON |
| 日志与 jobs | 按实际运行路径和所属合同判断，不能将运行中状态当临时文件清空 |

本项目已按逐文件清单清理旧备份和可重建杂项，共删除2,877文件、1,064,167,175逻辑字节；64件独有原证选留到artifacts。十份未匹配原件包、真实语义输入/结果、onboarding原始捕获、维护身份和生产状态保留。升级另有一套明确回退目的的当前原生export，未重新叠加旧历史备份。具体清单、保留映射及功能检查见[实施结果](../tasks/20261106-memory-system/maintenance-implementation-result.md#目录清理)。

清理结果分开记录：删除的字节与路径、保留例外、原件/旧依据和服务功能检查。减少目录体积不等同于 AI 维护提速。数据库版本记录和 WAL/vlog 由数据库管理，不通过文件删除自行压缩。
