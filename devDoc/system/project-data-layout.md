# 项目本机数据目录约定

2026-11-11。供配置、生成入口、维护过程及清理本机 `.basepack` 时使用。既有通用约定见[文档维护](../documentation.md)，实现和安装边界见[部署合同](deployment.md)。

此前已有状态/临时材料/原证的分工，但缺少完整的 `.basepack` 内部规范。本文补充推荐结构；现行 0.9.1 仍会把部分工作文件放在 memory/maintenance/work，后续由[维护试验](../tasks/20261106-memory-system/automatic-maintenance-plan.md)调整。以下树不代表已完成迁移，也不要求每个可选目录预先创建。

```text
项目根/
  .basepack/
    README.md                 本机目录说明入口
    config.toml               项目配置
    instructions.md           实际 Python、配置、设施与 agent 入口
    memory/
      store/                  数据库引擎管理的完整存储
      assets/                 已接受来源的原图快照
      codex/                  保留的聊天原件及已有身份记录
      codex-attachments/      采集到的附件原件（存在时）
      password.txt            本项目既有凭据，或配置指定的位置
      serve.ps1               实际数据库启动入口
      runtime.json            实际运行定位信息（存在时）
      logs/                   运行日志
      maintenance/            维护必要控制、收据及来源身份
        owner.lock            候选规划：项目唯一维护持有者
    jobs/                     作业运行与项目记录，按资源合同管理
  tmp/<任务或运行标识>/       可重建的 reading、batch、探针与一次性验证
  artifacts/runs/<运行标识>/  选定的长期原证和清理/迁移清单
```

配置和已有实际路径优先，不为统一名字移动数据库、改凭据或改旧依据位置。maintenance 只保留仍在使用的控制/收据及恢复所需出处信息；临时阅读包和验证不能无期限堆在生产状态中。owner.lock 尚未实现，布局本身不提供互斥。

## 生命周期与清理

| 内容 | 处理原则 |
| --- | --- |
| store、assets、聊天/附件原件、配置与原凭据 | 生产状态，保留引用及历史回读；不以“缓存”名义删除 |
| 活跃控制、收据、采集身份 | 在使用或恢复仍需时保留；结束后核引用，不凭时间或停止标记整批删除 |
| reading/batch、临时导出、试验/覆盖率验证 | 后续新产物放 tmp；任务结束前将少量独有且需保留的原证选留到 artifacts |
| 备份 | 由项目明确恢复目标、输出位置与保留规则；不默认在生产目录长期积累多套完整 export 和 records JSON |
| 日志与 jobs | 按实际运行路径和所属合同判断，不能将运行中状态当临时文件清空 |

本项目用户已选择清除既有历史备份及无用杂项，具体步骤在维护计划。本轮只建立规范和候选清单，不执行大规模删除或迁移。后续清理须核活动使用及当前/历史来源引用；覆盖率和接入验证目录有未另存的原证，应先选留，不能整目录视为垃圾。

清理结果分开记录：删除的字节与路径、保留例外、原件/旧依据和服务功能检查。减少目录体积不等同于 AI 维护提速。数据库版本记录和 WAL/vlog 由数据库管理，不通过文件删除自行压缩。
