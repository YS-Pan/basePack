# 项目本机数据目录约定

2026-11-11。供配置、生成入口、维护过程及清理本机 `.basepack` 时使用。既有通用约定见[文档维护](../documentation.md)，实现和安装边界见[部署合同](deployment.md)。

此前已有状态/临时材料/原证的分工，但缺少完整的 `.basepack` 内部规范。本文补充推荐结构；现行 0.9.1 仍会把部分工作文件放在 memory/maintenance/work，后续由[维护试验](../tasks/20261106-memory-system/automatic-maintenance-plan.md)调整。以下以本项目路径为示意，memory.data_dir、jobs_dir 与 password_file 按实际配置解析；不代表客户端已生成全部目录或迁移完成，也不要求预先创建可选目录。

```text
项目根/
  .basepack/
    README.md                 本机目录说明入口
    config.toml               项目配置
    instructions.md           实际 Python、配置、设施与 agent 入口
    memory/
      store/                  数据库引擎管理的完整存储
      assets/                 已接受来源的原图快照
      codex/                  保留的聊天原件及已有身份记录
      codex-attachments/      采集到的附件原件（存在时）
      password.txt            本项目既有凭据，或配置指定的位置
      serve.ps1               管理员按部署说明准备的数据库启动入口
      logs/                   运行日志
      maintenance/            维护必要控制、收据及来源身份
        owner.lock            候选规划：项目唯一维护持有者
    jobs/                     作业运行与项目记录，按资源合同管理
  tmp/<任务或运行标识>/       可重建的 reading、batch、探针与一次性验证（目标）
  artifacts/runs/<运行标识>/  选定的长期原证和清理/迁移清单
```

配置和已有实际路径优先，不为统一名字移动数据库、改凭据或改旧依据位置。现有 runtime.json 等外部定位文件若确实在用则保留，不作为客户端必备生成物。maintenance 保存仍在使用的控制/回执及恢复所需出处；控制可早于回执存在，stop/apply 仍使用时不能放到会自动清除的位置。owner.lock 尚未实现，与现有单任务 control 短时仲裁锁不同。

候选计划新增的使用反馈记录保存在项目记忆库，属于持久运行状态，纳入导出/恢复；当前尚未实现。它不是tmp工作包，也不必另建反馈文件目录；清理不得丢失未决报告，发现流程不得把内部报告再当业务原件摄入。

tmp/artifacts 的职责约定不自动意味着其中内容可以删除：source_scope 显式纳入会绕过 Git ignore，已登记来源和历史依据也继续参与维护。本项目已有 artifacts 来源，新实验的受管源码/README 也在默认 Git 发现范围，清理与统计必须按真实来源范围判断。临时包转入 tmp 不代表未接受的业务原件也可被临时清理。

## 生命周期与清理

| 内容 | 处理原则 |
| --- | --- |
| store、assets、聊天/附件原件、配置与原凭据 | 生产状态，保留引用及历史回读；不以“缓存”名义删除 |
| 活跃控制、收据、采集身份 | 在使用或恢复仍需时保留；结束后核引用，不凭时间或停止标记整批删除 |
| reading/batch、临时导出、试验/覆盖率验证 | 候选将可重建新产物放 tmp；现行生成位置仍有偏差。任务结束前选留独有原证，并核它们是否也是受管来源 |
| 备份 | 由项目明确恢复目标、输出位置与保留规则；不默认在生产目录长期积累多套完整 export 和 records JSON |
| 日志与 jobs | 按实际运行路径和所属合同判断，不能将运行中状态当临时文件清空 |

本项目用户已选择清除既有历史备份及无用杂项，具体步骤在维护计划。本轮只建立规范和候选清单，不执行大规模删除或迁移。后续清理须核活动使用及当前/历史来源引用；覆盖率和接入验证目录有未另存的原证，应先选留，不能整目录视为垃圾。

清理结果分开记录：删除的字节与路径、保留例外、原件/旧依据和服务功能检查。减少目录体积不等同于 AI 维护提速。数据库版本记录和 WAL/vlog 由数据库管理，不通过文件删除自行压缩。
